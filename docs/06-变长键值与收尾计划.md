## Context

调研结论：Rust 版 RasterKV（仓库 `raster`，分支 `codex/cpp-performance-parity`，基线提交 `746c562`）已对齐 FASTER C++（提交 `321d872e`）单 store 的全部核心协议，但**键和值只能定长**（`Key: Copy`、`Layout::<K,V>::SIZE` 编译期常量），而 C++ 支持变长键（`key_t::size()`、ShallowKey/`write_deep_key_at`）和变长值（`value_size()`、`value_size(old)`、值在 RMW/Upsert 中增长或缩小）。C++ 测试集中的 `VariableLengthKey`、`ResizeValue`、`GrowString` 系列都依赖它。用户决定：

- 缺口 1（变长键/值）在进入阶段 E 前补上；
- F2 冷热两级存储暂不做，列入 TODO；
- 配置格式可自由引入外部依赖（阶段 E 用）；
- Azure 分层存储不做。

本计划交给另一个 agent 执行。**硬性目标**：变长支持完成后，定长类型的所有现有基准不得回退；新增的变长基准对 C++ 达到吞吐 ≥ 1.0 倍、P99 ≤ 1.0 倍。

## 1. 设计（与 C++ 契约一一对应）

### 1.1 记录布局（`src/core/record.rs`）

与 C++ `record.h` 相同：`header(8) | pad→align(K) | key(key.size()) | pad→align(V) | value(value.size()) | pad→8`。

在 `Layout<K, V>` 上新增（全部 `#[inline(always)] const`/普通函数，定长时被常量折叠）：

- `KEY_OFFSET`（不变）
- `value_offset(key_size: u32) -> usize = pad(KEY_OFFSET + key_size, align V)`
- `size(key_size, value_size) -> u32`（含尾部对齐到 8）
- `disk_size(key_size, value_size)`（不含尾部 padding）
- `min_disk_key_size() = KEY_OFFSET + size_of::<K>()`
- `min_disk_value_size(key_size) = value_offset(key_size) + size_of::<V>()`
- `min_io_size() = pad(min_disk_key_size(), align V) + size_of::<V>()`（定长时等于整条记录 → 读盘仍是一次 IO）

`Record<K, V>`：`value()` 改为使用 `value_offset(self.key().size())`；新增 `size()`、`disk_size()`；`initialize*` 系列改为「先写 key（`write_key`），再由上下文原地初始化 value，最后 Release 写 header」。`initialize_copy(info, source)` 按 `source.size()` 拷贝。删除 `Layout::SIZE` 的所有外部使用（见 1.5 清单），保留一个 `#[cfg(test)]` 或私有常量用于断言即可。

记录大小必须 ≤ 页大小：在分配处 `assert!`（与 C++ 一致），并在 `StoreConfig` 文档中说明。

### 1.2 Key / Value trait（`src/core/kv.rs`）

```rust
pub trait Key: Eq + Send + Sync + 'static {
    /// Bytes this key occupies in a record, including any payload stored
    /// inline after `Self` (FASTER `key_t::size()`).
    #[inline(always)]
    fn size(&self) -> u32 { size_of::<Self>() as u32 }
    fn hash(&self) -> u64;
}

pub trait Value: Send + Sync + 'static {
    /// Bytes this value occupies in a record (FASTER `value_t::size()`).
    #[inline(always)]
    fn size(&self) -> u32 { size_of::<Self>() as u32 }
}
```

- 去掉 `Key: Copy` 与 `Value` 的 blanket impl；为 `u64`（已有 FNV-1a 哈希，必须保持与 C++ 基准一致）、`u32`、`AtomicU64`、`AtomicU32`、`u64`/`i64` 等常用类型显式 `impl Value`。
- 变长类型的写法与 C++ 相同：`#[repr(C)]` 头结构 + 内联尾部字节，`size()` 返回头 + 尾部长度，`PartialEq`/`hash` 读取尾部字节（通过 `unsafe` 指针，`SAFETY` 注释说明「记录内存至少 `size()` 字节」）。在 `src/core/kv.rs` 文档注释中给出范例。
- 记录中的 K/V 永不 drop（日志数据），文档写明 K/V 不得持有堆资源。

### 1.3 上下文 trait（键侧：ShallowKey 契约）

四个上下文 trait 都保留必需的 `fn key(&self) -> &K`，并新增带默认实现的方法（默认实现基于 `key()`，覆盖它们即得 C++ 的 ShallowKey，不必物化完整键）：

```rust
#[inline(always)] fn key_hash(&self) -> u64 { self.key().hash() }
#[inline(always)] fn key_size(&self) -> u32 { self.key().size() }
/// Writes the full key (key_size bytes) at `dst` (FASTER write_deep_key_at).
/// # Safety: dst is aligned for K and has key_size() writable bytes.
#[inline(always)] unsafe fn write_key(&self, dst: *mut K) { copy key_size() bytes from self.key() }
#[inline(always)] fn key_equals(&self, stored: &K) -> bool { stored == self.key() }
```

为避免四份重复，抽一个 `pub trait KeyContext<K: Key>`（含上面 5 个方法），四个上下文 trait 以它为 supertrait。store 内部所有 `let key = *ctx.key()`、`record.key() == &key` 改为 `ctx.key_hash()` / `ctx.key_equals(record.key())` / `ctx.write_key(ptr)`。注意：`hash` 只计算一次，后续传 `hash: u64`。

### 1.4 上下文 trait（值侧：原地初始化）

新增安全包装 `pub struct ValueSlot<'a, V> { ptr: *mut V, len: u32, .. }`（`src/core/kv.rs`）：

- `fn write(self, value: V)`：定长写入（`debug_assert!(len >= size_of::<V>())`）。
- `fn len(&self) -> u32`；`fn as_mut_ptr(&mut self) -> *mut V`（变长类型用 `unsafe` 自行初始化头与尾部）。

trait 改为（对应 C++ `Put`/`RmwInitial`/`RmwCopy` 原地写入）：

| trait | 新方法 | 默认 |
|---|---|---|
| `UpsertContext` | `fn value_size(&self) -> u32`；`fn put(&mut self, slot: ValueSlot<'_, V>)`；`fn put_atomic(&mut self, value: &V) -> bool`（不变，空间不足返回 false 走追加） | `value_size = size_of::<V>()` |
| `RmwContext` | `fn initial_value_size(&self) -> u32`；`fn copy_value_size(&self, old: &V) -> u32`；`fn rmw_initial(&mut self, slot)`；`fn rmw_copy(&mut self, old: &V, slot)`；`fn rmw_atomic(&mut self, value: &V) -> bool`（不变） | 两个 size 默认 `size_of::<V>()` |
| `DeleteContext` | `fn value_size(&self) -> u32`（墓碑记录的值空间，C++ 同名） | `size_of::<V>()` |
| `ReadContext` | 不变（`get`/`get_atomic` 收 `&V`，变长值通过 `V` 自身方法读尾部） | — |

所有现有测试、示例、内部上下文（`compact.rs` 的 `CopyRequest`、`pending.rs`）同步改写；定长写法统一为 `slot.write(AtomicU64::new(x))`。

### 1.5 需要修改的代码位置（`Layout::SIZE` / 键拷贝的全部使用点）

- `src/core/store.rs`：`upsert_append`（L~433）、`rmw_from_disk`（~533）、`rmw_attempt` 追加分支（~600）、`internal_delete`（~668）、`trace_back`、`read_attempt`。分配大小改为 `Layout::size(ctx.key_size(), value_size)`；RMW 追加时若源记录在内存，用 `copy_value_size(old)`，否则 `initial_value_size()`；**注意 RMW 的「源在分配期间被驱逐」回滚分支**：现在用 `initialize_tombstone`+`set_invalid`，变长后仍须写一个合法的、可被扫描跳过的记录（header + key + 至少 `value_size` 的零值区，`set_invalid`），保证扫描/恢复能按 `size()` 步进。
- `src/core/pending.rs`：`DiskRecord::record` 改为检查 `min_disk_key_size → min_disk_value_size → disk_size` 三级是否已读够；新增 `Lookup::NeedMore(len)`，所有 `PendingOp::resume` 遇到它返回新的 `Step::Read { address, len, marked }`（同一地址重读更长）。`Step::Read` 增加 `len` 字段。
- `src/core/session.rs`：`issue()`（~L314 用 `Layout::SIZE`）改为接受 `len`，首次读用 `Layout::min_io_size()`；`advance` 传递 `len`。
- `src/core/compact.rs`：`CopyRequest.words` 按 `record.size()` 拷贝；`block_allocate` 用记录实际大小；`PendingCopy::resume` 处理 `NeedMore`。
- `src/core/scan.rs`（~L133）：页内按 `record.size()` 步进；null header 或剩余空间不足 `min` 记录时跳到下一页；从设备读页的逻辑不变（整页读）。
- `src/core/recovery.rs`（~L109–132）：重放 `[checkpoint_start, final)` 时按 `size()` 步进，key 读取改用 `Record::key()`；`find_or_create(key.hash())`。
- `src/core/read_cache.rs`：`insert_cached` 分配 `source.size()`（来自磁盘记录则为其 `size()`）；`evict_cached` 循环按 `record.size()` 步进，null header 跳页。
- `src/core/hlog.rs`：`allocate` 的 `debug_assert!(size <= page_size)` 改为 `assert!`（变长时用户可触发）。
- `examples/{parity,disk,checkpoint,compact}.rs`、`tests/*.rs`：适配新 trait（机械改写）。

### 1.6 零成本保证（定长快路径）

- 所有 size 计算都经由 `K::size()` / `V::size()` / 上下文默认方法，默认实现返回 `size_of` 常量且 `#[inline(always)]`，定长时整个记录大小常量折叠。
- 不要引入新的运行期分支来区分定长/变长；`REST`/`RC` 常量泛型结构保持不变（`store.rs` 的 `*_attempt::<REST, RC, C>`、`*_general` 外联、`Session.plain`）。
- 首次磁盘读长度 `min_io_size()` 对定长类型等于整条记录，`NeedMore` 分支在定长时永不触发（标 `#[cold]`）。
- 阶段 V1 结束时必须用 callgrind（`cg.sh`）确认 `read uniform`、`upsert uniform`、`rmw worker-hot` 每操作指令数与基线 `746c562` 相差 ≤ 2 条，并用 `run.py` 交替确认 cyc/op 差 ≤ 3%。

## 3. 变长之后、阶段 E 之前：小缺口（阶段 D+）

按此顺序，各自独立提交、各带测试：

1. **操作选项**（对应 C++ `faster.h` L211–223）：`Session::read_with_options(ctx, serial, ReadOptions { abort_if_tombstone })`（墓碑返回 `Aborted`）、`rmw_with_options(.., RmwOptions { create_if_not_exists })`（不存在返回 `NotFound`）、`delete_with_options(.., DeleteOptions { force_tombstone })`（即使 key 不在索引也追加墓碑）。原 `read/rmw/delete` 保持零开销（选项走编译期默认或单独入口）。
2. **日志大小上限与反压**：`StoreConfig`（或自动压缩配置）增加 `log_size_budget`；当 `log_size() >= budget` 且有压缩进行时，Upsert/RMW 入口的线程参与压缩（对应 C++ `HlogMaxSizeReached` + `CompactRecords`，faster.h L1368/L1558）。需要把 `compact.rs` 的工作拆成可多线程认领的页批次。检查放在 `*_general` 或以低成本原子读实现，不得影响 plain 快路径（按 1.6 的方法验证）。
3. **压缩附加能力**：`compact(until, shift_begin, threads, checkpoint: bool)`，`checkpoint=true` 时压缩完成后自动做一次完整检查点（对应 C++ L3645）。旧的基于扫描的 `Compact()` 不实现（C++ 中已被 lookup 版取代），在文档中注明。
4. **诊断**：`FasterKv::num_active_sessions()`、`index_distribution()`（对应 `DumpDistribution`，返回每桶条目数直方图）、可选 `Stats`（读缓存命中/插入/驱逐、压缩字节数、pending 数），以 `cfg(feature = "stats")` 或原子计数器实现，默认关闭且零开销。

### 7.4 保留的失败与修正证据

- 初始 V1 驻留慢约 3%–10%；反转键比较和外联 RMW 追加没有解决。索引入口显式内联后通过该阶段验证；三项 callgrind 每操作指令数约减少 1、12、16 条。
- 早期矩阵曾出现 upsert/uniform/4 0.822 倍、rmw/worker-hot/4 0.692 倍的墙钟失败，而独立周期和 P99 未同步变差。逐线程绑核及 A/A 控制用于后续测量，但不据成功复跑宣称已经证明全部旧异常的根因。
- 旧候选压缩约 2.170 s／基线 1.978 s，恢复约 300.0 ms／269.8 ms，均失败。同步压缩改为借用扫描页，进入 Pending 才复制；恢复复用实际已对齐的返回缓冲区，未对齐时仍复制。
- 后续候选的读缓存单线程为基线 0.976 倍；检查点原三轮期间吞吐 0.968 倍，包含原样本的九轮扩展后检查点耗时比基线高 3.05%，仍失败。原始样本均保留。
- 缓存预算标志的检查点实验、固定索引输出缓冲区实验（耗时比基线高 21.5%）、设备构造冷路径标注实验均未采用。设备返回缓冲区最初的枚举表示又使驻留 read/uniform/4 降到 0.977 倍；改为单一 Vec 所有权和必要的分配内对齐后，通过当前完整驻留与缓存矩阵。
- 早期 shared-hot 四线程 upsert 的单次周期失败、六轮 A/A 吞吐失败继续保留；预先声明的 24 轮控制和对照随后通过。最终构建按完整的六轮／24 轮方法重新测量。
- GC 测试原先动态选择最新只读边界，可能合法删除已完成的新写入。修正为预先冻结旧记录可回收范围、屏障等待会话启动，并刷新至三次 GC 完成，保留最终新值完整可读断言；专项重复 100 次及后续全量 30 轮通过。

### 7.5 契约补充与范围

- `Value::initialize_empty` 为墓碑和放弃的分配初始化合法、准确的尺寸头；`DeleteContext<K>::value_size` 返回 Option，None 使用 V 的固定头大小。见 [ADR 0002](adr/0002-variable-length-records.md)。
- 单记录磁盘返回缓冲区补齐已初始化的尾部 padding；分级读取始终使用实际返回长度。必要时在原 Vec 分配内对齐，释放仍使用原分配布局。
- 压缩的 I/O／结构损坏错误会阻止截断；协调器互斥持续到协作者排空、截断及可选检查点结束。
- C++ TOML 四个用例中两个属于 F2，本轮对它们测试明确拒绝；单 store 的字符串／文件配置和非法字段、几何配置均有覆盖。pre_allocate 两个取值都保留 eager allocation；后台压缩须显式启动并持有句柄。
- F2 和真实高速磁盘／异步 O_DIRECT 后端仍为后续事项；Azure 不实现；不可达的 C++ snapshot 路径不列为缺口；可选 Stats 本轮不增加。
