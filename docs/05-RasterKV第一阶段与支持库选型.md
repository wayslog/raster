# RasterKV 第一阶段范围与支持库选型

更新日期：2026-09-12。名称、范围和独立文件格式已确定；P0—P8 已实现并验收，P9 总验收仍进行中。本文区分实际采用的依赖与初期调研候选，任务状态统一见 [实现计划地图](14-RasterKV第一期实现计划地图.md)。

## 1. 已确认的目标

- 仓库及库导入名为 `raster`，存储对象为 `RasterKV<S>`，Rust 2024 edition，工具链和 MSRV 均为 1.98.1。
- 第一阶段复刻固定 FASTER C++ `FasterKv` 的功能与行为，包括混合日志、Pending、会话、检查点恢复、缓存、扩容和维护。
- 使用独立磁盘格式，不读取 C++ 日志或检查点。独立格式不减弱持久化进度、版本切分或恢复正确性要求。
- 正式平台为 Linux 与 macOS 基础本地文件后端；Windows、io_uring 和 F2 后置。
- Cargo 当前设置 `publish = false`；第一期交付不自动发布 crates.io，也不代表已经取得未来发布名称。

上游固定提交为 `321d872eabda6a0345c8bd76419f89723ed864ae`。原始源码事实见 [03](03-功能与API契约.md)，当前 Rust 对应与验证见 [功能对应表](acceptance/功能对应表.md)。P9 已确认普通盲删和安全索引移除；强制墓碑保留可达性是明确的上游兼容修正，交叉验收正在更新，见 [删除契约](acceptance/P9.1删除契约.md)。

## 3. 当前依赖决策

源头为 [Cargo.toml](../Cargo.toml) 和 [Cargo.lock](../Cargo.lock)，不是初期候选列表。核心无需外部 async runtime；无额外开发依赖。

| 用途 | 当前采用 | 依据与边界 |
| --- | --- | --- |
| 本地文件和目录能力 | 固定 `cap-std = 4.0.3` | 目录能力与受约束路径访问；[P4.2 依赖审计](acceptance/P4.2依赖审计.md) |
| TOML | 可选固定 `toml = 1.1.6`，仅 std/parse 特性 | `config-toml` 启用完整语法解析，字段映射和预算自行校验；[P8.1 依赖审计](acceptance/P8.1依赖审计.md) |
| 并发和完成 | 标准库 Mutex、原子量、线程及拥有型队列 | 当前完成邮箱与设备队列有锁，不宣称无锁或免竞争 |
| 对齐内存与生命周期 | `std::alloc::Layout` 与自有许可/租约封装 | Miri、编译约束和真实交错分别验证；不以一般分配库替代日志协议 |
| 身份、哈希与格式 | 系统随机身份；内建固定 FNV-1a 64；显式 v1 编码与校验 | 键编码版本、算法/种子、Schema 身份参与恢复拒绝；不用默认 Rust Hash 冻结格式 |
| 错误和观测 | 自有 Error/OperationError、Diagnostics/Statistics | 保留失败影响；不安装全局日志订阅器 |
| 验证 | 自有固定轨迹、BTreeMap 模型、故障设备、历史枚举器、原生测试与 Miri | 不是 Loom/proptest/criterion 已接入；基准由 examples 和审核脚本执行 |

许可证、MSRV 和实际依赖闭包已按锁文件审查，记录见上述阶段报告与 [P9.2 入口依赖与内存审查](acceptance/P9.2入口依赖与内存安全审查.md)。这些是固定版本的检查结果，后续更新依赖必须重新核查，不能将过去审计当作持续无漏洞承诺。

[06 存储与 I/O](06-存储与IO支持库调研.md)、[07 并发与验证](07-并发与验证支持库调研.md)、[08 格式与通用支持库](08-格式与通用支持库调研.md)保留初期 crates.io 调研的日期、候选版本和一手来源；不代表这些库已经进入依赖闭包或经过本项目实测。初版推荐组合及设计讨论可查 [固定历史版本](https://github.com/wayslog/raster/blob/52c0657661edc319e5e6bc4af2ab7518d88733f6/docs/05-RasterKV第一阶段与支持库选型.md)。

## 5. 已知限制与后续 TODO

当前可观察契约、错误影响与恢复边界见 [公开接口](10-RasterKV公开接口.md) 和 [状态协议](11-RasterKV内存与状态协议.md)。扫描不是有效键快照，日志跨度不是键数，请求完成/关闭不是检查点持久化完成。

P9.1 先前原始随机对照在 Null 和文件后端各有 396 处删除相关返回差异，这是旧实现的历史证据。现已确认删除契约，并同步 A02/A05；当前实现需要重新执行固定上游、强制墓碑参考修正和生命周期验收后才能关闭门槛。

旧 P3 完整八组同机复核已完成解释与处理，但吞吐和部分 P99 仍有明显差距，作为明确性能限制保留；见 [性能复核结论](acceptance/P9.2性能复核结论.md)。局部优化通过不构成达到旧内存原型或 C++ 吞吐的承诺。

后置范围保持不变：

- F2 热冷组合、跨层墓碑/迁移、组合检查点及 ColdIndex。
- 跨 store 条件插入与 `to_other_store` 压缩。
- Azure Blob 等远端设备、Windows 原生后端、Linux io_uring。
- 面向 Tokio 等运行时的可选 async 外观。
- 后续性能优化与更少共享登记竞争；必须保留本期完整协议并重新测量。

第一期最后文档快照与总验收仍按 P9 推进，不自动发布 crates.io。
