# RasterKV 内存与状态协议

更新日期：2026-09-12。本文描述当前实现应保持的不变量；P0—P9 已完成交付验收。具体 API 见 [10](10-RasterKV公开接口.md)，初版设计讨论见 [固定历史版本](https://github.com/wayslog/raster/blob/52c0657661edc319e5e6bc4af2ab7518d88733f6/docs/11-RasterKV内存与状态协议.md)。

## 1. Schema、键和值表示

[Schema](../src/schema/mod.rs) 是 Send + Sync 的共享策略，组合 KeyCodec 与 ValueLayout。KeyOf、OwnedKeyOf、OwnedValueOf 分别表示借用键、可借用回相同键的拥有键和拥有值。Operation/Output 只属于原 Session，可以非 Send；后台使用的 Schema 和 ValueLayout::Owned 则满足 Send + Sync。

KeyCodec 提供规范编码、完整哈希及 FormatId/HashDescriptor。相等键必须具有相同编码和哈希；tag 相同不能省略完整键比较。恢复在解释记录前检查格式身份、算法与种子，decode_canonical 再验证规范往返；不能更换哈希并静默重建以掩盖不兼容。

内建 ByteKey 使用原始字节、U64Key 使用八字节小端，固定 FNV-1a 64。SerializedValue<ValueCodec> 通过拥有型编码适配普通值，AtomicU64Value 通过原子视图访问整数。进程指针、锁状态和 Rust struct 内存布局不作为磁盘格式。

## 2. 安全视图与专家布局

安全业务回调接收 ValueRead/ValueUpdate，不接收可任意延长寿命的裸记录引用。ValueLayout 是 unsafe 专家 trait；方法和 Safety 约束以 [value.rs](../src/schema/value.rs) 为准。

| 能力 | 实际约束 |
| --- | --- |
| plan / plan_decode | 校验活跃尺寸、编码尺寸、容量、对齐和算术溢出；稳定字节长度不等于活跃表示大小 |
| initialize / decode_initialize | 只初始化未发布槽；错误或展开 panic 前清理自身已初始化子对象，恢复未初始化状态 |
| read / update | 返回受许可寿命约束的布局视图；原子访问不与无保护普通字节读取混用 |
| stable_encoded_len / encode_stable | 同一稳定访问期间长度与精确编码一致，不能读取未初始化 padding |
| decode_owned | 返回独立拥有值，语义与槽解码/读取一致，不借用输入或页 |
| drop_value | 仅对成功初始化的值，在最后访问结束后执行一次 |
| concurrent_updates | 默认为 false；声明 true 的布局必须保证多个更新视图同时安全 |

Init/Read/Update/Stable/DropPermit 由内部构造，携带范围、代次和生命周期。PhantomData 本身不构成安全证明；真实页所有者、记录租约和 MutationGate 提供存活及访问仲裁。业务 Output 的 'static 约束和编译失败示例限制短期视图逃逸。

## 3. 原地修改、稳定读取与替换

[MutationGate](../src/log/gate.rs) 将记录访问与存活区分：租约保证字节仍存在，值许可保证读取、原地更新和稳定编码之间的互斥关系。SerializedValue 的更新独占共享槽；AtomicU64Value 允许原子更新视图，但引擎仍有业务条带锁和版本仲裁，不宣称整体无锁。

复制替换必须取得源替换许可，重新确认最新键与索引快照，读取当前值、初始化目标并条件发布。索引 CAS 无法发现源地址未变的原地更新，不能单独替代源许可。原地更新也须重新检查版本、可变边界和记录未替换。

Append 必须在未修改旧值时返回；从更新转向替换前先释放许可，禁止锁升级。不可跨 Pending、设备等待或日志容量等待持有直接记录视图。下次推进重新获取许可并查找，不能继续使用过期页或链头。

内部 ValueAccess::Contended 只表示未取得许可，尚未调用布局或业务回调；请求继续等待。取得许可后用户/布局返回的 Busy 是实际错误，按影响终结，不能笼统捕获 Busy 重试。详细回归见下文“值许可争用与用户错误”。

## 4. 日志地址、页与回收

LogAddress、CacheAddress、PageId、Generation 分开表达逻辑位置与物理复用代次，不能将地址直接解引用。索引快照保存逻辑地址和表代次，不跨异步保留桶引用。磁盘格式为显式 v1 字节协议，见 [格式规范](acceptance/磁盘格式规范.md)。

[HybridLog](../src/log/mod.rs) 维护 begin、head、safe_head、read_only、safe_read_only、flushed_until 和 tail。begin 表示有效起点；read_only 阻止新的原地修改；安全边界必须等待相应访问结束；写出进度与检查点持久化分别记录。一次通用边界快照不代替后续访问时的重新验证。

分配返回未发布独占槽，初始化成功后才能构造预留记录。条件发布失败或放弃需撤销候选，不能让扫描看见半初始化对象；预留活动持续至发布判定及清理结束。页尾填充、invalid、墓碑均有显式解析规则。

页循环复用须满足冻结/写出或合法作废条件，且最后记录/设备相关引用已退出，再改变 generation。迟到完成须匹配请求、文件和页代次。预分配只准备物理容量，不推进逻辑 tail；泄漏租约可以阻挡复用，不能导致悬垂访问。

可变查找在日志边界锁内读取必要 begin/read_only/head，并检查页池中毒；特殊截断竞争再读完整边界。不承诺检查之后其他线程不会失败，安全仍由租约及许可维持，见 [边界查询记录](acceptance/P9.2可变记录边界查询.md)。

## 5. Epoch、检查点版本和同键许可

[EpochManager](../src/epoch/mod.rs) 负责参与者、嵌套 guard 和延迟动作；[Coordinator](../src/coordination/mod.rs) 负责身份、序号、版本切分和全局动作，二者不是同一个计数器。

参与者句柄持有稳定槽位及代次，进入/退出只锁定该槽位，不再查询全局槽位向量，也不在每次操作中克隆句柄。注册、注销、推进和收集仍受登记锁控制；需要两层锁时固定先登记表、后槽位。最外层进入记录当前访问 epoch，嵌套 guard 保留原 epoch，最后退出才清零。控制表或任一槽位中毒均停止后续进入和回收。

对象必须先从可见结构摘除，再登记延迟动作。可能见到旧对象的读者必须先进入，其槽位在最后 guard 退出前保留不晚于退休动作的 epoch；逐槽检查因此可保守延迟回收，但不能漏过仍在使用旧对象的读者。新读者只能在进入后取得对象，不能从已摘除的可见结构重新获得旧对象。正常用户 panic 的栈清理仍释放 guard，不将已存在的 unwind 误判为槽位中毒。

同步业务进入 epoch guard；返回 Pending 前释放直接记录访问。挂起状态保存逻辑地址、原序号、操作版本、拥有 I/O 状态及必要段租约。继续执行时重新取 guard、索引和记录许可，旧请求不能因为获得新 guard 就升级检查点版本。

开始动作与会话注册/退出共享协调锁，固定参与集合。会话提交/轮询自动观察阶段；同键版本许可让旧版本请求全部退出后新版本才执行，新版本不能原地修改旧版本记录。无业务但仍活跃的会话也须参加切分。

SessionRuntime 保存当前与前一 ExecutionContext。接受序号是严格递增、可跳号的应用标识；持久化切分须排除仍在途请求，不能用最大完成序号或全局 tail 冒充。

## 6. 拥有型 I/O 与完成路由

[Device](../src/device/mod.rs) 不接收 Schema、业务 Operation 或回调。DeviceFactory::open、poll、shutdown 使用共用 Error；submit 拒绝时归还整个 RejectedIo，接受后负责终结并归还拥有缓冲。

基本文件读写、短传输、同步、长度、目录、重命名、删除、枚举、跨实例锁、关闭和取消均为显式 IoOperation。IoCompletion 带 IoId、route、结果和可选缓冲；失败也归还缓冲。poll 全局失败或超时不能提前释放设备仍可能访问的字节。

[CompletionHub](../src/engine/io_hub.rs) 在接受业务请求前预留全局额度和不复用的路由号。Task 拥有不能克隆的 OperationRoute；同步结束时返还尚未登记邮箱的额度，进入 Pending 前才在邮箱表登记。尚未登记的操作与已有 I/O 邮箱共同受同一容量上限限制，不能把容量延后到回调之后检查。注册后的返还仍校验完整身份；未注册额度的返还不需要访问邮箱表，也不能解除其已中毒状态。

首次冷读或 RMW 查询到达 I/O 边界时，先停在提交前，完成邮箱登记，再继续这一次预提交暂停；必须在返回 Pending 前建立原有文件段保护并提交读取。这个继续点尚未调用值回调或发出 I/O，不能推广为回调错误或修改后失败的自动重试。同步路径未发出 I/O 时统计明确记录零次完成；可能存在 I/O 的已注册路径仍读取实际完成数。

轮询线程可投递别的会话完成，但不执行业务回调；原会话收取后继续原任务。当前已注册邮箱及设备队列仍采用锁保护，不是无锁完成队列。

Memory 用于可控设备协议验证，Null 不支持磁盘溢出/持久化；ThreadPool 提供正式 Linux/macOS 文件后端。Windows/io_uring 仍是后置入口，其能力不能由编译特性推断。

## 7. 接受、终结和失败影响

```text
未接受 --资源/序号/状态拒绝--> Rejected（归还输入，不消费序号）
   |
   +--接受--> 同步执行或拥有型 Pending
                   |
                   +--一次终结--> Ready 直接结果或 Ticket 完成结果
```

接受前准备须归还预留容量；非法序号在用户键逻辑前拒绝。部分键编码等准备回调可能执行后拒绝，因此“拒绝不执行业务修改回调”不等于从未调用任何用户策略。最终接受仍由全局登记校验。

计算可因真正内部冲突重做，不能重放已生效修改。OperationError 保留 NotApplied/Applied/Unknown；普通原地错误或 panic 在无法证明未修改时保留未知影响并失败关闭。Delete 原地标记墓碑使用与值读取、更新、冻结和条件复制共用的独占许可，只处理同版本可变记录；索引 CAS 成功后才标记，冲突重查。清除槽位仍保留单调空槽修订，旧空快照不能跨越一次插入/删除。Delete 生效后的 complete panic 不撤销删除，也不再次通知。票据一次收取，丢弃不取消，跨关闭结果仍有所有权。

结果预算控制块可复用但不复用 RequestId/generation；票据或完成端尚存都占名额。同步 Upsert 只在确实挂起时创建共享槽，接受、统计和失败收尾协议不变。具体协议和历史优化证据保留在下文。

## 8. 检查点发布、恢复与保留

Full/Index/Log 共用动作仲裁，但语义不同：Index 不宣布会话持久化，Log 绑定已提交且有效的索引基准，Full 自含索引与日志材料。成功启动票据不是提交成功；文件写出、同步、manifest 和最终 commit 都成功后才发布报告。

恢复先验证存储与 Schema 身份、算法/种子、token 配对、长度和校验，再重放模糊索引与版本过滤，准备独立工作副本；失败不发布半恢复实例。恢复后缓存为空，原会话经 continue_session 显式激活。旧检查点材料独立保留，后续原地更新不覆盖它们。

发布和恢复持共享 checkpoint.lock，显式释放持独占锁；释放验证磁盘上的实际 Log→Index/Full 保留图，不能只信内存缓存。先使 commit 失效并同步目录，再删除材料；失效状态、已确认删除及原始错误分别报告，支持重启后显式接续。细节见下文跨实例仲裁协议。

进程强杀、模拟未同步数据丢失与真实硬件断电不是同一种证据；验收记录说明模型和文件系统同步边界，不以一次重启成功证明任意断电安全。

## 9. 扫描、压缩和关闭

扫描使用短期稳定许可复制拥有键值，预读持有拥有页，不向应用借出页指针。逻辑截断使旧范围扫描返回 RangeTruncated。压缩重新核对最新源，在同步发布窗口内保护源值；多工作者不移交业务 Session/Operation。

GC 先排空相关写入，再清理索引和回收完整旧段；逻辑 begin 与物理删除分开。运行租约引发 DeferredByRuntime 时当前动作可终结，稍后再回收；检查点材料需要独立显式释放。

close 排空并注销会话；shutdown 停止自动接受、收取线程、排空设备并释放终态资源，超时保留可接续状态。不等待的异常 Session Drop 失败关闭；业务对象和设备缓冲各自按所有权回收。panic=abort 只能由进程恢复协议接管；mem::forget 可泄漏资源但不能破坏访问安全。

## P7.1 条件复制的同步发布窗口

压缩先按完整键重查当前主日志链，只有最新匹配地址仍为候选源才允许搬迁。源位于内存时，记录替换许可覆盖当前值编码、目标初始化及索引 CAS；源位于磁盘时只使用已验证拥有页，并在读完成后重新核对索引快照。复制等待不保留记录租约、Schema 拥有值或用户上下文。

目标初始化后，预留计数持续到 CAS 判定和冲突清理结束，扫描不能持有尚未发布的目标。业务条带锁只能减少冲突，不能替代源许可或处理不同条带的同桶竞争。目标编码错误是终结错误，即使其错误分类为 Busy 也不能误当源许可争用重试。

当前条件复制内核和公开单工作者压缩调度已实现；实施状态与证据见 [P7.1 交付记录](acceptance/P7.1压缩交付记录.md)。


### P7.2 工作段回收的实际边界

逻辑 begin 在全部业务仲裁内发布，索引逐桶清理保留空槽修订历史，缓存安装也在仲裁内重查动作和源边界。物理回收先停止新刷盘、排空已有写入，再越过作废完整页并等待记录/段租约。无需将 begin 之前的数据重新写出；跳过的 flushed_until 范围不代表已丢弃数据获得持久化保证。

读取整个页帧的租约覆盖跨段/短读及完成邮箱。段映射摘除后删除任务独占旧代次文件，按关闭、删除、目录同步推进；失败保存当前步骤，只由后续显式 GC 重试。运行期租约延后以 DeferredByRuntime 终结动作，独立检查点材料继续默认保留。检查点材料显式释放使用下述跨实例持久依赖协议。


### 检查点目录的跨实例仲裁

所有当前发布/恢复实例通过同一根目录的 `checkpoint.lock` 协调。发布及恢复取得共享锁，显式释放取得独占锁；文件不能被清理或替换。发布共享锁在创建检查点目录之前取得，覆盖材料创建、Log 基准重新验证及最终 commit 同步；恢复共享锁覆盖全部元数据、材料读取及恢复工作副本同步；成功报告及实例发布之前确认解锁关闭。锁文件自身不替代 commit/manifest 的持久化验证。

锁操作使用独立打开的句柄，不克隆锁所有权；发布/恢复的锁竞争完成 Busy 可继续推进；释放遇到锁竞争终结本次动作，由调用者显式重试。锁状态错误保留失败关闭路径。设备 Close/shutdown 显式解锁后关闭，避免并发进程创建暂时继承文件描述符而延长锁。目录枚举受条目和名称总字节预算限制，超限整体失败；枚举本身不保证并发快照。


释放持续持有同一独占锁，从 checkpoints/ 完整枚举到最终删除同步及关闭。目录读取同时校验存储身份、锁模式和句柄身份，不能在两次枚举之间解锁重加。完整 commit/manifest 图只把有效 Log→Index/Full 作为保留依赖；失效 token 不再提供新恢复集，未提交目录默认保留，损坏或未知对象阻止释放。全部参与者必须遵守同一锁协议；不支持其他程序绕过协议修改共享目录。

释放顺序为 `commit → commit.released` 重命名、同步 token 目录、逐材料删除并逐次同步目录。第一次目录同步完成前不删除材料，因而掉电后若 commit 仍可见，其材料仍完整。保留 manifest 和原 v1 commit 字节作为持久化删除意图，重启后可重新验证并继续；文件格式版本没有变化。正常错误只结束当前动作，不重放未知效果。即使删除实际成功但报告失败，下一次显式调用也从磁盘重建状态，允许材料已经不存在，再以目录同步确认。

本实例在接受失效重命名后取消同 token 的自动索引配对，确认失效同步后才移除运行期保留项。其他实例的缓存不能作为发布许可：其 Log 在共享锁内重新读基准 commit，若释放已经完成便拒绝发布。已恢复实例使用独立工作副本，对外可用后释放原检查点不影响其业务读取。


### P7.3 多工作者的拥有型状态与退出

单个协调驱动者保存扫描/候选状态；每个工作线程保存一个 ConditionalCopy 槽，槽中只有拥有型键、查询、完成路由、逻辑版本许可和段租约。记录值许可不跨 I/O，布局方法在有许可的同步步骤中执行；业务 Operation 和 Session 不移交给工作线程。

工作者空闲时仅持 Weak 存储引用，正常完成前收取全部线程，随后才能启动后续检查点或 GC。普通错误停止投递、排空读取、汇总实际发布计数后终结。panic 或协议错误先让全部工作者停止发布；结果可报告，但未知在途资源保持在任务槽中，设备结束后才销毁。不能为了返回错误提前复用段，也不能把线程退出当作 I/O 已归还。


### 自动调度、挂起读取与异常关闭

每个启用的实例持有一个自动调度控制块和线程句柄。线程只在单个推进步骤临时升级 Weak 引用，等待间隔与空闲时不保持 Engine 强引用。控制块持有一张当前任务票据，接受与停止在同一控制锁内排序；复制、设备推进和用户布局在锁外执行。停止禁止新接受，已接受任务按原协议完成。自动物理回收延后时只保存一个待重试标记，按配置间隔重新读取实际 begin，不累积删除任务。

公开停止状态要求线程已退出并 join。正常失败保留具体 CompactionFailed/GcFailed，禁止自动重跑。设备 poll 恐慌也进入引擎失败协议，先终结全局动作并停止发布工作者，再允许设备关闭。设备关闭后可以使用专用终态路径释放保留完成；该路径只回收拥有型缓冲，允许取得已中毒的轮询序列化锁，不清除中毒、不恢复运行权限、不执行业务回调。

挂起读取可能先保存旧索引，再由压缩搬迁记录并推进 begin。旧链返回 Missing 时必须重新核对索引快照；若已变化则丢弃已经结束且无在途 I/O 的旧查询，从当前头重新开始。否则活键可能被误报缺失。缓存源在读回调之前被逻辑截断时也重新解析索引。回调仍只在最终有效值上执行，原序号、票据和版本许可保持不变。

### 值许可争用与用户错误

驻留值的读取、原地更新和刷页稳定编码通过同一个 MutationGate 仲裁。只有未取得该许可时，内部 ValueAccess 才返回 Contended；此时尚未调用值布局的 read/update 或业务读写回调，原请求、序号、票据和版本许可保持不变。Read、Upsert、RMW 留在等待状态，下次推进重新解析索引和记录，避免沿用已经结束的查询。原地路径的影响恢复为 NotApplied，不能因这次内部争用使引擎失败关闭。

取得许可后，布局或用户代码返回的 Busy 是实际错误，按原影响协议终结一次；不能笼统捕获 Busy 并重试。原地回调可能已修改值，其错误仍保留 Unknown 和失败关闭规则；复制回调的错误仍是 NotApplied。上述区分仅属内部推进协议，没有增加公开状态或修改持久化格式。


### 同步 Upsert 的结果转交

初次推进前仍预留结果预算、请求身份和逻辑版本，再接受序号。若可同步终结，准备值及请求先按原影响协议收尾，记录完成统计后直接将拥有型结果移交给调用者；同步结果不需要共享票据槽。只有确实要继续推进时，才以同一请求身份和已预留预算建立 Ticket/Completer。

挂起请求的预算覆盖未收取结果；销毁票据不取消操作，收取结果后调用者继续持有输出不占用结果名额。两条路径均只终结一次，Ready 不构成持久化承诺。通用完成槽、会话线程边界、检查点切分和错误影响保持原契约。


### 结果预算控制块复用

会话保留不含用户数据的结果预算控制块池。只有池本身持有强引用时，该项才空闲；票据或完成端任意一方尚存都继续占用名额。Ticket 收取、销毁以及 Completer 的既有析构顺序不变，复用控制块不复用 RequestId、generation 或 I/O 路由。池在 SessionRuntime 析构时释放自身引用，结果仍可由票据跨关闭拥有。

控制块保留至历史同时占用峰值，正常配置下受 max_results 限制。顺序请求优先复用最早空闲项；若传入限额小于历史池长度，必须检查全部活跃名额，不能用空闲槽绕过更小限额。此保留仅涉及控制块和向量容量，不保留用户输出。计时、异常复核及交付边界见[结果预算复用记录](acceptance/P9.2结果预算复用.md)。


### 接受进度的本地预检查

SessionRuntime.current.last_accepted 用于用户键调用前的非法序号拒绝；创建及续接从注册表初始化，每次 admit 成功后同步更新，版本切分保留它。活动身份唯一，关闭对象不可重新提交。最终接受仍由全局注册表验证活动身份、版本、关闭状态和严格递增序号；本地值不替代全局登记，也不代表 durable progress。公开拒绝/恢复/重续证据见[序号预检查记录](acceptance/P9.2序号预检查.md)。
