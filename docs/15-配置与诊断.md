# RasterKV 配置与诊断

配置对象、完整默认 TOML 和统计输出以本文及实际接口为准。第一期平台是 Linux/macOS 基础文件后端；`io-uring` 特性仍只编译后置入口。阶段验收见 [P8.1 交付记录](acceptance/P8.1配置诊断交付记录.md)。

## 创建与解析

`Config::default()` 提供九组拥有型参数。Builder 的 `config` 接收完整对象，`device` 接收实际设备工厂，`create` 或 `recover` 校验并完成资源准备后返回实例。设备工厂及其线程数、队列容量由 Rust 代码选择，TOML 不实例化任意插件或执行代码。日志与缓存配置不会替代设备工厂的容量限制。

启用 `config-toml` 后可用四个入口：`from_toml_str`、`from_toml_file` 选择根表；`from_toml_str_at`、`from_toml_file_at` 以 `&[&str]` 选择嵌套子表，带点的键名作为一段，不再切分。仅显式选定子表时允许该子表外存在应用自己的配置；选定表内始终拒绝未知字段。解析结果不借用输入字符串。

```rust
# #[cfg(feature = "config-toml")]
# fn main() -> Result<(), raster::types::Error> {
use raster::config::Config;
let config = Config::from_toml_str_at(
    "[app.raster.log]\npage_bytes = 4096\nmemory_pages = 4\n[app.raster.statistics]\nenabled = true",
    &["app", "raster"],
)?;
assert!(config.statistics.enabled);
# Ok(())
# }
# #[cfg(not(feature = "config-toml"))]
# fn main() {}
```

[完整默认配置](examples/raster.toml) 的解析结果由测试直接与 `Config::default()` 比较。文件后端要求显式填写 `storage.root`；相对目录相对于进程当前目录，不自动以配置文件位置为基准。解析不创建目录、不打开存储设备。

使用完整 TOML 解析器处理引号、Unicode 转义、注释、内联表、点分键和各进制整数。文档最多 1 MiB，文件最多读取上限加一个字节；非 UTF-8、重复字段、语法错误、未知字段、错误类型、数值越界和无效组合均拒绝。`ConfigDocument` 仅保存静态分组名、UTF-8 字节偏移和静态原因，不回显原文、未知键名或文件路径；配置语义错误为 `InvalidConfig` 或 `CapacityExceeded`，文件系统错误保留为 `Io`。

时长既支持毫秒整数 `timeout_ms` / `check_interval_ms`，也支持 `timeout` / `check_interval = { seconds = 1, nanoseconds = 123 }`。同一时长的两种表示不能共存；纳秒小于十亿，时长非零且能转换为本平台截止时间。数值字段不从字符串或布尔值转换；比例接受整数或浮点，但必须有限且在相应范围内。

## 默认值与上游映射

上游固定为 `321d872eabda6a0345c8bd76419f89723ed864ae` 的 [config.h](https://github.com/microsoft/FASTER/blob/321d872eabda6a0345c8bd76419f89723ed864ae/cc/src/core/config.h)。RasterKV 使用明确字节单位和 Rust 字段名，不直接解析旧 C++ TOML 的别名；迁移时按下表转换。

| RasterKV 字段 | 默认值 | 生效方式与对应关系 |
| --- | --- | --- |
| storage.root / segment_bytes | 空 / 1 GiB | `filepath` 与独立分段格式；段至少一页且整除页长 |
| storage.pre_allocate_log | false | `hlog.pre_allocate`；预分配内存日志页 |
| index.buckets | 1024 | 上游索引容量换算为桶数，非零二次幂；恢复时需与材料桶数一致 |
| log.page_bytes / memory_pages | 32 MiB / 4 | `hlog.in_mem_size_mb` 转换成页长乘页数；页长至少 4096 且为二次幂，至少两页，乘积不能溢出 |
| log.mutable_fraction | 0.9 | 上游同名，有限且在 `[0,1)`；零仍保留安全的最小可变页窗口 |
| cache.enabled / capacity_bytes | false / 0 | `read_cache.enabled / in_mem_size_mb`；启用时容量必须非零，按实际记录计费 |
| cache.mutable_fraction / pre_allocate | 0.5 / false | 最近字节窗口与缓存负载预分配；具体等价策略见下节 |
| maintenance.auto_compaction / workers | false / 1 | `hlog.compaction.enabled / num_threads`；C++ 默认结构线程数为 4，Rust 默认 1 |
| maintenance.auto_compaction_policy.check_interval | 250 ms | `check_interval_ms`；有效非零时长 |
| maintenance.auto_compaction_policy.trigger_fraction / compact_fraction | 0.8 / 0.2 | `trigger_pct / compact_pct`，有限且在 `(0,1]` |
| maintenance.auto_compaction_policy.max_compacted_bytes / log_size_budget | 512 MiB / 0 | `max_compacted_size_mb / hlog_size_budget_mb` 转为字节；单次上限至少一页，启用自动压缩时预算显式非零 |
| maintenance.max_checkpoint_tokens / max_checkpoint_catalog_bytes | 4096 / 64 MiB | 显式释放检查点时扫描目录的 token 和累计元数据预算，含已失效目录 |
| maintenance.max_compaction_keys / max_compaction_key_bytes | 1,000,000 / 64 MiB | ScanDedup 的键数和键字节预算，Lookup 不累积去重键集合 |
| maintenance.max_compaction_workers | 64 | 每任务线程上限，worker 数必须非零且不超过上限 |
| session.max_sessions / max_pending / max_results | 96 / 1024 / 1024 | 活跃会话、每会话在途及未收取结果容量，均非零；派生 I/O 路由容量检查乘加溢出 |
| recovery.max_records / max_index_bytes / timeout | 1,000,000 / 128 MiB / 300 s | 恢复材料重放记录、索引输入与截止时间；索引预算至少 36 字节 |
| scan.max_scanners / timeout | 16 / 30 s | 活跃及排空中扫描器预算、同步等待时间，均非零 |
| statistics.enabled | false | 运行时控制历史采样；C++ 在编译 STATISTICS 后默认开启，Rust 选择默认关闭 |

所有容量上限都只约束对应资源，不能相加当作进程 RSS 上限。禁用的缓存/自动压缩不执行工作，但配置中的比例、时长及工作者边界仍校验。启用缓存但不能容纳单条记录时，正常读取完成，仅跳过可选缓存安装。

C++ 的 `DEFAULT_READ_CACHE_CONFIG` 实際只初始化 `enabled=false`，内存、比例和预分配处是被注释的设计意图；聚合初始化的其余值为零。Rust 明确选择比例 0.5，容量仍为零，不将注释中的 256 MiB 当作上游真实默认值。C++ 部分解析路径会警告后忽略未知字段，Rust 则拒绝，避免配置拼写错误被静默接受。

## 预分配与缓存窗口

日志预分配在创建或恢复发布前准备 `page_bytes × memory_pages` 字节的清零、对齐内存页；不提前推进 tail、建立逻辑记录或预留磁盘空间。循环回收等到所有 PageRange 退出后清零并复用原分配，逻辑页号和代次继续单调更新。恢复得到原检查点 end，旧页仍从磁盘读取。系统可能延迟为已分配地址空间提供物理页，因此这不是驻留内存承诺。

缓存预分配准备 `capacity_bytes` 字节的连续负载区，记录只持有互不重叠的范围租约。最后一个读者退出前，该范围不能重新分配；淘汰后仍被读者持有的记录继续计费。记录头及树节点另行分配；预分配不承诺后续零分配。容量或连续空洞不足时只跳过安装，实际业务值仍来自日志。

缓存记录始终不可变。`mutable_fraction` 定义最近插入字节窗口，位于窗口之外的命中将淘汰顺序移到尾部；窗口中的命中无需刷新。零表示每次命中都可刷新。上游用只读区命中后复制到缓存尾部达到保留热项的目的，RasterKV 只调整顺序元数据，保持缓存地址、索引头和已有读者字节不变；不复制 C++ 缓存页布局及“零比例转为两页”的特殊取整行为。差异影响缓存淘汰与 I/O 次数，不改变四操作结果、日志版本或持久化材料。

## 真实诊断

`RasterKV::diagnostics() -> Result<Diagnostics, Error>` 逐组件采样。它不是跨组件事务快照；并发中的字段可能来自相近的不同时刻，索引分布还会逐桶观察。调用不规范化缓存、不迁移桶、不推进维护，也不把观察本身算作索引查询。短时间无法取得一致的请求数量时可返回 Busy；锁中毒或资源错误明确返回错误。

| 字段 | 实际含义 |
| --- | --- |
| begin / tail / log_span_bytes | 同一次日志边界读取及 `tail - begin`，包含物理历史跨度，不是有效键数量 |
| active_sessions | 已注册且活跃的会话，不含尚未续跑的恢复身份 |
| active_requests / pending_requests | 已接受未终结业务请求 / 已返回 Pending 未终结业务请求；前者包括执行中的同步回调，后者不含完成但未收取的票据 |
| cached_bytes | 活跃及被读者保留的缓存记录计费，包括负载和记录结构；不含树节点和分配器元数据 |
| cache_reserved_bytes | 预分配负载区容量；未启用时为零，与 cached_bytes 有重叠，不能简单相加 |
| log_allocated_bytes / log_resident_pages | 页池负载分配量（含空闲预分配页）/ 已分配逻辑内存页数量，不是 OS 驻留页或 RSS |
| table_generation / bucket_distribution | 活跃表代次与各桶非空物理条目数；一个 tag 链可能包含多个键，不能解释为键数 |
| growing_index / migrated_buckets / retired_index_retained | 迁移目标表真实分布、已迁移旧桶数和仍被保留的旧表；扩容两表可以包含重复历史链头 |
| auto_compaction_scheduled / auto_compaction | 实际自动调度状态、任务、结果及预算到达状态；手动任务不冒充自动任务 |
| failed / shutdown_requested | 失败关闭和关闭进度标记，不代表关闭已完成 |

## 历史采样与输出

`enable_stats_collection` / `disable_stats_collection` 切换历史采样，`statistics` 返回拥有型快照，`write_statistics` 向调用方提供的 `Write` 输出中文汇总及 I/O 分布；写出失败返回 `Io`。库不安装全局日志订阅器，不默认打印用户键值。

四操作在序号接受后计数；拒绝、非法序号和接受前背压不计数。每个请求在接受时固定是否采样：关闭前已采样的请求仍记录到终结，关闭期间接受的请求不会在重新开启后补记。开关不清空历史；创建/恢复新实例从零开始，统计不进入检查点。实时资源数量始终可用。

每类记录 accepted、completed、同步终结数、Success/NotFound/Aborted/失败，以及失败中已生效与影响未知的子集；总失败数包含这些子集。条件复制单独统计，success 为实际复制，not_found 为源过时，不占业务在途数量。完成指结果交付到票据，不要求用户已经收取。

I/O 统计为请求邮箱在终结前收到的实际完成数，包括短传输续传；不是全设备提交数或字节放大率。后台刷页、检查点材料 I/O、路由注销后的迟到完成不记到该业务请求。挂起耗时从首次 Pending 到终结，包含应用延迟推进的时间，不冒充纯设备延迟。直方图分为 0、1、2–3、4–7，直到最高桶 `2^63..u64::MAX`；缺失测量的请求不进入直方图，`measurements_complete=false`，不能将其解释为零 I/O。历史计数采用饱和加法并设置 `saturated`，不回绕。

缓存和索引计数按每次内部事件时的开关采样：缓存查询、命中、插入、淘汰、顺序刷新；索引查询、合法发布尝试及冲突（含跨代旧快照）。一次业务操作可产生多个内部事件，不能用其比值推导业务请求命中率。refresh/maintenance 纳秒累计相应推进调用的墙钟时间；并发调用可能重叠，不代表 CPU 时间。
