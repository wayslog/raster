# RasterKV 各模块基础骨架

日期：2026-09-10。状态：**已建立 Rust 工程和可编译接口骨架；存储算法尚未实现**。本文落实 [09 模块设计](09-RasterKV模块设计.md)、[10 公开接口](10-RasterKV公开接口.md) 和 [11 状态协议](11-RasterKV内存与状态协议.md)，是接下来逐模块实施的入口。

## 1. 当前交付边界

- 一个 `raster` 库 crate，对外对象为 `RasterKV<S>`，暂不发布到 crates.io。
- 18 个职责模块均有实际 Rust 类型/接口文件，不只是目录或空 mod。
- 已实现的少量基础行为：配置校验、ValuePlan 校验、安全零初始化对齐缓冲、一次性结果槽、只读报告收取、共享 Schema 组合。
- 创建/恢复、会话注册、四种操作、真实设备、索引、日志、缓存和检查点尚未实现，返回带模块路径的 `Error::NotImplemented`。没有 `todo!()` 占位 panic，也不把空数据或成功状态用作桩结果。
- P1.1 已实现 `ByteKey`、`U64Key`；`SerializedValue<C>`、`AtomicU64Value` 仍待实现。测试中的 TestSchema 只验证类型和拒绝边界，不是生产值布局。
- 零外部依赖。P1.1 固定了键编码和哈希语义，详见 [类型与键契约](acceptance/P1.1类型与键契约.md)；磁盘材料格式仍由 P1.2 实现。

工程入口：[Cargo.toml](../Cargo.toml)、[lib.rs](../src/lib.rs)。Rust 2024 edition；只在当前 Rust 1.92.0 工具链验证，不据此宣称最低支持版本。Cargo.lock 固定本轮实际依赖图，目前只有本项目。

## 3. api：公开对象与操作面

文件：[store.rs](../src/api/store.rs)、[session.rs](../src/api/session.rs)、[operation.rs](../src/api/operation.rs)、[completion.rs](../src/api/completion.rs)、[maintenance.rs](../src/api/maintenance.rs)、[scan.rs](../src/api/scan.rs)。

`RasterKV<S>` 只拥有 `Arc<Engine<S>>`。Builder 收集 Schema、Config 和 DeviceFactory；create/recover 校验配置后仍返回未实现，设备工厂不会被提前调用。以后只有引擎完全就绪才允许创建公开句柄。存储根目录由 `Config.storage.root` 提供，具体设备验证它的语义。

`Session<S>` 持有共享引擎和自己的 SessionRuntime；Read/RMW 等的序号、选项和拥有型请求已经转交到对应 engine 入口。当前四种入口全部拒绝且归还请求，不消费序号、不执行用户函数。Session 中的本线程标记和任务对象使其不能 Send/Sync。

`Ticket<T>` 用本线程结果槽表达 Pending → Ready → Taken。Completer 只能由库内部创建，重复完成和重复收取都会报错。票据与会话没有 Rust 借用关系，完成端销毁后票据仍拥有结果。实际引擎尚未产生业务票据。

维护句柄使用共享最终报告，允许重复观察，与业务票据的一次收取区分。GC 物理删除可报告 `DeferredByRecoverySet`，不将合法保留集合当作全局动作永不终结的理由。扫描公开结果拥有键值，不借出长期日志指针。

后续：实现会话创建/关闭/失败退出、用户回调策略、维护等待推进、错误影响分类和扫描状态。未接入前不提供绕过 Builder 的公开构造函数。

## 4. types：身份、地址、错误与预算

文件：[id.rs](../src/types/id.rs)、[error.rs](../src/types/error.rs)、[progress.rs](../src/types/progress.rs)。

StoreId、SessionId、CheckpointToken、FormatId 使用独立 16 字节类型。P1.1 为前三者实现 Linux/macOS 系统随机身份生成与非零校验，FormatId 仍是固定语义 ID。LogAddress 和 CacheAddress 不可互换，已具备有效性、分页和溢出检查；EpochVersion 与 CheckpointVersion 也不共用类型。

RequestId 包含 store/session/slot/generation。HashDescriptor 将哈希算法标识与种子和键编码版本分开，供恢复一致性检查。数字类型暂未冻结磁盘位宽或压缩编码，公开字段不意味着任意值都可直接解引用。

`Error` 是初版共用错误分类；`Rejected<R>` 归还未接受输入，`OperationError` 增加 NotApplied/Applied/Unknown。TicketError 单独描述观察/收取错误。这里暂未为每个模块重复生成同构错误枚举，后续按实际恢复策略细分。

Deadline 使用单调时钟，PollBudget 要求非零，DrainReport 不包含持久化成功。后续序号单调性与身份合法性由会话/格式模块验证，不能仅靠 newtype 名称假定有效。

## 5. config：配置与校验

文件：[config/mod.rs](../src/config/mod.rs)。

六组配置为 storage、index、log、cache、maintenance、session。包含根目录、段尺寸、日志预分配、桶数、页尺寸/数量、可变区比例、缓存预算、压缩线程及在途/结果槽预算。

当前检查桶数/页尺寸的二次幂、日志内存乘法溢出、段尺寸整页关系、有限比例和非零资源预算。默认值仅用于骨架，不作为性能基线。空 root 可用于无文件设备，文件设备真正 open 时必须拒绝不合适路径。

`config-toml` feature 目前只暴露两个入口并返回未实现，不拉取 TOML 依赖、不假装完成解析。后续需要逐项映射原 C++ 配置名称、默认值、非法输入和平台选项。

## 6. schema：键和值的访问协议

文件：[key.rs](../src/schema/key.rs)、[value.rs](../src/schema/value.rs)、[builtin.rs](../src/schema/builtin.rs)。

KeyCodec 定义键借用类型、拥有键类型、编码、编码键相等比较、哈希和哈希描述。SchemaPair 将两个具体策略组合为共享 Schema，不强制用户每次操作使用相同输出类型。

P1.1 的 ByteKey 是原始字节编码，U64Key 是八字节小端编码；两者使用固定 FNV-1a 64 位哈希。validate_identity 拒绝编码版本、算法或种子变化，恢复调用由 P5 接入。

ValueLayout 为 unsafe 专家 trait，拥有值和生命周期相关 Read/Update GAT 分开。方法覆盖 plan、plan_decode、initialize、read、update、stable_encoded_len、encode_stable、decode_initialize 和 drop_value；内建字节槽与原子整数布局已实现。稳定长度与编码必须在同一受保护访问期间一致。安全用户实现 ReadOperation/RmwOperation 等，不直接构造许可。

Init/Read/Update/Stable/DropPermit 类型字段只在库内可见，包含范围、页代次和本线程约束；骨架没有铸造这些许可的运行路径。**PhantomData 本身不证明内存安全**，后续必须由真正的页租约和写入仲裁产生许可，才能实现布局适配器。

ValuePlan 当前同时检查活跃尺寸、磁盘尺寸、容量和对齐。ValueRead/ValueUpdate 的公开方法只借用布局专属能力；不能将共享日志转换为无约束 `&mut V`。测试布局不解引用指针，仅用于接口验证。

## 7. engine：编排与挂起任务

文件：[engine/mod.rs](../src/engine/mod.rs)、[read.rs](../src/engine/read.rs)、[upsert.rs](../src/engine/upsert.rs)、[rmw.rs](../src/engine/rmw.rs)、[delete.rs](../src/engine/delete.rs)、[pending.rs](../src/engine/pending.rs)、[progress.rs](../src/engine/progress.rs)、[conditional_copy.rs](../src/engine/conditional_copy.rs)。

Engine 聚合共享的 Schema、索引、日志、缓存、epoch、协调器和 storage。用户任务没有放进 Engine：它们通过 `Box<dyn PendingTask>` 保留在 SessionRuntime 的当前/旧版本 ExecutionContext 内，从类型结构上防止 !Send 上下文进入共享引擎。

PendingTask 接收拥有型 IoCompletion，返回 Complete/AwaitingIo/Retry/Failed；请求身份、序号和版本可检查。CompletionRouter 是完成投递与有限预算推进的接入点。它们目前是协议类型，尚无完整调度实现。

ConditionalCopy 专供压缩复用，不是公开第五种用户命令。它保留预期索引快照、源地址和拥有字节，后续必须取得源记录替换许可，不能只靠索引 CAS 检测原地值变化。

后续先实现“预检/接受 → 内存执行 → 需要挂起时保留原任务 → 终结结果”，统一处理错误和内部重试；拒绝必须保持当前未消费序号的契约。

## 8. index：索引项与表代次

文件：[index/mod.rs](../src/index/mod.rs)。

IndexHead 为 Empty/Log/Cache；EntrySnapshot 包含桶、tag、头和表代次；IndexImage 描述检查点材料。MemIndex 有 locate、compare_publish、snapshot、restore 和 grow_step，当前全部明确未实现。

索引只认识地址，不读取 Value、不直接访问设备。发布成功必须晚于记录初始化；涉及同键可变源时还需 engine/log 的共同更新仲裁。索引扩容通过表代次和 epoch 回收旧表，而不是让 Pending 长期持有桶指针。

后续验收：同 tag 不同键、溢出桶、发布冲突、扩容中读取、旧表回收、检查点中缓存头规范化。内部接口暂不承诺外部自定义异步索引 ABI。

## 9. log：页、记录和写入仲裁

文件：[log/mod.rs](../src/log/mod.rs)。

Frontiers 独立保存 begin/head/safe_head/read_only/safe_read_only/flushed_until/tail。PageState 用 frozen/closed/flushed、读者数、I/O 引用数与 generation 表达组合事实，避免把不同阶段混成一个“已完成”。

RecordReservation 表示未发布槽，finish_initialization 才能进入发布阶段；RecordLease 是本线程短期访问。它们没有实际构造/Drop 逻辑，尚不能访问页内存。HybridLog 的 reserve/lease/abandon/advance/flush 返回未实现。

MutationGate 区分 SharedUpdatePermit 与 ReplacementPermit。后续必须防止共享升级死锁，在等待磁盘或页空间前释放许可；RMW 读取—计算—发布须与原地修改共同仲裁。

后续优先：页面真实所有权、代次校验、许可 RAII、初始化失败清理，再连接并发发布和安全刷盘；不能先补一个无保护的裸指针 Get。

## 10. cache：读缓存

文件：[cache/mod.rs](../src/cache/mod.rs)。

CacheEntry 保存缓存地址、主日志源地址和版本。ReadCache 定义 lookup、insert_if_current、invalidate、normalize_head 和 evict_step；normalize_head 明确成为检查点过滤缓存地址的接口。

缓存失效与写入/删除共用索引预期值校验，不能把过期读取缓存成最新值。缓存必须在第一阶段完成，缓存容量和地址空间不能混入主日志 Size 或持久化格式。

后续验收：写后读、删除后读、缓存插入竞争、淘汰时在途读取、检查点恢复后缓存为空。

## 11. epoch：访问安全与延迟动作

文件：[epoch/mod.rs](../src/epoch/mod.rs)。

ParticipantId 带槽代次，EpochGuard 绑定参与者与管理器。DeferredAction 仅包含回收页、释放旧索引、推进安全只读地址；没有检查点版本或会话序号。

register/enter/defer/advance/unregister 尚未实现，也未产生“空 guard 就安全”的替身。后续应让 guard 真正记录访问状态，最慢参与者结束前不执行破坏内存的动作；mem::forget 造成的泄漏可阻碍进度但不能触发强行回收。

与 coordination 的联系只通过参与者状态和事件；禁止用一个全局整数同时表示页安全版本和检查点版本。

## 12. coordination：全局阶段与会话切分

文件：[coordination/mod.rs](../src/coordination/mod.rs)。

SystemState 组合 Action、Phase 和 CheckpointVersion。SessionCut 记录会话切分序号及旧挂起数量；Coordinator 使用内部锁占位承载状态，但锁的具体性能策略尚未确定。

start_action、enroll、acknowledge、fail_action 和 leave 尚未实现。后续需要统一原子地检查是否可注册新会话/发起动作，并固定阶段参与集合。旧请求不能因为取得新的访问 guard 就偷偷升级版本。

关闭、失败退出与 shutdown 都必须通过这里协调；成功排空和持久化确认分开，关闭入口后仍允许旧请求推进。

## 13. checkpoint：材料、发布和恢复

文件：[checkpoint/mod.rs](../src/checkpoint/mod.rs)。

CheckpointMachine 划分索引收集、会话切分、旧请求排空、冻结、写材料、同步、写 manifest、发布提交、完成/失败。RecoveryPlan 保存 manifest 和重放范围。

step、validate、replay_step 尚未实现。正常创建、恢复工厂会在该模块真正完成前拒绝返回运行实例。只有提交材料完整且持久化后才能构造成功报告。

后续需要完整/索引/日志三种子流程、模糊索引窗口、会话 durable prefix、格式与 hash 标识验证、较新记录过滤、恢复后继续会话。页末冻结和不覆盖已提交映像的策略不能被普通 flush 简化。

## 14. maintenance：复合维护与保留

文件：[maintenance/mod.rs](../src/maintenance/mod.rs)。

MaintenanceJob 用扫描、条件复制、推进 begin、清索引、回收段、检查点等步骤表达复合动作。ReclamationPlan 区分逻辑 begin 和保留恢复集的地址范围。

poll/deletable_segments 未实现。后续工作线程复用 engine 的条件复制，不向用户操作上下文发跨线程回调；自动压缩使用相同协议，不建立另一套隐藏状态机。

保留集导致的物理删除延后必须在报告中可见，并释放全局动作；不能边持有 GC 动作边等待由同一仲裁器启动的新检查点。

## 15. scan：物理扫描

文件：[scan/mod.rs](../src/scan/mod.rs)。

ScanCursor 持有当前位置、结束地址、截断代次和拥有型页缓冲。next_encoded 未实现；公开 RecordScanner 最终再解码为拥有键值结果。

无预读/单页/双页模式在公开 ScanOptions 中表达，不能将当前空缓冲列表理解为模式已经支持。后续需检查单条记录一致读取、变长补齐、跨页填充、墓碑/invalid、截断错误和扫描租约释放。

## 16. storage：段和命名空间

文件：[storage/mod.rs](../src/storage/mod.rs)。

SegmentedStorage 持有 Arc<dyn Device>、根目录和段尺寸；SegmentLocation 是 file/offset/generation。resolve、checkpoint_path 和 publish_plan 尚未实现。

这里集中管理日志段和检查点对象命名，不能让 engine/checkpoint 直接散落 fs 调用。后续发布计划显式列出数据同步、manifest 和命名空间动作；对路径做验证，不能允许对象名越出存储根目录。

## 17. device：请求所有权和后端

文件：[device/mod.rs](../src/device/mod.rs)、[buffer.rs](../src/device/buffer.rs)、[thread_pool.rs](../src/device/thread_pool.rs)、[memory.rs](../src/device/memory.rs)、[null.rs](../src/device/null.rs)、[uring.rs](../src/device/uring.rs)、[windows.rs](../src/device/windows.rs)。

DeviceFactory 创建共享前端；前端可以把非 Send driver 固定在专属线程。IoOperation 包含偏移读写、文件开关、同步、长度修改、目录同步/创建、发布 rename、删除和取消。取消结果的精细语义仍需后端实现时补全。

IoRequest 不携带用户上下文。接受后 Device 负责最终归还缓冲；IoCompletion 即使失败也保留 buffer。RejectedIo 原样归还未接受请求；对这个接口局部允许 Clippy 的大 Err 提示，以避免在容量不足路径为拒绝结果再分配。

AlignedBuffer 已用“额外分配并调整切片起点”提供真实对齐、零初始化、固定容量和独占可写切片，全程无 unsafe。它有额外空间和清零成本，是基础正确性实现，不宣称达到原分配器性能；后续可在同一接口换 aligned-vec 或专用分配器。

所有设备工厂当前 open 都返回未实现。Memory 是可控测试磁盘，Null 是无后备存储，两者不能混用；Linux io_uring 按 target 和 feature 编译，Windows 按 target 编译。本机检查不代表其他 target 已通过。

## 18. format：独立磁盘格式

文件：[format/mod.rs](../src/format/mod.rs)。

RecordHeader 描述前驱、检查点版本、键值长度/容量、墓碑、invalid 和 final。Manifest 描述存储、键/值/哈希语义、版本、地址范围和会话进度；字段还需扩展材料清单、校验和及匹配规则。

当前没有 `repr(C)` 直接落盘，所有 encode/decode 都返回未实现。不能拿结构体 size_of 生成持久化文件。后续先制定规范和固定字节样例，再实现有边界检查的解析及损坏输入测试。

## 19. sync：并发原语接入点

文件：[sync/mod.rs](../src/sync/mod.rs)。

目前统一重导出标准库 AtomicU64/Mutex/Ordering，PUBLISH_ORDER 明确为 SeqCst。未来内部协议的小模型通过专用配置切换到 Loom，不能在同一个模型里将标准原子与 Loom 原子混用后宣称已覆盖。

当前没有引入 Loom 或实现模型测试；基础 compile_fail 只验证 Send/Sync 和借用约束。辅助 API 的 Rc 结果槽属于单线程，不应为使用统一原子入口而机械替换它。

## 20. diagnostics：真实、结构化的状态

文件：[diagnostics/mod.rs](../src/diagnostics/mod.rs)。

Diagnostics 包含日志跨度、begin/tail、会话/在途数量、缓存字节数、自动压缩状态、索引代次和桶分布。读取入口暂时返回未实现，避免全零报告被误读为健康存储。

后续逐项定义瞬时/累计统计、并发采样一致性及单位，接入可选 tracing；不由库安装全局 subscriber，也不默认输出用户键值。

## 21. 骨架与原设计的具体化差异

1. 各模块暂共用 Error，业务结果用 OperationError + Effect，票据用 TicketError；避免骨架阶段复制大量同构枚举。具体模块错误仍由 module/cause 保留。
2. Diagnostics 改为 Result，因为当前不能提供真实状态；create/recover 也完全禁止伪造成功。
3. KeyCodec 增加 HashDescriptor，避免将键编码 ID 和哈希算法/种子混成一个字段。
4. 增加 storage 配置、Null 和 Windows 工厂类型，补齐设备接入信息；未增加真实 OS I/O 实现。
5. 内建 Schema Adapter 的实现推迟到哈希与许可可验证时；没有给不安全内存访问提供空实现。
6. 内部未接入模块局部允许 dead_code，接口编译示例有具名原因说明；不是关闭 unsafe 检查。实施模块时移除对应抑制并将接口接入真实路径。
7. 运行期共享的日志分配、缓存维护和索引扩容使用 `&self` 接口，原子状态和控制锁封装在模块内，避免 Arc<Engine> 无法调用 `&mut self`。实例发布前的独占索引恢复仍可使用 `&mut self`。
