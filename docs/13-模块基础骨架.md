# RasterKV 模块实现与接入地图

更新日期：2026-09-12。最初骨架已演进为真实存储实现，本文按当前代码列出18个模块的状态、入口、不变量与验证位置。P0—P9 已完成交付验收；状态台账只维护在 [14](14-RasterKV第一期实现计划地图.md)。P0/早期 P1 的原始骨架记录见 [固定历史版本](https://github.com/wayslog/raster/blob/52c0657661edc319e5e6bc4af2ab7518d88733f6/docs/13-模块基础骨架.md)。

## 1. 工程基线

一个 raster 库 crate，Rust 2024 edition，工具链和 MSRV 1.98.1，暂不发布 crates.io。直接依赖为固定 cap-std 4.0.3 和可选 toml 1.1.6；依赖闭包由 Cargo.lock 固定。基础文件后端正式覆盖 Linux/macOS；Windows/io_uring 后置。

[lib.rs](../src/lib.rs) 公开 api/types/config/schema/device/diagnostics 六模块，其余十二模块内部使用。生产索引为 MemIndex，公开类型只有 RasterKV<S>，没有第三方索引注入泛型。架构见 [09](09-RasterKV模块设计.md)，实际 API 见 [10](10-RasterKV公开接口.md)，内存及状态协议见 [11](11-RasterKV内存与状态协议.md)。

## 2. api：应用对象与结果边界

入口：[store.rs](../src/api/store.rs)、[session.rs](../src/api/session.rs)、[operation.rs](../src/api/operation.rs)、[completion.rs](../src/api/completion.rs)、[maintenance.rs](../src/api/maintenance.rs)、[scan.rs](../src/api/scan.rs)。

RasterKV 只共享 Arc<Engine>；Builder 完成创建/恢复准备后发布。SessionRuntime 留在本线程，Session/Ticket 不可 Send/Sync，多个异构票据不占用会话借用。Read/Upsert/RMW/Delete 返回 Rejected 或已接受的 Ready/Pending，错误影响由 OperationError 表达。

Ticket 一次收取，维护 SharedReport 可重复观察；close/shutdown/Drained 不等于检查点完成。真实入口验证为 tests/p3_lifecycle.rs、p3_failures.rs、p5_recovery.rs、p6_scan.rs 和五个公开示例。源码 doctest 验证线程及视图边界，不能只验证类型可编译。

## 3. types：身份、地址与失败信息

入口：[id.rs](../src/types/id.rs)、[error.rs](../src/types/error.rs)、[progress.rs](../src/types/progress.rs)。

StoreId/SessionId/CheckpointToken 为不同的16字节身份，系统随机生成并拒绝无效值；FormatId 表示固定语义。LogAddress 与 CacheAddress、EpochVersion 与 CheckpointVersion 分开；地址计算检查有效性和溢出。RequestId 包含 store/session/slot/generation，不能用单个槽号匹配迟到完成。

Error 为共用错误枚举；Rejected 归还未接受输入，OperationError 保留 Effect，维护失败保留部分生效报告。Deadline 使用单调时钟，PollBudget 非零。验证见 tests/p1_keys.rs、P1.1类型与键契约、p3_failures 和维护错误测试。

## 4. config：配置准备与预算

入口：[mod.rs](../src/config/mod.rs)、[document.rs](../src/config/document.rs)、[tests.rs](../src/config/tests.rs)。

九组为 storage/index/log/cache/maintenance/session/recovery/scan/statistics。Config::validate 检查尺寸、比例、预算、组合与溢出；Builder 在设备打开前校验。空 root 只适合无文件设备，文件工厂验证实际路径。

config-toml 通过完整解析器提供字符串/文件及各自子表入口，拒绝未知字段、错误类型和超限输入，不回显私人原文/路径。实际默认、上游迁移差异和运行入口见 [15](15-配置与诊断.md)；配置单元测试包含文件、子表和完整创建生命周期。

## 5. schema：规范键与值生命周期

入口：[key.rs](../src/schema/key.rs)、[value.rs](../src/schema/value.rs)、[builtin.rs](../src/schema/builtin.rs)、[builtin/layout.rs](../src/schema/builtin/layout.rs)。

SchemaPair 组合 KeyCodec 和 ValueLayout。ByteKey/U64Key 提供规范字节与稳定哈希；恢复验证身份后解码并重新核对编码。SerializedValue<ValueCodec> 适配普通值，AtomicU64Value 提供原子整数；ValuePlan 分别描述活跃尺寸、磁盘尺寸、容量和对齐。

许可由日志模块真实构造，ValueRead/ValueUpdate 不允许视图逃逸。unsafe ValueLayout 的初始化失败清理、稳定编码、拥有解码和一次销毁必须覆盖扫描/缓存/恢复，不能只验证读写成功。验证见 tests/p1_keys.rs、p1_values.rs、布局单元测试、Miri及 [P2.2](acceptance/P2.2页内存交付记录.md)。

## 6. engine：运行任务与跨模块编排

入口：[mod.rs](../src/engine/mod.rs)、[pending.rs](../src/engine/pending.rs)、[progress.rs](../src/engine/progress.rs)、[io_hub.rs](../src/engine/io_hub.rs)、[version_permit.rs](../src/engine/version_permit.rs)。四操作分别位于 read/upsert/rmw/delete.rs。

Engine 聚合共享组件及维护任务槽，不持有用户非 Send 操作；这些任务保存在 SessionRuntime 的当前/前一 ExecutionContext。prepare 在调用用户键前拒绝非法序号，admit 仍由全局登记最终验证。CompletionHub 有界预留和按身份回送，版本许可隔离同键跨版本操作。

继续执行须重查索引、截断与记录许可；内部 Contended 只表示没有取得许可，不能吞掉用户 Busy。同步 Upsert 直接移交结果，Pending 才建立票据。结果预算控制块复用不复用请求身份。主要验证为 p3_model/p3_history/p3_failures、pending_read_tests、value_contention_tests、p9_history 和故障矩阵。

维护运行入口分布在 checkpoint/growth/scan/compaction/gc/checkpoint_release/auto_compaction/storage_progress.rs；修改同名低层模块时必须同时验证这些真正的调用方。

## 7. index：条件发布与表代次

入口：[mod.rs](../src/index/mod.rs)、[growth.rs](../src/index/growth.rs)、[gc.rs](../src/index/gc.rs)，运行驱动见 [engine/growth.rs](../src/engine/growth.rs)。

MemIndex 保存桶和溢出链；prepare 返回带修订及代次的 EntrySnapshot，compare_publish 检查预期后更新链头。完整键比较由日志/引擎完成，不能只比 tag；缓存头进入持久映像前转为主日志地址。

扩容增量迁移并保护旧表，Pending 按当前代次重定位；GC 清理需保留空槽修订历史。IndexImage/格式模块负责明确的检查点字节。验证见 index 单元测试、growth_tests、online_tests 和 [P6.1](acceptance/P6.1索引扩容交付记录.md)。

## 8. log：页、记录与访问许可

入口：[mod.rs](../src/log/mod.rs)、[page.rs](../src/log/page.rs)、[value.rs](../src/log/value.rs)、[gate.rs](../src/log/gate.rs)、[lookup.rs](../src/log/lookup.rs)、[flush.rs](../src/log/flush.rs)、[evict.rs](../src/log/evict.rs)。

HybridLog 维护逻辑/安全/写出边界，PagePool 管理对齐容量与复用代次，RecordAllocation/Reservation 隔离未发布初始化，RecordLease 与 MutationGate 分别保证存活和访问仲裁。扫描/稳定编码不能读取正在修改的非原子字节。

查链覆盖驻留与冷历史；刷盘交出拥有字节，页复用等待必要引用退出。预分配不推进 tail，页尾填充/墓碑/invalid 按格式解析。验证见 [P2.2](acceptance/P2.2页内存交付记录.md)、[P4.3](acceptance/P4.3混合日志交付记录.md)、frozen_tests、scan_page_tests、值争用和GC回归。

## 9. cache：来源校验与淘汰

入口：[mod.rs](../src/cache/mod.rs)、[arena.rs](../src/cache/arena.rs)、[engine/cache.rs](../src/engine/cache.rs)。

ReadCache 具有容量和最近字节窗口，缓存记录保留主日志来源。冷读安装与业务写入/删除交错时重查索引，命中也验证来源有效；淘汰读者退出前不复用其负载。预分配只准备容量，恢复从空缓存开始。

验证见 cache 单元测试、cache_tests、online_tests、p5_recovery 以及 [P6.2](acceptance/P6.2读缓存交付记录.md)。缓存地址不能进入持久恢复材料。

## 10. epoch：访问退出与延迟动作

入口：[mod.rs](../src/epoch/mod.rs)。

EpochManager 注册带代次的参与者，enter 返回可嵌套 EpochGuard，defer/advance/collect 在安全访问结束后交付延迟动作。unregister 不能把仍参与中的访问视为退出；泄漏 guard 允许阻挡回收，不允许提前释放内存。

它不维护业务序号、检查点切分或全局动作。实际接口的交错枚举与边界测试见模块测试及 [P2.1](acceptance/P2.1回收协议.md)，不是 Loom 检查。

## 11. coordination：会话与动作切分

入口：[mod.rs](../src/coordination/mod.rs)、[action.rs](../src/coordination/action.rs)、[engine/observe.rs](../src/engine/observe.rs)。

Coordinator 在同一注册表锁内维护身份、活动状态、接受序号、SystemState 和参与集合。恢复身份保留 durable cut，续接重新激活；当前接受进度不退回检查点。动作互斥、阶段确认与退出有实际状态转换。

提交和轮询自动观察版本，旧请求始终属于旧 ExecutionContext。必须等待相关参与者/旧请求后才完成切分；不能将闲置活跃会话自动删除。验证见协调器测试、pending_read_tests、p5_recovery 和 [P5.1](acceptance/P5.1阶段协调交付记录.md)。

## 12. checkpoint：材料、提交、恢复与保留

入口：[mod.rs](../src/checkpoint/mod.rs)、[publication.rs](../src/checkpoint/publication.rs)、[recovery.rs](../src/checkpoint/recovery.rs)、[replay.rs](../src/checkpoint/replay.rs)、[retention.rs](../src/checkpoint/retention.rs)、[catalog_lock.rs](../src/checkpoint/catalog_lock.rs)；运行驱动为 engine/checkpoint.rs、engine/checkpoint_release.rs、api/recover.rs。

索引/日志材料、manifest、commit 分步同步；Full/Index/Log 有不同持久化承诺。恢复校验完整配对和 Schema，重放后准备独立工作副本。发布/恢复共享目录锁，释放独占锁，按持久 Log→Index/Full 依赖图拒绝破坏被保留集合。

失效先重命名并同步 commit，再删除材料，保留可跨重启接续的证据及失败影响。验证见 p5_recovery、checkpoint_crash_tests、checkpoint_power_model、checkpoint_release_crash_tests，交付记录为 [P5.4](acceptance/P5.4恢复安全交付记录.md) 与 [P7.2](acceptance/P7.2回收交付记录.md)。

## 13. maintenance：候选选择与复合任务

入口：[scan.rs](../src/maintenance/scan.rs)、[engine/conditional_copy.rs](../src/engine/conditional_copy.rs)、[engine/compaction.rs](../src/engine/compaction.rs)、[engine/compaction_workers.rs](../src/engine/compaction_workers.rs)、[engine/auto_compaction.rs](../src/engine/auto_compaction.rs)、[engine/gc.rs](../src/engine/gc.rs)。

低层模块负责扫描候选和去重预算，engine 负责单/多工作者、复制发布、可选后续检查点和截断、自动调度及停止。ConditionalCopy 是内部内核，不是公开第五种业务命令；源重查和替换许可保护真实当前值。

普通 Compact 不暗中移动 begin；选项显式决定后续动作。GC 将逻辑边界与物理删除分开，租约延后也终结本次动作，错误保留已复制/已删除效果。验证见 p7_compaction、conditional_copy_tests、compaction_chain_tests、auto_compaction_tests、gc_tests 和 [P7.3](acceptance/P7.3自动维护交付记录.md)。

## 14. scan：物理读取与拥有输出

入口：[page.rs](../src/scan/page.rs)、[record.rs](../src/scan/record.rs)、[engine/scan.rs](../src/engine/scan.rs)、[api/scan.rs](../src/api/scan.rs)。

运行注册表保存扫描身份、页请求与关闭状态；解析器处理页末填充、变长记录、invalid 和墓碑。三种模式按需当前页及预读一/两页。ScannedRecord 拥有键和值，应用保留结果不会长期借用日志。

next_record 可输出旧记录和重复键；RangeTruncated 明确终止失效范围，close 排空已接受预读，超时可续。验证见 tests/p6_scan.rs、scan_tests、scan_page_tests 及 [P6.3](acceptance/P6.3物理扫描交付记录.md)。

## 15. storage：分段映射与文件寿命

入口：[mod.rs](../src/storage/mod.rs)、[open.rs](../src/storage/open.rs)、[transfer.rs](../src/storage/transfer.rs)、[reclaim.rs](../src/storage/reclaim.rs)。

SegmentedStorage 将逻辑地址拆成段及偏移，绑定 FileId/Generation，维护跨段请求与读取租约。短传输按实际完成字节继续；迟到或错代次完成不能访问已复用段。

工作段回收按关闭、删除、目录同步推进，只有同步确认后计入报告；失败保存步骤供显式重试。检查点材料在独立目录发布，不能将工作段删除当作恢复集释放。验证见 storage/tests.rs、p4_files、gc_tests、p7_metadata。

## 16. device：拥有型设备及本地后端

入口：[mod.rs](../src/device/mod.rs)、[buffer.rs](../src/device/buffer.rs)、[thread_pool.rs](../src/device/thread_pool.rs)、[local_files.rs](../src/device/local_files.rs)、[memory.rs](../src/device/memory.rs)、[null.rs](../src/device/null.rs)。

DeviceFactory 创建尚未服务的设备，Device 报告真实能力。IoRequest 拥有缓冲与操作，RejectedIo 完整归还，IoCompletion 带回身份、结果和缓冲。线程池队列有界且有锁；用户 Schema/Operation 不进入设备线程。

ThreadPool 使用实际文件及目录同步、锁和命名空间操作。Memory 验证可控协议，Null 用于受限内存；uring/windows 文件是明确后置入口。验证见 tests/p4_device.rs、p4_files.rs、原生故障矩阵及 [P4.2](acceptance/P4.2本地文件后端.md)。

## 17. format：独立 v1 字节协议

入口：[wire.rs](../src/format/wire.rs)、[record.rs](../src/format/record.rs)、[page.rs](../src/format/page.rs)、[index.rs](../src/format/index.rs)、[manifest.rs](../src/format/manifest.rs)。

记录、页、索引、manifest 和提交使用明确字段和字节序；长度、边界、身份、版本与校验均验证。禁止序列化 Rust 对象内存镜像、活动锁或缓存指针。v1 已在 P5.4 冻结，后续变更必须明确兼容/拒绝规则。

tests/fixtures 中的固定十六进制字节是独立预期，损坏/截断输入测试不与实现共同生成预期。规范和恢复边界见 [磁盘格式规范](acceptance/磁盘格式规范.md)。

## 18. sync：并发原语入口

入口：[mod.rs](../src/sync/mod.rs)。

目前重导出标准库 AtomicU64/Ordering/Mutex/MutexGuard，发布顺序为 SeqCst。并非所有内部锁都必须经重导出，模块存在也不代表支持无锁执行或 Loom。

弱化顺序或更换同步原语需要新的交错/内存验证与真实性能证据，不能只因编译通过而调整。epoch、索引、值许可和完整历史测试分别验证其协议。

## 19. diagnostics：真实观察与统计

入口：[mod.rs](../src/diagnostics/mod.rs)、[engine/metrics.rs](../src/engine/metrics.rs)、[api/store.rs](../src/api/store.rs)。

Diagnostics 观察真实日志边界、活跃会话、同步/挂起请求、页/缓存分配、扩容分布与自动维护。Statistics 计四操作、条件复制、缓存/索引和 I/O；采样在接受时固定，关闭采样不抹去在途终结，溢出饱和并标记。

观察不构成全局事务快照；日志跨度和桶占用不能充当键数。输出位置由应用提供，不安装全局订阅器。验证见 p8_tests、metrics 单元测试和 [P8.1](acceptance/P8.1配置诊断交付记录.md)。

## 20. 后续接入和交付检查

修改模块时先确认其不变量及 engine 调用链，再运行对应真实入口和必要交错；低层模型成功不能代替业务验收。基础命令：

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-features
cargo test --locked --examples --all-features
RUSTDOCFLAGS='-D warnings' cargo doc --locked --all-features --no-deps
```

正式交付还需指定提交的 Linux/macOS 原生制品、故障/历史、资源、上游以及适用性能证据，入口见 [环境与命令](acceptance/环境与命令.md) 和 [工具说明](../tools/acceptance/README.md)。

当前第一期正常运行入口的占位检查见 [P9.2 入口审查](acceptance/P9.2入口依赖与内存安全审查.md)；后置平台入口不能计作支持。P9.1 删除契约已确认；修改后的交叉验收、P9.2 整体验收与 P9.3 最终快照仍待完成；F2、ColdIndex、跨 store 压缩、远端设备、Windows/io_uring 及 async 外观继续列为后续范围。
