# RasterKV 调研与设计文档

本项目的 Rust 存储对象命名为 **RasterKV**。第一阶段完整复刻 FASTER C++ `FasterKv` 的功能与行为，使用独立文件格式；F2 等高级功能列为后续 TODO。当前已有模块代码骨架，存储算法尚未实现。

本目录包含上游调查、支持库选型和 Rust 设计。01–04 为上游源码调查；05–08 为第一阶段范围及 crates.io 支持库选型；09–12 为模块、公开接口、内存/状态协议和三种接口方案比较。范围以 05 中的已确认决定为准；09–12 是建议设计，尚未实施，历史源码事实保持原名称。

后续统一执行入口为 [第一期实现计划地图](14-RasterKV第一期实现计划地图.md)，包含 P0—P9 的依赖、任务状态与验收门槛。P0、P1.1 已完成，下一项为 P1.3。第一期平台已确认 Linux + macOS 基础本地文件后端，Windows/io_uring 后置。

代码接入位置见 [各模块基础骨架](13-模块基础骨架.md)，设计背景见 [RasterKV 模块设计](09-RasterKV模块设计.md)；范围和依赖背景见 [第一阶段范围与支持库选型](05-RasterKV第一阶段与支持库选型.md)，术语见 [CONTEXT](../CONTEXT.md)。

## 总体判断

P0 验收入口：[功能对应表](acceptance/功能对应表.md)、[环境与命令](acceptance/环境与命令.md)、[轨迹与故障契约](acceptance/轨迹与故障契约.md)、[P0 验收报告](acceptance/P0验收报告.md)。

P1.1 验收入口：[类型与键契约](acceptance/P1.1类型与键契约.md)、[P1.1 验收报告](acceptance/P1.1验收报告.md)。

C++ 部分是以模板为主的嵌入式键值存储库。`FasterKv` 将哈希索引、混合日志与异步设备组合；`F2Kv` 进一步组合热存储和冷存储。核心实现集中在头文件，静态库只编译少量平台和基础设施 `.cc` 文件，不能按编译单元数量估计改写规模。

“API 输出”在这里指 C++ 库方法的返回值、出参、上下文结果、异步回调和持久化标识，并非 HTTP 服务接口。C# 目录中的接口和产品能力不自动计入 C++ 功能范围。

建议先阅读结构文档，再沿 `FasterKv → 操作上下文 → 索引 → 混合日志 → 设备 → 完成队列` 理解读写，最后阅读检查点和 F2。对照 API 文档时，重点区分“请求已受理”“异步请求完成”和“检查点持久化完成”。

## 已定位、尚未运行验证的问题

- `F2Kv::Recover` 未给调用者的 `version` 出参赋值，底层恢复失败的部分路径未复位 F2 阶段，详见 API 文档第 6 节。
- 磁盘读取的 I/O 错误分支直接调用用户回调，不能无条件承诺所有回调均在发起线程执行，详见架构文档第 5.3 节。
- 两个检查点元数据工具对 `fread` 返回值的检查有误，且未检查 `fopen` 失败；部分示例帮助与基准注释不符合实现，详见结构文档第 5、6 节。
