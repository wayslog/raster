## 8. 2026-10-19 修订：单键四线程争用的 P99 改为记录项

**用户决策**：`memory/upsert/shared-hot/4` 和 `memory/rmw/shared-hot/4` 的 P99 对 C++ 改为只记录、不卡验收。H3 的其余各项不变。

### 依据

- 收尾矩阵在 `memory/upsert/shared-hot/4` 处触发 H3 停止：候选 730.5 ns，C++ 705.5 ns，固定 Rust 基线 721.5 ns（报告见 `.perf-baseline/closeout/resume-20261019/report.md`）。固定基线同样高于 C++，说明这不是本轮引入的回退。
- 诊断实验（证据在 `.perf-baseline/closeout/shared-hot-diagnostic-20261019/`）：
  - 实验变体用同一引擎源码 `49f882d` 构建，只在 `examples/parity.rs` 的计时区间之外加入一个默认不执行的循环（`RASTER_DELAY=0`）。
  - 在正式的逐线程绑核方式下（worker 用 CPU 4–7，协调器用 8），与正式候选二进制、C++ 交替运行共 10 轮。
  - P99 中位数：C++ 约 711 ns，正式候选约 735 ns，引擎相同的驱动变体约 688 ns，低于 C++。驱动变体的吞吐约低 2%。
- 结论：4 个线程更新同一个键时，P99 由同一条缓存行的争用公平性以及驱动循环时序决定，不能反映引擎单次操作的延迟。Rust 吞吐比 C++ 高约 37%，争用强度本来就不同。

### 执行要求

1. **不修改** `examples/parity.rs` 或任何驱动来让该项通过；那个实验变体只用于诊断，不得合入。
