# ADR 0003：延迟日志操作的所有权与扫描借用边界

日期：2026-10-23。状态：已实现。范围为 PR #1 的 Standards / Spec 正确性修复。

## 问题

`HybridLog` 是可移动、可单独销毁的公开类型。epoch 动作和异步写回调捕获指向它的裸指针，不能靠“store 仍然存活”的约定保证安全：外部仍持有 epoch 时，已销毁日志的动作还能执行；尚有写入时移动日志也会使旧地址失效。两种情况均已用 Miri 复现。

扫描记录同时暴露 `&AtomicU64` 和覆盖同一内存的 `&[u64]`，允许纯安全代码并发进行原子写和非原子读。仅把字段改为私有仍会创建重叠引用，不能消除问题。

后续复审还发现两个纯安全调用缺口：`shift_read_only_to` 接受超过配置页大小的偏移，部分扇区复制会越界；公开的 `load_page(&self)` 可以与扫描并发覆盖同一页。两者在修复前均经 Miri 复现，不能只靠注释限制调用时机。

## 决策

将页帧、日志边界和刷盘状态放进地址稳定的 `Arc<HybridLogStorage>`。`HybridLog` 仍持有 epoch 和设备；延迟动作持有 storage，刷盘动作同时持有设备，I/O 回调只持有 storage 和必要的部分扇区缓冲。storage 不反向持有 epoch 或设备，避免队列循环引用及设备在线程池回调内成为最后一个所有者。句柄析构仍等待已提交写入；页帧由最后一个 storage 所有者释放。

引用计数只在边界移动、提交 I/O 等维护路径增加，读写操作的地址访问和分配不克隆 Arc。此改动使日志访问多一层间接寻址；功能验证不能证明其性能等价，之前冻结版本的矩阵不覆盖本次改动。保持 REST / RC 编译期特化和内部单次 fetch_add 分配，不开展新优化。

`ScannedRecord` 保留类型化 key/value 访问，新增 `size()`，移除公开 `words` 字段。内部压缩通过 unsafe `raw_words()` 借用原始内容，要求整个借用期间没有任何类型化字段写入，包括原子写；它只使用本批次独占的扫描页。一般调用方不能在安全代码中取得重叠的原始字切片。此处有意收紧 API。

`HybridLog::get` 使用 wrapping pointer arithmetic。安全调用可以计算任意地址的指针，解引用仍要求页内边界及 epoch 保护，不能把“返回指针”理解为“验证该地址可读写”。

`shift_read_only_to` 在发布边界或排队动作前断言页几何、缓存标记和 tail 上界；无效请求不改变状态。恢复原始写页和边界重置改为 crate 内部的 `&mut self` 方法，公开 `recover` 同样要求独占借用新建 store，编译器排除仍存活的会话及扫描。写页还要求 `Arc::get_mut` 成功，排除尚未完成的 epoch 动作和 I/O 回调，不能仅由句柄独占推导页存储独占。

恢复开始前校验日志未使用且 storage 独占；任何恢复写页或边界重置都会标记该实例已使用，部分加载失败后必须重建实例。元数据失败但尚未写页允许重试。begin/start/end 的地址几何、8 字节对齐及顺序在读取索引前校验，非法元数据不能进入要求对齐的 Record 解码。新增检查仅位于边界移动和恢复路径，不增加正常记录分配的计数或锁。

## 相关 Spec 修复

恢复窗口下界不得早于 checkpoint 中的 begin 页；空窗口直接恢复边界，不能读取已经由 GC 删除的段。索引重放区间 start == end 时同样跳过读取，即使地址的页内偏移不为零；初始空库的 (0,64) 检查点不依赖日志文件已存在。默认 mutable 比例至少留下两个不可变页帧，满足开启下一页时的回收距离。刷盘失败保留未完成的持久化边界、记录失败并递减 pending 计数，检查点回调报告 IoError；后续必须跨越失败页的分配会明确失败，不支持失败设备上的透明重试。

独立扫描和压缩的扫描共用非空范围校验：先按现有契约夹紧范围，再验证实际起止地址的页几何。非法偏移返回 InvalidArgument；读取长度由当前页的合法起止偏移计算，避免设备偏移相减掩盖跨帧范围。Address::MAX 上界、空范围和规范页末保持兼容。扫描越界和初始空库恢复缺陷均已在 b929b83 及其修复前的 4944f67 复现，不是 b929b83 引入。

## 验证

`tests/safety.rs` 覆盖句柄移动、销毁后延迟动作、越界地址计算、异步写失败和无效刷盘边界；扫描模块单元测试覆盖原子值跨线程访问，均以 Miri 检查实际内存操作。扫描、恢复及原始写页 API 有 compile-fail 约束。恢复测试覆盖延迟动作和未完成写入期间拒绝覆盖、已用／部分加载实例拒绝恢复。GC 集成测试分别恢复空日志和保留少量记录的日志，并验证删除键、保留键和新写入。另有默认页比例的有界推进测试和所有权无循环测试。结果和原失败证据见 [审查修复记录](../07-审查修复与重新验收.md)。

## 2026-10-29 合入前修复

GC 与恢复共用页几何及 8 字节对齐校验。恢复从索引开始加载起出现错误就保留 Action::Recover，拒绝新会话和再次恢复；索引加载前的元数据失败仍可重试。

按 docs/09 唯一一次定向修复授权，`de1c56f` 将 tail、帧指针表、页几何及 begin/head/read_only 内联到 HybridLog。storage 继续拥有页面；句柄内联的帧表仅复制指针，不拥有页面。safe_head、safe_read_only 和 flushed_until 仍由异步动作在句柄移动或销毁后更新，故与页所有权、写回状态一同保留在 Arc；恢复继续要求 Arc::get_mut 独占成功。7 项 Miri 安全检查与完整基础功能验证通过，但首项复测吞吐/基线 0.93900 未达到 0.98，性能验收停止，不能将实现状态解释为合入通过。详见 docs/07。
