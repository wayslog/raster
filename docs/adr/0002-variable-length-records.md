# ADR 0002：变长内联记录与零成本默认操作

日期：2026-10-13。状态：已采纳并实现。性能验收状态见 [执行计划](../06-变长键值与收尾计划.md)，实现提交不等于整体验收通过。

## 决策

保留 ADR 0001 的 FASTER C++ 契约和 8 字节 RecordInfo。记录按键、值实际分配大小计算偏移，不引入额外记录头或定长/变长运行期分支；同一页内存储完整记录，尺寸超过页大小时立即拒绝分配。

Key 去掉 Copy 约束，Key/Value 提供 size；默认值为固定头尺寸。移除 Value blanket implementation，以便变长类型覆盖尺寸。KeyContext 统一四种操作的浅键、哈希、等值判断和 deep write。ValueSlot 提供新分配上的原地初始化；现有记录仍通过 &V 访问，并发安全属于值类型。

磁盘读取分三个阶段验证尺寸：键头、完整键及值头、完整值。每次不足时从原地址重读所需前缀。扫描、压缩、读缓存驱逐和恢复使用实际记录长度；设备返回的字节不必包含记录尾部对齐 padding；引擎在复制到缓存或日志前补齐已初始化的尾部空间。分级读取判断始终使用实际收到的长度，不能把补齐的空间当成读取结果。

## 计划的两处补充

1. Value::initialize_empty 是必需方法。墓碑和分配后源已被驱逐的无效记录需要合法且精确的尺寸头，清零不能保证 Rust 值有效或尺寸正确。该回调不改变正常定长读写快路径。
2. DeleteContext 只携带 K，因此 value_size 返回 Option<u32>：None 由 store 选择 V 固定头大小，Some 为明确的变长墓碑空间。

## 生命周期与并发

- Key/Value 不持有堆资源，不执行 Drop，并支持持久化后的字节搬移。用户类型的固定头必须足以安全计算 size。
- V::size 是分配尺寸，不能随逻辑长度缩短而改变。扩容通过新记录和索引 CAS 完成。
- 并发值在原地扩容失败时冻结旧值；generation lock 的 replaced 位防止复制期间旧值继续被修改。
- RMW 在分配前取所需尺寸，分配后重新检查源地址是否已被驱逐；失败分配也初始化尺寸头，然后置 invalid，扫描才能正确跳过。

## 默认路径与维护

Read/RMW/Delete 的附加选项使用常量参数特化。读缓存和非零日志预算才启用维护路径。维护任务装箱，避免把大型结构内嵌进热字段区域。压缩按页认领，写侧协作者和专用工作线程共同推进；截断必须等待所有认领页和 Pending 复制完成。

压缩的同步存活检查借用已拥有的扫描页，只有进入 Pending 才深拷贝记录，异步请求因此不依赖扫描页的生命周期。恢复先检查设备返回缓冲区的实际对齐，满足 8 字节对齐时直接重放，否则复制到对齐缓冲区；结构边界检查保持不变。磁盘单记录返回缓冲区采用单一 Vec<u8> 所有权表示，先初始化尾部 padding；如基址未对齐，在分配内预留至多 7 字节并移动记录，使读取指针满足 8 字节对齐。原始返回长度单独保留，释放时仍使用 Vec 的原始分配布局。

## 验证与边界

定长基线为 746c562，C++ 基线为 321d872e。V1 的指令数、周期和磁盘吞吐门槛，以及 V5/最终矩阵必须分别验收，不能用本地测试替代远端性能证据。测试覆盖变长键、哈希碰撞、值扩缩容、磁盘分级重读、缓存插入失败、压缩竞态、恢复前缀、扫描和索引增长。

保留 F2、异步 O_DIRECT 后端及真实高速磁盘验收为后续事项；Azure 不实现。pre_allocate 提示可以解析，但当前始终预分配页帧。
