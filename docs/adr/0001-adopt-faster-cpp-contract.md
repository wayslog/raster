# ADR 0001：采用 FASTER C++ 契约并重写引擎

日期：2026-10-12。状态：已接受。

## 背景

旧 RasterKV 引擎为每次操作提供了更强的保证：每操作 epoch 进出、会话准入与结果额度、记录级 MutationGate、回调 panic 隔离以及自定义 v1 格式。在 18 组驻留负载上，它的吞吐只有 FASTER C++ 的 7%–23%，每操作指令数是 C++ 的 6 倍以上。差距来自这些协议在每次操作上的固定成本，局部优化无法消除。

## 决策

- 全面采用 FASTER C++ 的契约：会话级 epoch 加 Refresh、Status 与 Pending/CompletePending、值类型自行负责并发、回调 panic 不捕获、CPR 检查点、48 位地址加 8 字节 RecordInfo 的内联记录布局、FASTER 风格的持久化组织。
- 删除旧引擎、旧测试、旧验收记录与实验工具，在 `src/core/` 按 C++ 模块结构重新实现。
- 性能目标为不低于 C++；实施计划见 [05-FASTER契约重写计划](../05-FASTER契约重写计划.md)。

## 后果

- 公开 API 与旧版本不兼容，旧 v1 数据文件不可读。
- 空闲会话必须定期 refresh；值类型需要自行保证原位更新的并发安全（`V: Sync`）。
- 重写完成前，crate 只提供已实现阶段的功能。
