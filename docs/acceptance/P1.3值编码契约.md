# P1.3 值编码契约

普通值由安全的 `ValueCodec` 编解码策略定义，`SerializedValue<C>` 持有实际 codec 实例，允许配置型策略。编码返回独立 `Vec<u8>`；失败不接触共享槽。解码返回拥有型值，临时对象遵循 Rust 的析构规则。专家 codec 仍负责规范编码、损坏输入拒绝及自身错误路径资源管理。

`PreparedValue` 拥有编码字节和经过检查的 `ValuePlan`，不包含页指针或访问许可。P2.2 接入后的普通值活跃表示是八字节长度前缀加编码字节槽，live 比 encoded 多八字节、对齐为 8；长度前缀不落盘，同步元数据仍位于槽外。原子值活跃大小和对齐由 `AtomicU64` 类型取得，编码固定八字节小端；它的磁盘字节始终表示逻辑 u64，不是原子对象镜像。

| 适配 | 格式身份（16 字节 ASCII） | 编码 |
| --- | --- | --- |
| ByteValueCodec | `raster:valbytes1` | 原始字节，空值、非 UTF-8 合法 |
| U64ValueCodec | `raster:valu64le1` | 恰好八字节小端 u64 |
| AtomicU64Value | `raster:atomic641` | 恰好八字节小端 u64，布局身份与普通整数不同 |

`ValuePlan::validate` 要求 live 和 encoded 都不超过 capacity，capacity 不超过 u32 最大值，对齐为非零二次幂，而且能构成合法分配 Layout。P1.2 完整记录的总长度上限仍另外约束头部、键及校验开销；值计划通过不保证完整记录能进入当前页。

`PreparedValue::fits` 校验候选槽的容量和声明对齐，尺寸越界必须追加或拒绝；它不证明实际地址对齐、页代次有效或已有独占权。P2.2 负责在真实槽上验证这些条件。零长普通值合法，页池仍须为其记录头和键分配空间。

初始化清理契约：`initialize`/`decode_initialize` 返回错误或展开 panic 前，专家实现负责销毁已初始化的子对象，将槽恢复为未初始化状态。调用者仅回收原始槽，不再调用 `drop_value`；成功后页所有者恰好一次销毁。解码先形成拥有型临时值，再在合法 InitPermit 下初始化槽。

P1.3 当时没有构造许可；P2.2 已开始用真实页范围和仲裁许可实现内建 ValueLayout，见 P2.2 交付记录。AtomicU64Value 的 prepare 接受逻辑 u64，实际稳定快照必须在 P2.2/P5 的受保护路径通过原子读取获得。普通值更新、原子更新和替换共同仲裁仍由后续页及引擎协议实现。

测试 `tests/p1_values.rs` 覆盖固定整数边界、小端样例、空值、变长值、非文本值、两类大小越槽、对齐和分配上限、损坏整数长度、codec 失败及临时拥有值析构。本阶段测试不证明真实页上的初始化失败清理；该验收仍属于 P2.2。
