# P0 轨迹与故障契约

版本1测试格式与存储文件格式无关。支持代码只在集成测试编译；目前没有真实引擎适配器。

## 轨迹输入

首行：`raster-trace 1 <十进制种子>`。之后每行：`session serial hex-key operation arguments`。会话/序号为u64；字节为十六进制，空字节为 `-`。空白分隔；未知版本、字段数、操作、类型、非法数值/布尔值拒绝并报告行号。

操作：
- `read <0或1>`：abort_if_tombstone。
- `upsert u <u64>` 或 `upsert b <hex>`。
- `rmw <0或1> u <u64>` 或 `rmw <0或1> b <hex>`：create_if_missing。
- `delete <0或1>`：force_tombstone。

整数 RMW 为 wrapping 加法；缺失时初值就是操作数；字节 RMW 追加。不同类型更新终结为模型 TypeMismatch，不修改旧值，不代表新增公开错误。单个键正常生成轨迹始终使用同一类型。

SplitMix64 固定初始种子、wrapping 常量；每步四次取样依次决定会话、键、操作、值。会话0—2、键0—7（0为空），每会话序号增量1—3。改变生成算法必须升级轨迹生成契约或保留旧生成器；种子只是复现辅助，完整文本输入为权威。固定样例为 tests/fixtures/p0.trace，独立预期写在测试内，不从模型生成。

## 模型边界

BTreeMap 表示全局键状态，独立会话记录 last_accepted；序号第一次允许0、严格递增且可跳号。拒绝返回原Step，执行计数和接受序号不变；已接受的 NotFound/类型错误均消费序号。模型输出与输入逐项比较。

模型保留逻辑墓碑。真实引擎默认删除可能直接移除索引，所以跨实现对照默认删除后的墓碑探测只能接受协议允许的结果；强制墓碑场景才要求 Aborted(Tombstone)。Deleted 不区分 TombstoneWritten/IndexRemoved。模型不模拟页、原子并发、版本切分或磁盘，不提供 durable progress。

## 故障与副作用

上游重复删除的返回还依赖索引项是否被消除：可能是 Success，也可能是 NotFound；模型选取逻辑 NotFound。P9适配器须归一化这一差异，不把具体物理删除路径的状态作为全局顺序模型断言。另在 faster.h 的可变区删除分支静态观察到索引消除未检查force_tombstone；该分支的墓碑可观察性需P3/P9定向核实，不能无条件复制为Rust契约。

事件稳定名称：request.before_accept、request.after_accept、user.compute、user.may_apply、result.notify、io.submit、io.complete、checkpoint.material_sync、checkpoint.commit_publish。FaultScript 按事件及从1开始的出现次数触发一次；其他事件不推进计数。P4/P5 增加子阶段事件时须同步此文档和测试，当前事件没有接入设备。

| 位置 | 预期 |
| --- | --- |
| 接受前拒绝 | 归还请求，不消费序号，不运行用户计算 |
| 接受后，尚未修改 | 可返回 NotApplied；正常计算可内部重试，不二次接受 |
| 明确修改后报错 | Applied，失败关闭，不重试 |
| 可能修改后 panic/报错 | Unknown，失败关闭，不重试 |
| 结果通知 panic | 结果已记录终结，不重复运行操作或通知；释放guard |
| panic=abort | 进程终止，后续阶段从已提交检查点恢复 |

普通 Append/Err 必须未修改共享值。计算方法不得含不可重复的外部副作用。Lifecycle 仅是接受/重试/终结预言机；测试不证明真实 panic 展开、回调线程和设备清理，这些由 P3.3/P4.4 验证。票据遗弃不取消业务；错误终结不推导检查点成功。进程崩溃测试不等同真实断电。

新增真实适配器时复用 Trace/Step，逐项比较归一化结果；失败必须打印种子、完整轨迹、第一处差异。不得用两个相同模型的结果作为引擎正确性证据。
