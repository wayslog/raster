# 环境与命令

开发工具链与MSRV固定为 Rust 1.98.1，edition 2024。rust-toolchain.toml 安装 minimal + rustfmt/clippy；Cargo rust-version 明确为1.98.1。初始工程提交为4f07dea，初始工具链1.92.0，仅作历史记录。

## 正式工程矩阵

CI使用 ubuntu-24.04 与 macos-14；记录实际host target、OS版本、runner镜像版本和文件系统，不能用交叉编译替代原生运行。每平台运行 default、仅config-toml、all 三组。macOS本地环境是 aarch64-apple-darwin，实际版本和文件系统见报告；CI实际架构以产物为准。

以下以默认组合为例，另两组给所有支持特性选择的Cargo命令加 `--no-default-features --features config-toml` 或 `--all-features`：

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked --examples
cargo doc --locked --no-deps
```

CI额外对rustdoc设置 `-D warnings`。cargo test运行单元、集成和doctest；examples 单独编译检查。全部特性不会证明 io_uring 运行支持；TOML 在 P8.1 接入严格解析，特性与默认值见 [配置与诊断](../15-配置与诊断.md)。

## 证据记录

每个job保存p0-平台-组合产物，包含 environment.txt 与 checks.txt；记录提交SHA、rustc -Vv、cargo版本、uname、OS、镜像、文件系统与测试输出。GitHub job最终状态和退出码决定通过；任一命令失败则job失败。

本地记录使用中性目录名和相对引用。编译器路径通过 --remap-path-prefix 归一化；归档日志额外移除Cargo进度和诊断中原始工作树/用户目录。不要把用户名、私有根路径或完整本机环境变量归档。CI产物按平台默认保留周期保存，长期报告保留固定提交链接、job链接与摘要。

## 依赖引入规则

P0没有外部依赖。后续逐项核查官方版本/维护状态、许可证、声明MSRV和实际target/features依赖闭包；更新Cargo.lock并在1.98.1原生矩阵执行。不照抄调研版本，不把单个crate的MSRV当作闭包保证；新增依赖原因和验证结果写入对应任务。

P2 的模型与内存检查、P4 的真实 I/O 故障、P5 的崩溃恢复以各阶段交付记录为准；P9 上游对照仍待执行。不能从常规 Cargo 命令推断全部专项验收通过。

## 公开流程验收命令

P8.2 起，每组原生 CI 在工程检查之后实际运行：

```sh
cargo run --locked --release --example memory
cargo run --locked --release --example memory_matrix
cargo run --locked --release --example interface
cargo run --locked --release --example disk_lifecycle
cargo run --locked --release --example automatic
python3 scripts/check_examples.py
```

另两组同样加相应特性参数。后一个脚本验证已有内容保护和显式目录保留；使用刚构建的 release 示例。完整行为、目录参数及等待契约见 [公开接口使用流程](../16-公开接口使用流程.md)，实际平台、数量和 CI 见 [P8.2 交付记录](P8.2公开流程交付记录.md)。
