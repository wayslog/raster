# P7.1 条件复制与单存储压缩交付记录

状态：**待验收。条件复制、公开单工作者压缩及 ScanDedup/Lookup 两种算法已接通；公开驱动的双平台检查尚待本次提交验证。**

## 已实现的条件复制协议

`engine/conditional_copy.rs` 接受所属实例的压缩动作、源逻辑地址及规范键字节。每次推进重查当前索引链，比较完整键及最新匹配地址。相同标签的不同键可以共用索引链；不能仅凭标签、索引头地址或扫描所得旧值判断源仍有效。

驻留源在记录独占许可内重新编码，并将许可保持到目标初始化及索引 CAS 判定结束。等待磁盘、版本许可或空间时只保存地址、键字节、拥有型磁盘页和完成路由，不保存源记录租约或 Schema 拥有型对象。冷源使用完整验证的页字节，返回后再次核对索引快照。

复制目标使用压缩动作当前版本，并连接当前主日志链头；缓存索引头先解析为主日志地址。最新墓碑按墓碑搬迁，不解码值。成功后仅发布新索引头，不改变逻辑 begin、不删除源记录、不提供额外持久化承诺。

源的原地更新不改变索引地址，因此仅靠 CAS 不足以防止覆盖更新。业务条带锁和源记录独占许可共同覆盖同步复制窗口；不同条带的同桶、同标签写入仍可造成合法 CAS 冲突。目标预留计数保持到发布判定和清理结束，物理扫描不能提前借出未发布目标。CAS 冲突清理目标后重新查证源；布局错误不能作为内部争用自动重试。

复制成功、源过时、编码失败或恐慌均使该请求终结；恐慌使引擎失败关闭。失败收尾先消费已接受 I/O，不再提交读取，再释放版本许可和邮箱。维护调度器随后才能释放全局动作。内部任务持有完成路由中心的 Arc，不持有 Engine Arc，避免未来任务注册形成实例引用环。

## 已执行的定向测试

`src/engine/conditional_copy_tests.rs` 的九项测试覆盖：

- 候选捕获后原地 RMW：地址不变但复制值包含最新增量，一次终结且 begin 不变。
- 追加和删除使旧源过时；迁移最新墓碑之后仍返回 NotFound。
- 固定同标签键 8969/9239 在单桶中共链，复制链内源保留另一个键。
- 冷页读取挂起期间追加能够完成，旧源不会重新发布。
- 外来引擎拒绝操作，所属引擎仍可继续完成。
- 目标初始化暂停时源更新被阻止；另一条带写入造成 CAS 冲突，未发布目标不出现在物理扫描中，重试保留两键当前值。
- 目标初始化返回 Codec 或 Busy 时都终结，不重复执行编码，不改变当前索引和源值。
- 目标初始化恐慌使引擎失败关闭，没有发布目标。
- 冷源成功搬迁、在途读取排空、后续 Full 检查点及旧版本许可等待。

`src/log/scan.rs` 的发布窗口测试另行验证：初始化目标已经进入记录表时，扫描、尾部填充及只读边界推进仍受预留计数约束；冲突清理后背压解除，目标不会泄漏为可见物理记录。

这些测试直接使用现有索引、混合日志、Schema 和完成路由；冷页场景使用原生文件设备，不使用参考模型代替引擎。

## 公开压缩驱动与输出

`Maintenance::compact` 接受半开范围 `[当前 begin, until)`，通过 `Maintenance::poll` 或任意已有 `Session::poll` 推进；`wait_maintenance` 等待同一维护票据。全局压缩动作排斥检查点、扩容和其他压缩，已有会话仍可进行读写。范围捕获后新增记录不纳入扫描；结束地址落在冷记录中间时先验证失败，不进行任何迁移。

- **Lookup**：物理扫描每取得一个候选，即使用条件复制查证其是否仍是该完整键的最新源。
- **ScanDedup**：扫描中按规范键字节保存范围内最后地址，再逐键使用同一个条件复制内核；仍会检查范围外的新写，不能把局部去重结果当作当前索引事实。
- 去重候选默认最多 1,000,000 个不同键和 64 MiB 键字节，由 `maintenance.max_compaction_keys` / `max_compaction_key_bytes` 调整。条目和树节点受键数量上限约束。Lookup 不累积候选集合。
- 内部扫描最多保存一个已完成页或一条在途分段读取；每个步骤最多产出一条记录或提交一段 I/O。在途读取保护帧覆盖的物理段，完成后拥有页不继续占用段租约。
- 成功报告 `until/copied/gc/checkpoint`；当前普通压缩的后两项为 None。`copied` 包含已迁移的最新墓碑，压缩不消费会话序号，也不递增检查点版本。
- 失败使用 `Error::CompactionFailed { until, copied, cause }` 保留已经发布的迁移数。错误中的 `until` 是请求边界，不能理解为已完成扫描边界。正常编码、容量、范围或读取错误先停止新工作并排空，再终结本次动作；保留已有迁移和原始历史，允许发起新维护。恐慌或收尾协议失败则失败关闭；设备关闭后才释放异常任务的在途资源。

## 公开路径交付测试

`src/engine/compaction_tests.rs`、`src/engine/scan_tests.rs`、`src/engine/cache_tests.rs` 与 `tests/p7_compaction.rs` 增加以下真实路径证据：

1. 两种算法各搬迁 400 个跨内存/磁盘键，包含过时记录和最新墓碑；物理输出逐键比对，begin 不变、序号不变；Full 检查点后重启恢复并续用原会话。
2. 冷结束边界切入记录时零迁移失败，读取仍正常；去重键数预算不足时零迁移终结，空范围和之后的 Lookup 均可执行。
3. NullDevice 日志容量耗尽时，失败报告的已迁移数与实际新增物理记录数相等，全部源键仍可读取。
4. 暂停设备完成，连续二十次维护轮询仍只有一条扫描读取；解除暂停后短读跨段继续，用户 Pending 读取独立终结，整个压缩可仅由会话轮询推进。
5. 单次读取失败不会自动重试；维护报告零迁移和真实 I/O 原因，新动作可重新执行同一范围。
6. 缓存命中、原范围双页扫描、Pending 读取与压缩并存，追加、删除和原地 RMW 之后仍读取最新结果，扫描固定范围不混入新目标。
7. 公开路径中专家解码恐慌只执行一次，维护报告保持同一结果；关闭后弱引用证明实例没有被内部任务循环持有。
8. 仅用公开接口对空键、非 UTF-8 变长键值和墓碑先执行 ScanDedup，再执行 Lookup；逐条核对两次新增记录，检查点重启后逐键读取和会话切分一致。

## 与后续任务的边界

本步支持 `workers=1`、`shift_begin=false`、`checkpoint=false`。零工作者是非法配置；多工作者或串接选项仍明确拒绝，按 P7.3 接入。P7.2 负责公开逻辑截断、索引 GC、段删除及恢复集保留约束；普通压缩不会隐式进行这些操作。
