# P5.2 检查点交付记录

状态：**进行中**。当前已实现单材料文件写入与文件同步组件，尚未接入完整检查点状态机，不宣称检查点可用。

## 单材料写入任务

MaterialWrite 绑定存储身份、检查点 token、固定材料名和完成路由。构造时验证文件同步能力、基本后端的传输对齐以及材料命名；不支持同步的设备在接受任何 I/O 前被拒绝。父目录由上层检查点任务创建。

任务按 Open(create_new) → 分块 Write → SyncFile(metadata=true) → Close 推进，最多一个在途 I/O。短写按实际完成字节推进偏移，零写返回 WriteZero。只有全部字节完成、文件同步和关闭均成功，才返回包含字节数与 CRC32C 的 WrittenMaterial。空文件也必须同步和关闭；manifest 是否允许引用空材料由格式层另行校验。

create_new 避免覆盖旧材料。写入输入为调用者拥有的 Vec，单次设备缓冲受 chunk 和剩余长度约束；后续检查点驱动负责分批形成材料并控制总输入内存，不能据此声称整个检查点已经实现流式快照。

## 拒绝、错误与资源归还

Busy 拒绝保持阶段不变，可以稍后重试；其他拒绝和完成错误转入失败清理，不自动重做写入。已有文件句柄时先尝试关闭，保留首个错误。关闭本身失败时返回错误并通过 has_resources 表明仍有设备所有的句柄，不能把它当作清理成功；上层须保留任务或由失败关闭流程接管资源。

完成项必须匹配存储身份、IoId 和路由；错误身份原样归还完成及缓冲，不消费当前在途状态。匹配完成只消费一次，重复完成被拒绝。写完成还检查返回缓冲及字节数。Drop 不执行阻塞 I/O；调用者不能因为丢弃任务就推断设备已经停止访问缓冲。

该组件只证明文件级同步，尚未同步新目录及其父目录项，也没有 manifest 或 commit 发布。

## 当前测试

- 固定 `123456789` 输入通过两字节短写完成，校验值独立固定为 CRC32C `e3069283`；核对写入、同步、关闭顺序。
- 打开、写入、同步、关闭各阶段故障均返回错误，不自动重试；写入/同步错误后尝试关闭。
- 零写、Busy 拒绝、错存储、错路由、重复完成、原缓冲归还、空文件和不支持同步能力。
- Linux/macOS 原生线程池分块写入后重读全部字节；重复新建返回 AlreadyExists，旧材料不被覆盖。

脚本设备仅验证流程和故障语义，不提供持久化证据；原生后端另验证实际文件 I/O。新增六项测试、本地格式、Clippy、全特性回归和 rustdoc 已通过。没有新增依赖或 unsafe。
