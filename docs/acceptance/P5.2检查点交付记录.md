# P5.2 检查点交付记录

状态：**进行中**。当前已实现目录排他预留、材料文件同步与提交发布组件，尚未接入引擎快照状态机，不宣称检查点可用。

## 单材料写入任务

MaterialWrite 绑定存储身份、检查点 token、固定材料名和完成路由。构造时验证文件同步能力、基本后端的传输对齐以及材料命名；不支持同步的设备在接受任何 I/O 前被拒绝。父目录由上层检查点任务创建。

任务按 Open(create_new) → 分块 Write → SyncFile(metadata=true) → Close 推进，最多一个在途 I/O。短写按实际完成字节推进偏移，零写返回 WriteZero。只有全部字节完成、文件同步和关闭均成功，才返回包含字节数与 CRC32C 的 WrittenMaterial。空文件也必须同步和关闭；manifest 是否允许引用空材料由格式层另行校验。

create_new 避免覆盖旧材料。写入输入为调用者拥有的 Vec，单次设备缓冲受 chunk 和剩余长度约束；后续检查点驱动负责分批形成材料并控制总输入内存，不能据此声称整个检查点已经实现流式快照。

## 拒绝、错误与资源归还

Busy 拒绝保持阶段不变，可以稍后重试；其他拒绝和完成错误转入失败清理，不自动重做写入。已有文件句柄时先尝试关闭，保留首个错误。关闭本身失败时返回错误并通过 has_resources 表明仍有设备所有的句柄，不能把它当作清理成功；上层须保留任务或由失败关闭流程接管资源。

完成项必须匹配存储身份、IoId 和路由；错误身份原样归还完成及缓冲，不消费当前在途状态。匹配完成只消费一次，重复完成被拒绝。写完成还检查返回缓冲及字节数。Drop 不执行阻塞 I/O；调用者不能因为丢弃任务就推断设备已经停止访问缓冲。

该组件只证明文件级同步，尚未同步新目录及其父目录项，也没有 manifest 或 commit 发布。

## 目录排他预留与同步层级

DirectoryPrepare 创建 checkpoints 命名空间后同步设备根目录，再创建 token 目录，以 create_new 写入并同步 owner 预留文件，最后同步 token 目录和 checkpoints 父目录。根目录同步使用设备约定的空相对路径。只有全部完成后才产生不可克隆的 PreparedDirectory 凭据。

owner 文件保留 store/token 身份，已有 token 不能重新预留；失败不会删除 owner 或复用该 token。这防止重复任务覆盖已有提交，也避免把残留目录当成可以重新开始的空目录。owner 仅是排他预留，不是成功提交证据。

## 清单与提交发布

材料任务可以返回绑定存储身份、token、规范文件名及长度/校验值的 SyncedFile 凭据。CommitPublish 接受 PreparedDirectory 和全部材料凭据，先匹配 manifest 的身份、数量、文件名和摘要，再执行：

1. 写入并同步、关闭 manifest。
2. 按 manifest 的精确字节长度与 CRC32C 写入并同步、关闭 commit.pending。
3. 重命名 commit.pending 为 commit。
4. 同步 token 目录，成功后才产生 PublishedCommit。

缺失、重复、错存储、错 token、错名称或摘要不匹配的凭据在写清单前拒绝。Busy 拒绝保留待执行操作，允许稍后重试。重命名一旦被设备接受就保守标记 may_be_visible；重命名或最终目录同步失败不会成功，也不能擅自删除可能已可恢复的目录。错误身份、路由和重复完成不推进状态。
