# P2.1 epoch 与延迟回收协议

状态：待验收。本模块只管理访问安全，不代表检查点或持久化进度。

参与者身份包含管理器唯一编号、槽号和槽代次。管理器编号、槽代次与 epoch 都不回绕；耗尽时拒绝操作，代次耗尽的槽永久不复用。注销后旧身份无效，跨管理器身份拒绝。活动 guard 尚未退出时注销返回 Busy。

每次 enter 增加槽的活动数，首次进入记下当前 epoch；嵌套进入不抬高最老 epoch。guard 线程绑定且借用管理器，Drop 减少活动数。遗忘 guard 保留活动数并阻碍回收，不能通过注销强制清除。

调用者须先从可见结构摘除对象，再调用 defer；defer 在控制锁内捕获当前 epoch，拒绝让调用者传入过旧版本。collect 只交付早于所有活动参与者 epoch 的动作；没有活动参与者时可交付全部动作。每项队列条目只交付一次。实际销毁在控制锁外执行，页和索引模块仍须检查对象代次、I/O 引用及检查点保留约束。重复提交同一动作不是本模块的去重职责，资源所有者不得重复退役同一所有权。

整个状态机使用 `sync` 模块提供的同一把 Mutex，所有状态转换在线性化点串行完成。不在控制锁下调用用户代码。锁中毒时拒绝管理操作，guard 退出也不尝试恢复中毒状态，保守阻碍回收。该实现优先保证首轮安全性；P3/P9 基准再评估每次进入控制锁的成本。

模型测试调用真实 EpochManager 接口，穷举两个读者 enter/exit 与回收者 defer/advance/collect 的 210 种顺序保持交错，逐步验证退役时仍在场的读者退出前不交付动作，最后恰好交付一次。由于全部转换持同一锁，该模型覆盖这些转换的线性化顺序，不声称覆盖未来无锁原子协议。另有真实线程屏障测试、嵌套许可、旧槽/跨管理器身份、遗忘 guard、代次耗尽及 epoch 溢出测试。

本阶段没有回收真实页或索引，资源销毁与访问许可由 P2.2/P2.3 接入后继续验证。未新增依赖与 unsafe。保留 epoch 的临时 dead_code 抑制，直至调用者接入。

本地 Rust 1.98.1 的格式、Clippy、全特性测试及 rustdoc 通过，共 48 个运行测试和 5 个文档测试。原生六组合 CI 待核验。
