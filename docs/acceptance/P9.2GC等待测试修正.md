## 原始失败与定位

报告提交 52c0657661edc319e5e6bc4af2ab7518d88733f6 的 [Rust CI 34619283567](https://github.com/wayslog/raster/actions/runs/34619283567) 六组中五组成功，ubuntu-24.04 / all 失败。唯一失败为 `公开截断使旧扫描失效且挂起读取保护段可延后再回收`，在“有界 GC 应终结”断言处退出；344 个其他单元测试通过。该运行未重跑，原始失败记录保留。

原测试以十万次无让出线程的轮询作为完成界限。异步设备完成尚未交付时，这个次数可以很快耗尽，不能代表经过了允许的等待时间。原样本地单独执行通过，因此又构造确定的等待条件验证这个假设。

第一轮诊断使用真实 ThreadPool 文件设备，只包装完成轮询：明确冻结日志并启动真实后台刷盘，断言刷盘任务存在，然后延迟 100,001 次完成交付。GC 的 PrepareIo 阶段必须排空该刷盘；业务冷读则继续保持 Pending，不能通过推进会话提前释放被测段租约。

在同一夹具下临时恢复旧十万次循环，0.30 秒后复现同一断言失败、退出码 101；恢复截止时间循环后，0.23 秒通过。最初只延迟任意完成的夹具不能保证 GC 实际依赖那批 I/O，曾在延迟计数归零断言失败；已用明确的在途刷盘补齐，最终红绿证据使用补齐后的同一夹具。
