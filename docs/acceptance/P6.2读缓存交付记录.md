# P6.2 读缓存交付记录

状态：**进行中，等待最终双平台交付检查**。缓存核心已接入真实读写、检查点、扩容和恢复；Config.cache.enabled 可在创建和恢复时启用。新增原生和变长值测试通过。

## 缓存记录与地址

缓存只保存经过校验的冷日志 RREC 字节，保留源地址、版本、完整哈希及原主日志链头。墓碑和 invalid 记录不缓存；缓存源前驱须严格递减，源地址不得高于主链头。缓存数据没有 Schema 对象或自定义销毁回调，读取时由引擎解码为短期值。

CacheAddress 单调分配且不复用，避免旧地址失效请求误伤新项；地址空间耗尽时跳过插入。缓存绑定索引运行期身份，拒绝另一索引。索引头改为 CacheAddress 后，resolve 在同一个缓存临界区读取最新索引快照、解析主日志头并取得缓存租约；只有完整编码键相等才命中，同 tag 不同键仍沿主日志链查找。

## 条件安装与规范化

安装前复查 EntrySnapshot，索引已被写入/删除改变则跳过插入。通过索引 CAS 安装缓存头，失败不保留候选项。替换旧缓存头时回收其目录项，但已借出的 Arc 仍然有效。

淘汰按缓存地址顺序选择最早项。如果索引仍指向该项，先条件还原其原主日志头，再移除目录项；如果业务写入已更换链头，不覆盖新头。with_normalized_index 持有同一缓存锁，清理缓存头后执行索引快照或迁移，保证操作期间不会有新缓存头插入。缓存地址不进入冻结的磁盘 v1。

引擎中的缓存安装、可能发生的淘汰以及索引规范化受业务写入仲裁保护。仅索引 CAS 不能保护已经执行用户回调但尚未发布的写入；缓存修改不能导致这些请求在值已消费后仅因缓存修订号变化失败。扩容必须在缓存锁下先规范化再迁移，不能复制缓存地址后只修复其中一个新桶。

## 容量与租约

预算计入拥有型记录 Vec 的容量和固定记录结构大小；它不是总进程 RSS 上限，不包含分配器与 BTreeMap 节点自身的开销。目录项数也受最小记录计费约束。记录在最后一个 Arc 释放、字节缓冲析构后才归还计费；目录淘汰不提前扣除读者仍持有的内存。

超大记录、禁用缓存、容量被在用记录占据或过期快照均跳过插入，不扩展容量。淘汰过程中若改变了预期索引快照，本次插入让出，由后续读取再尝试。此处不缓存可原地修改的内存记录，避免索引头不变时读到旧值。

## 组件验证

测试覆盖完整键命中与同 tag 不串值、迟到安装拒绝、外部索引身份拒绝、规范化后持久映像只含主日志地址、租约跨淘汰仍可读且继续计费，以及旧地址不影响新缓存项。

## 引擎接入与并发边界

仅成功解码冷磁盘记录后尝试缓存安装。复制编码前先检查缓存的单条记录预算，避免为超大记录另行分配缓存副本；容量不足、临时仲裁竞争和可选缓存分配失败均跳过安装，不使正常读取失败。安装前若已观察到维护动作就跳过；与动作接受之间的竞争仍由规范化时的缓存锁和写入仲裁保证安全。

读取开始时，在缓存临界区获取索引快照、主日志头和可选拥有型缓存租约。命中后解码为短期值并在原会话推进线程执行回调，不发起磁盘 I/O。缓存源低于当前 begin 时拒绝访问。RMW/Delete 仍查找真实日志并在 I/O 完成后复查快照；Upsert/RMW/Delete 构造前驱时只使用已解析的主日志地址。

业务写入替换缓存索引头后，旧项立即无法再命中，字节在后续 FIFO 淘汰或规范化时释放；不主动复活旧项。已开始的磁盘读取可在线性化于更新前的位置返回旧值，但该结果的过期快照无法再次安装，后续读取看见新值或墓碑。

安装及淘汰非阻塞取得全部业务写入仲裁锁，遇到回调立即让出。索引检查点同样在写入仲裁及缓存锁内规范化再导出，忙时保持任务并等待下一轮；扩容在已有迁移仲裁内规范化后才搬迁桶。缓存头不会进入 RIND 或新日志记录前驱。恢复构造新的空缓存，不加载运行期 CacheAddress。

## 引擎验证

- 冷页首次挂起读取后，后续读取同步命中；写入及删除后不再返回旧缓存值。
- 在磁盘读取尚未恢复推进时先完成更新或删除，迟到结果不能污染未来读取。
- 小容量 FIFO 淘汰、缓存头扩容规范化、Full 检查点及恢复连贯验证，恢复后首次仍为 Pending，第二次重新命中。
- 写回调暂停并持有缓存索引快照时，另一读取尝试安装/淘汰会让出；写入随后成功，旧项之后淘汰也不会覆盖新值。
- 一字节缓存预算不导致读取失败，也不分配缓存记录。
- 公开 API 变长字节值测试验证第二次读取同步命中、RMW 扩展值、再次检查点与恢复后的完整字节。
