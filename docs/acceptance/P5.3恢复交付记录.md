# P5.3 恢复交付记录

## 恢复文件读取

MaterialRead 绑定存储身份、token、文件名和路由。声明长度须符合调用者的资源上限，检查长度转换与溢出后才分配。以 create_new=false 打开既有文件，不创建缺失材料；沿固定偏移分块读，短读按实际返回量推进，提前 EOF 拒绝。

读取声明长度后再读一个字节，只有返回 EOF 才认为长度精确。尾随字节拒绝，包括声明零长度但文件非空。完成项必须带回正确长度的拥有型缓冲，存储、IoId 和路由均需匹配；错误完成原样归还。所有字节及 EOF 验证完毕后仍须关闭句柄，关闭成功才返回结果。

Busy 提交拒绝可稍后重试；其他失败保留首个错误并尝试关闭，关闭失败仍保留资源状态，由驱动者或设备 shutdown 接管。结果只返回一次，Drop 不发起隐藏 I/O。读取成功只证明精确文件字节，不能代替格式或恢复集校验。

## 提交驱动的清单读取

ManifestRead 固定先读取 56 字节 commit，验证 CRC、版本、store/token 及清单长度范围；之后才按声明长度读取 manifest。Commit 解码将清单限制在既有 8 MiB 上限内，伪造的超大长度不会触发清单分配或打开。清单随后通过 Commit::verify 检查精确长度、CRC、身份及格式语义。

只接受已发布的 commit，不将 owner、manifest 或 commit.pending 当作提交证据。解析阶段也检查存储身份；相同路由不能被另一存储复用。成功输出 Manifest 仍不表示其所有材料已验证，后续必须逐项检查并验证 index/log 配对。

## 索引映像安装

MemIndex::restore 接受已解码的 IndexSnapshot，先校验条目和桶数量。持久桶数量必须与恢复配置一致，不能用磁盘中未受配置约束的桶数量驱动巨大分配。构建新的桶与溢出块，保留表代次，重新分配运行期 owner 并将 CAS 修订号初始化为零；全部成功后才替换原索引。

新增两项测试覆盖 30 条目/五个溢出块、零地址、表代次、规范重新编码、旧 owner 快照拒绝、新快照 CAS 成功及重复 CAS 冲突；错误桶数量和无效地址不改变原索引，空映像恢复后仍使旧快照失效。该入口只验证索引结构，日志地址对应的记录、范围和版本仍由完整恢复流程核对。

## 恢复集合与逐材料校验

RecoveryPlan 替换原有未实现占位，接收经提交读取器验证的两份清单、请求恢复集、Schema 和配置。构造时校验 store/token、index/log 类型及 base_index 配对、版本与重放范围、键编码/哈希/值布局兼容性。用户语义校验恐慌转换为错误，不发布实例。

按（token、材料编号）建立所需材料集合，同一 Full 清单用于两端时去重。当前 RIND 每份清单要求一份完整索引材料，长度受配置桶数与每桶 u16 tag 空间约束；日志材料必须对应配置中的单页范围及 RPAG 字节数。在读取材料内容前拒绝不匹配的页布局或长度声明。

verify_material 先核对清单长度/CRC，再解析索引或整个日志页及全部记录。索引桶数量必须符合配置，链头必须位于其声明日志范围；日志允许保留新版本记录，后续重放负责过滤。仅成功材料进入已验证集合，重复或集合外材料拒绝，失败不改变 remaining。remaining 为零仅表示该层材料校验完成，不代表键/值解码、前驱链验证、重放或恢复实例已经完成。

## 冷日志边界与恢复后追加

PagePool::new_at 支持从已验证的逻辑页号建立空内存页池。尚未分配新页时 tail/pad_tail 返回恢复尾部，旧逻辑页不占内存预算；后续分配、释放和代次复用保持单调页号，不回填旧地址。

HybridLog::from_checkpoint 校验 begin/end 与页对齐尾部，将 head、safe_head、read_only、safe_read_only、flushed_until 初始化到 end，旧记录仅通过磁盘路径访问。调用前必须完成旧日志材料的安装；此构造器不读取文件，也不证明数据已复制或可恢复。

## 接入重放时必须保持的约束

混合版本页不能直接作为恢复后可见的普通日志：同 tag 的旧版本链可能经过应被过滤的新版本记录。重放需剔除超出恢复版本的记录，并修复跨越这些记录的前驱链，否则新键可能经碰撞链重新可见。

重建索引需要从解码的拥有型键计算完整稳定哈希。KeyCodec 的 OwnedKey 现已要求 Borrow<Key>，恢复通过规范解码后借用逻辑键计算哈希，不能仅凭持久化 bucket/tag 猜测完整键哈希。


## 拥有型键与规范恢复编码

开发期 KeyCodec 契约收紧为 OwnedKey: Borrow<Key>，允许恢复和扫描从拥有型结果借用原逻辑键；Vec<u8>/[u8] 与 u64/u64 直接满足，自定义拥有型封装可实现 Borrow。该要求不改变内建键的磁盘字节或哈希算法，外部自定义 KeyCodec 实现需满足新增借用约束。

decode_canonical 先解码拥有键，再验证 encoded_len、重新编码的精确字节和 equals_encoded，随后计算完整 KeyHash。用户解码、借用、编码或哈希恐慌转换为恢复错误。RecoveryPlan 的日志材料验证已调用该入口；每次也重新核对传入 Schema 的身份，失败不推进材料验证计数。

新增三项测试覆盖空/变长/非 UTF-8 字节键、整数边界、同 tag 不同完整哈希、非同型拥有键借用、宽松解码产生的非规范别名、哈希恐慌，以及记录/页帧/材料校验均正确但整数键长度非法的原生检查点材料。完整恢复与版本过滤仍待实现。
