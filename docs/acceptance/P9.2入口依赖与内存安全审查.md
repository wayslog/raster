## 入口与未使用代码

强制检查命令为 `cargo rustc --locked --lib --all-features -- --force-warn dead_code`。原来的 28 组告警已逐项核对，不能把整个模块的抑制当作实现完整：

| 分类 | 处理与依据 |
| --- | --- |
| 未调用的占位入口 | 删除 `Engine::not_ready`、`MaintenanceJob::poll`、`ReclamationPlan::deletable_segments` 及仅供这些旧骨架使用的类型；真实维护由 `engine/compaction`、`gc`、`checkpoint_release` 等实现 |
| 未构造的状态 | 删除 `ResumeReason`、`CompletionRouter`、`TaskStep::AwaitingIo`、`PageState`；真实 `LookupStep::AwaitingIo` 和设备在途状态保留 |
| 仅供协议测试调用 | 保留页/记录初始化、租约、代次、稳定编码、检查点保留目录和故障查询辅助方法，限定为 `cfg(test)`；运行入口使用实际的分配、版本许可、回收和完成协议 |
| 无消费者的字段/包装 | 删除扫描的 started、编码页的重复页号及维护扫描的 has_inflight；页号测试改从实际编码的 PageFrame 解码后检查 |
| 根目录重复存储 | SegmentedStorage 不再复制根路径；实际路径能力仍由 Device 持有，测试从已存在的 Config 取得合成目录 |
| Epoch 动作 | 保留真实 ReleaseIndex；删除未接入的 RecyclePage/AdvanceReadOnly，原 epoch 交错测试改用真实动作，不减少生命周期断言 |
| 模块级告警抑制 | 移除 lib.rs 中八处 `allow(dead_code)`；普通 Clippy 对全部目标保持 `-D warnings` |

强制检查只剩一项已解释告警：`PublishResult::Conflict(EntrySnapshot)` 的快照负载由索引协议测试读取；生产引擎冲突后重新准备索引入口。该字段保留局部 `expect(dead_code)` 和当前用途说明，不以未来功能掩盖模块。锁 guard 的 RAII 所有权继续保留。

第一期 Linux/macOS 路径没有 `todo!`、`unimplemented!` 或 `Error::unimplemented` 占位返回。后置的 `UringDeviceFactory`、`WindowsDeviceFactory` 和非 Linux/macOS 的基础工厂分支仍明确返回未实现；`io-uring` 全特性编译不代表后端可用。`Error::NotImplemented` 作为这些公开拒绝的错误类型保留。

## unsafe 边界

| 实现位置 | 核对的不变量与验证路径 |
| --- | --- |
| `schema/value.rs`、`schema/mod.rs` | 专家 ValueLayout 的 Safety 契约规定尺寸/对齐、许可寿命、并发访问及失败清理；SharedValue 逐项转交同一 schema，不延长许可寿命；compile_fail 验证视图不可逃逸 |
| `schema/builtin/layout.rs` | 普通槽按长度前缀检查范围，独占许可下先编码再替换；AtomicU64 完成尺寸/对齐检查且运行期始终原子访问；稳定编码读取逻辑值，不保存进程镜像 |
| `log/page.rs` | Layout 非零且对齐；不可克隆 PageRange 持 Arc 并拥有不重叠范围；旧范围全部退出才释放/清零复用，代次不回绕 |
| `log/value.rs` | 对齐与长度检查后构造内部指针；MutationGate 仲裁读写/稳定编码；失败初始化由布局清理，成功值仅销毁一次；销毁失败保守保留分配，不释放可能仍被引用的内存 |
| `cache/arena.rs` | 控制锁发放独占范围，初始化后只读，最后租约归还前不复用；租约持 Arc；自由区间元数据预留后归还，不在 Drop 分配 |
| `examples/resources/allocator.rs` | 仅验收可执行程序安装计数分配器，委托 System 并按成功分配/重分配/释放计数；独立测试检查内容保留、零填充和全部释放 |

本次未新增生产 unsafe 块或更改这些访问算法。Clippy 继续执行 `unsafe_op_in_unsafe_fn = deny` 和 `undocumented_unsafe_blocks = deny`。静态说明不代替执行：`tools/acceptance/run_miri.py` 运行 32 项默认泄漏检查，另将故意 forget 租约的一项隔离为忽略泄漏；原生 I/O、恢复和并发历史由现有双平台矩阵验证，不声称 Miri 覆盖全部系统调用。
