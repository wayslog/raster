# P5.1 阶段协调交付记录

状态：**进行中**。当前交付动作仲裁、参与者屏障、会话上下文切分与正常阶段退出；自动阶段观察和维护推进尚未接通，不能据此宣称检查点可用。

## 动作和注册的原子边界

动作状态、会话注册表及单调维护 ID 共用一把锁。start_action 原子固定当时全部活跃会话，包括没有提交业务的空闲会话；动作期间新注册返回 Busy。注册与动作开始竞争时，注册要么被纳入集合，要么被明确拒绝，不存在被遗漏但成功注册的中间态。相同锁下 snapshot 返回动作 ID、种类、阶段和版本，供后续会话推进绑定确认。

同一时刻只允许一个顶层动作。关闭在有活跃会话或尚未终结动作时返回 Busy；恢复动作要求没有活跃会话。动作 ID 单调分配且不复用，确认、推进、终结和失败均校验 ID，旧动作迟到消息不能改变新动作。

## 阶段与确认

| 动作 | 阶段序列 |
| --- | --- |
| 完整检查点 | PrepareIndex → IndexSnapshot → Prepare → InProgress → WaitPending → WaitFlush → Publish |
| 仅索引检查点 | PrepareIndex → IndexSnapshot → WaitFlush → Publish |
| 仅日志检查点 | Prepare → InProgress → WaitPending → WaitFlush → Publish |
| 恢复 | WaitFlush → Publish |
| GC | GcIo → GcIndex → Publish |
| 索引增长 | GrowPrepare → GrowCopy → Publish |

PrepareIndex、Prepare、InProgress、WaitPending、GrowPrepare 是参与者屏障。未全部确认时 advance 返回 Busy。其余阶段必须由实际驱动者完成对应 I/O、索引或发布工作再调用 advance/finish_action；协调器本身不执行这些工作，也不证明数据已持久化。

完整/日志检查点进入 InProgress 时递增检查点版本；仅索引检查点不递增日志版本。版本耗尽返回 CapacityExceeded 并保持原状态。

InProgress 登记各会话的 last_accepted 切分及 old_pending；WaitPending 仅允许旧请求为零的确认。确认序号不能超过注册表的已接受序号，重复确认不能改变已固定序号或增加旧请求数。API 使用维护 ID 和预期阶段拒绝过期确认。

## 失败边界

动作参与会话未经阶段处理直接 leave，会保留 SessionAbandoned 并进入 Failed；fail_action 保留第一个失败原因。失败状态禁止新注册、新业务接受、新动作及成功发布，剩余会话仍可退出，退出后设备关闭路径可以继续。正常 Session::close 已接通 leave_drained，在两个上下文都排空后保留切分并退出；阶段屏障可以跳过已确认排空的退出参与者，参与集合和切分不会被删除。异常 Drop 仍调用保守 leave；协调动作的失败向共享引擎主动传播待后续接入。

## 当前/前一上下文及正常退出

会话注册在协调器锁下返回当前版本，SessionRuntime 初始化使用该返回值，避免新会话总从版本零开始，或另取快照时与动作开始竞争。

switch_version 只允许相同版本幂等观察或连续递增；切换前检查任务所属会话、版本及序号，将完整旧上下文移动到 previous，新上下文继承最新已接受序号但初始无任务。旧任务的 ID/版本/序号均保持不变。更老上下文仍有任务时拒绝再次切换；空旧上下文可以替换。cut 按明确版本返回固定序号及该上下文剩余任务数，不使用新上下文最大序号冒充旧切分。

正常 close 排空两个上下文后提交它们的版本与切分。协调器在当前阶段下选择对应旧版本，校验已固定序号未被改变，再保留退出参与者的切分。动作开始时还保存已退出会话的进度；后续会话接受的新序号只进入下一次动作的切分。

新增真实 Session/Pending 测试验证跨版本读取身份与序号保留、旧/新请求独立完成、第三版本提前切换被拒绝、动作前与动作中关闭的会话进度，以及切分后新序号不进入旧检查点。测试通过内部协调器和切分入口驱动阶段，不声称公开维护接口已经可用。新测试、本地全特性回归、Clippy 与 rustdoc 已通过；新版本写入许可与自动阶段推进仍待实现。

## 记录自身版本与原地更新限制

PageValue 在发布前固定操作版本，RecordLease 可查询该版本。Upsert、RMW 和 Delete 在发布新记录或墓碑前写入请求的固定版本。普通刷盘按上界校验而不改写记录版本；后台刷盘使用协调器当前版本作为范围。记录版本一旦发布不可变，因此版本比较不依赖另一个可变化的标签。

Upsert/RMW 只对同版本记录调用原地更新回调；不同版本返回追加路径。测试保留旧租约，验证新版本替换和 RMW 后旧记录值不变，而新记录再接受同版本操作时仍能原地更新。页编码测试包含版本 0、1、2 的记录和墓碑，验证不同页上界编码均保留各记录版本，并拒绝不足上界。

这一步没有开启公开维护接口或自动切分。仍需接入新旧请求同键执行许可、处理混合版本页读取，并让旧版本在途请求在新版本请求存在时安全推进；仅有记录版本比较不能替代完整检查点协议。

## 新旧请求执行许可与混合版本页读取

四操作在接受序号前登记哈希/版本，登记失败归还请求且不消费序号。相同哈希的较旧版本仍有请求时，新版本任务留在 Pending，初次同步执行和后续 poll 均在用户回调及查询推进前检查许可。相同版本不互相阻塞，不同哈希互不阻塞；哈希碰撞可能增加等待，不会跳过键比较。许可只保留有界的逻辑计数，不持有记录租约。任务终结或会话放弃时释放许可，Ticket 丢弃与结果收取不改变业务任务许可。

新版本 Read 在许可就绪后才创建查询、取得当时链头，避免等待旧 RMW 完成后仍读取提前捕获的旧链头。已有更高版本任务登记时，迟到旧版本登记返回 Busy；完整的全局阶段接受版本检查仍须随自动阶段观察接入，不能只靠当前未终结任务推断永久的版本下界。

PageRead 只负责物理页和帧校验，不再用操作版本拒绝整个新版本页；帧内记录仍校验记录版本不超过帧上界。实时查询可以遍历同页新旧版本的异键链，新旧同键操作顺序由引擎许可约束。检查点恢复的版本过滤属于 P5.3，不能把实时查询当作 MVCC 历史读取。

新增验证包括四操作等待真实旧 RMW 的矩阵（回调次数、完成值、旧记录不变）、Ticket 丢弃不释放许可/会话放弃释放许可，以及真实写入和淘汰混合版本页后沿异键链读取旧记录。许可组件另验证多个旧请求全部退出、不同键独立、迟到旧登记拒绝及计数清空。当前仍由内部入口驱动会话切分，尚未开启自动阶段推进或公开 checkpoint 成功路径。
