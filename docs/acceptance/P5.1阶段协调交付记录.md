# P5.1 阶段协调交付记录

状态：**已完成**。本地验证及 Linux/macOS 六组原生 CI 全部通过。下一项为 **P5.2 检查点材料写入与提交发布**。

本阶段交付动作仲裁、参与者屏障、会话切分、版本执行许可及维护等待。公开 checkpoint/recover 仍未实现；协调阶段测试不代表检查点已经持久化。

## 动作与参与者

动作状态、会话注册、单调维护 ID 和接受序号共用一把锁。start_action 原子固定全部活跃会话，包括无业务的空闲会话，并保存已退出会话的进度。动作期间新注册返回 Busy；注册与动作开始竞争时，要么纳入集合，要么明确拒绝。

同一时刻只有一个顶层动作；确认、推进、终结、失败均校验维护 ID 和阶段。恢复要求没有活跃会话；shutdown 在仍有活跃会话或未终结动作时返回 Busy。失败状态保留第一个错误，禁止新成功动作。

| 动作 | 阶段序列 |
| --- | --- |
| 完整检查点 | PrepareIndex → IndexSnapshot → Prepare → InProgress → WaitPending → WaitFlush → Publish |
| 仅索引检查点 | PrepareIndex → IndexSnapshot → WaitFlush → Publish |
| 仅日志检查点 | Prepare → InProgress → WaitPending → WaitFlush → Publish |
| 恢复 | WaitFlush → Publish |
| GC | GcIo → GcIndex → Publish |
| 索引增长 | GrowPrepare → GrowCopy → Publish |

PrepareIndex、Prepare、InProgress、WaitPending、GrowPrepare 是参与者屏障。其余阶段必须由实际材料、索引和发布驱动者完成工作后推进；协调器不证明材料持久化。完整/日志检查点进入 InProgress 时递增版本，仅索引动作不递增日志版本。版本耗尽拒绝推进并保持状态。

## 会话切分与接受边界

注册在同一锁内返回当前版本，SessionRuntime 使用该版本初始化。四操作提交前、Session::refresh、poll 前后观察动作；进入 InProgress/WaitPending 时自动切分当前与前一上下文。旧任务保留请求 ID、版本和序号，新上下文只接受后续请求。旧上下文仍有任务时不能再次替换。

接受序号时原子校验操作版本等于全局版本，旧/未来版本拒绝且不消费序号。InProgress 固定旧上下文的序号及挂起数；WaitPending 仅接受旧请求为零的确认。新上下文最大序号不能覆盖旧切分。确认期间阶段变化会重新观察，重试有固定上限，不把正常迟到观察误判为失败。

正常 close 排空两个上下文后提交对应切分。协调器保留退出参与者的切分而不删除；屏障可以跳过已经排空的退出参与者。动作中异常 Drop 保留 SessionAbandoned 并使共享引擎失败。动作前已退出会话的最新进度进入下一次动作，不遗漏不活跃会话。

## 记录版本与执行许可

每条记录和墓碑在发布前固定请求版本，发布后不可变。刷盘只校验版本上界，不覆盖记录版本。同页可以包含多个版本；新版本 Upsert/RMW 对旧记录走追加，同版本且可变的记录仍可原地更新。

四操作在接受序号前登记哈希/版本。相同哈希存在旧版本请求时，新版本任务保留为 Pending，初次执行和后续轮询都在用户回调前检查许可。同版本不互相阻塞，不同哈希独立；哈希碰撞可能增加等待，但不省略键比较。许可只持有逻辑计数，不持有记录租约。任务终结或放弃释放许可，Ticket 丢弃不取消业务，也不释放业务许可。

新版本 Read 在许可就绪后才创建查询并取得链头，避免复用旧 RMW 完成前的链头。实时 PageRead 只校验物理页及帧，记录版本仍不得超过帧上界；不会用操作版本拒绝整个混合版本页。实时查询不是 MVCC 历史读取，恢复版本过滤由 P5.3 接入。

## 维护推进与报告

Maintenance::poll 推进设备完成、普通后台页及已确认的参与者屏障，不执行会话用户回调，不跳过材料或索引工作。Session::wait_maintenance 交替推进自己的会话和维护；其他空闲会话必须 refresh 或正常 close，不能被等待者代为确认。

等待先校验 StoreId，再尝试收取报告。已有报告即使 deadline 已过也立即返回；重复收取保持同一 Arc。超时保留票据和动作。完成端只允许设置一次报告，放弃时产生失败报告；实际任务还须负责协调器的失败/终结。

P5.2 将创建真实材料任务并使用完成端，届时移除 API 完成端上的局部 dead_code 注解。当前创建入口用于协议测试，没有通过虚假的公开 checkpoint 成功路径掩盖未接入的任务。
