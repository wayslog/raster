# RasterKV 磁盘格式 v1

本文规定记录、页帧、索引材料、manifest、提交标识、预留文件与恢复集合的 v1 格式。P5.3 已验证完整恢复；P5.4 冻结提交正在交付检查，只有其双平台验收完成后才正式标记冻结。

## 记录占槽

所有整数显式使用小端编码，不存储 Rust 对象、指针、锁或原子对象的内存镜像。记录头固定 48 字节，后接键、值槽及 4 字节记录校验。各偏移从记录起点计算。

| 偏移 | 位宽 | 字段及约束 |
| --- | --- | --- |
| 0 | 32 | 魔数，ASCII `RREC` |
| 4 | 16 | 必需版本，当前必须为 1 |
| 6 | 16 | 标志：bit 0 墓碑，bit 1 无效记录，bit 2 本页最后记录；其余位必须为零 |
| 8 | 32 | 完整占槽字节数，等于 48 + 键长度 + 值容量 + 4 |
| 12 | 32 | 键编码字节数 |
| 16 | 32 | 值编码字节数，不得超过值容量 |
| 20 | 32 | 值磁盘槽容量，不包含键、头部和尾部校验 |
| 24 | 64 | 前驱主日志地址；全一表示无前驱，零是合法地址 |
| 32 | 64 | 检查点版本 |
| 40 | 32 | 保留，必须为零 |
| 44 | 32 | 前 44 字节的校验值 |
| 48 | 可变 | 键原始编码，允许为空 |
| 48 + 键长度 | 可变 | 值编码，允许为空；墓碑必须为空 |
| 后续 | 可变 | 值槽未用空间，必须全零 |
| 占槽长度 - 4 | 32 | 前面全部占槽字节的校验值，包含头部校验与零空间 |

计算长度使用检查算术，完整占槽必须可由 u32 表示。解析先检查固定头部与头部校验，再检查声明的长度；仅接受恰好一个占槽，不忽略尾随数据。当前解码返回借用的编码切片，不分配由输入声明的巨大缓冲。外层页读取仍须先约束设备请求预算和记录不得跨页；P2/P4 已接入此约束。

校验定义：32 位寄存器初值 `0xffffffff`；依次将每个字节异或到低八位，再执行八次右移，每次移出的最低位为一时异或反射多项式 `0x82f63b78`；最后异或 `0xffffffff`。结果以 u32 小端存储。该校验用于发现意外损坏，不提供真实性认证；不能以合法校验值代替字段语义校验。

`invalid` 记录仍需要完整格式校验，扫描是否输出它由后续扫描契约决定。`final_record` 表示页遍历到此结束，后续页剩余空间必须验证为零；不能据此跳过校验或读取下一页任意位置。前驱地址的记录存在性、必须早于当前记录、是否落在保留范围等，须由已知当前地址与日志边界的上层验证，纯字节解析不授予访问许可。

## 页尾填充

页剩余范围采用全零填充，允许剩余空间不足 48 字节。填充函数只接受调用者明确划定的剩余页切片并将其清零；校验函数要求其中每字节均为零。填充不是有效记录，不能作为键值记录解码。

页遍历者仅在明确结束该页或确认后续完整页剩余范围均为零时识别填充，不能将损坏的记录魔数无条件当成页尾。空填充允许存在，例如记录恰好占满当前页。页大小与记录是否跨页由日志模块负责，不在独立记录中冗余编码。

## 固定样例与验证

固定输入位于 `tests/fixtures/p1-record.hex`，由独立 Python 字段打包和逐位校验脚本生成，测试不会用被测编码器生成预期输入。它包含键 `6bff`、值 `616263`、值容量 4、版本 7 和无前驱。Rust 测试先解码固定字段，再编码并比较完整字节。

运行 `cargo test --locked --lib format::record` 验证固定输入、每一位翻转、全部截断长度、尾随字节，以及重算校验后的未知版本、未知标志、占槽长度不匹配、长度溢出、值越槽、非零保留字段和非零槽空隙。另验证墓碑、空键、地址零、无效前驱、版本边界、拒绝不修改输出和页尾填充。

P4 文件后端及 P5 检查点/恢复已使用本格式。格式测试与真实恢复测试分别记录，见 P1.2、P5.3 和 P5.4 验收文档。

记录格式子步骤已通过本地检查；完整检查结果统一记录在验收报告中。

## Manifest 与材料清单

Manifest 魔数为 `RMAN`，所有整数仍为小端，尾部追加前面全部字节的同算法 u32 校验。文件必须恰好消费完毕，不忽略尾随字节。总输入上限 8 MiB；种子上限 1024 字节；会话与材料数量各不超过 65536。固定头部为 148 字节，尾部校验另占 4 字节。解析先校验总输入与校验和，再验证计数对应的精确输入长度，之后才分配列表。

| 偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 4 | `RMAN` |
| 4 | 2 | 必需版本 1 |
| 6 | 2 | 类型：1 完整、2 索引、3 日志；其他拒绝 |
| 8 | 16 | 非零 StoreId |
| 24 | 16 | 非零 CheckpointToken |
| 40 | 16 | 非零绑定索引 token |
| 56 | 16 | 键 FormatId |
| 72 | 16 | 值 FormatId |
| 88 | 16 | 哈希算法 FormatId |
| 104 | 8 | 检查点版本 |
| 112 | 8 | 日志 begin |
| 120 | 8 | 日志 end，排他 |
| 128 | 8 | 模糊索引重放起点 |
| 136 | 4 | 种子字节数 |
| 140 | 4 | 会话数量 |
| 144 | 4 | 材料数量 |
| 148 | 可变 | 种子原始字节，随后是会话列表和材料列表 |

每个会话项为非零 SessionId 的 16 字节加 Serial 的 8 字节；同一身份不得重复。记录的是检查点协议已经确认的可恢复序号边界，不能用当前最大已完成序号代替；无可恢复操作的会话不输出该项。P5 通过每会话版本切分和旧请求排空确定此边界，不能跨过未完成的旧请求。

每个材料项固定 48 字节：数字 ID u64、文件代次 u64、类型 u16、零保留位 u16、begin u64、end u64、文件长度 u64、整个文件内容的校验 u32。材料类型仅允许索引和日志，文件长度非零，数字 ID 在一个 manifest 内唯一。数字 ID 和代次由 storage 映射到根目录下固定文件名，不从磁盘内容接受路径。

日志材料按地址连续排列，必须完整覆盖 `[begin,end)`，不允许缺口、重叠或空区间。索引材料声明与 manifest 相同的范围，完整/索引检查点至少有一份索引材料。日志检查点不携带索引材料；索引检查点不携带日志材料或会话进度。空日志范围可以没有日志材料。清单的向量顺序保留，重编码不擅自排序。

地址必须通过 P1.1 数值有效性校验，并满足 `begin <= replay_from <= end`。FormatId 和哈希种子按原始字节保存；读取记录前，恢复者须与当前 schema 的键、值及哈希描述逐项比对。本模块不擅自限制自定义 FormatId，也不把格式可解析等同于 schema 兼容。

## 提交标识与恢复集合

提交标识固定 56 字节：`RCMT` 四字节、版本 u16=1、保留 u16=0、StoreId 16 字节、CheckpointToken 16 字节、manifest 总长度 u64、整个 manifest 文件内容的校验 u32、前 52 字节校验 u32。两项身份均非零。长度必须在 152 字节到 8 MiB 之间。

`Commit::verify` 要求 manifest 长度与校验精确匹配、manifest 能合法解析、store/token 与提交标识一致。恢复者还必须逐个读取清单材料，校验长度和整个文件内容；提交标识匹配不能替代材料存在性检查。

集合匹配规则：索引侧只能为完整或索引检查点，日志侧只能为完整或日志检查点；日志侧显式绑定索引侧 token。完整和索引检查点的绑定 token 必须等于自身 token。两侧 store、键格式、值格式、哈希算法和种子必须相等，索引版本不晚于日志版本，日志 begin 不晚于索引 begin，日志 end 不早于索引 end，两侧重放起点一致。同 token 必须对应完全相同的 manifest。

这些规则支持完整检查点单独恢复，以及绑定旧索引的新日志检查点组合；不接受任意两个 token 猜测配对。P5.3 已接入记录版本过滤、模糊索引重放和 Schema 兼容校验。P6 启用缓存与扩容时仍须证明持久化头是主日志地址，并回归同一格式约束。

发布顺序保持既定契约：冻结恢复范围、写入并同步全部材料、写入并同步 manifest、发布提交标识并同步目录，之后才能报告成功。本模块生成的字节不证明任何同步已发生，未提交材料也不能凭合法校验被当作有效恢复点。

固定样例为 `tests/fixtures/p1-manifest.hex` 与 `tests/fixtures/p1-commit.hex`，独立打包产生。测试覆盖逐字节损坏、全部截断、尾随字节、重算校验后的非法版本/数量/身份/保留位、重复材料/会话、范围缺口、仅索引进度拒绝和集合错配。

## 页帧

逻辑页字节放入独立 RPAG 页帧，防止整条记录被清零后被误认为合法间隙。逻辑记录地址不包含帧开销。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | ASCII RPAG |
| 4 | 2 | 小端帧版本 1 |
| 6 | 2 | 必须为零的标志 |
| 8 | 8 | 小端逻辑页号 |
| 16 | 8 | 小端页帧检查点版本上界 |
| 24 | 4 | 小端逻辑页字节数，必须为二次幂 |
| 28 | 4 | 前 28 字节 CRC32C |
| 32 | 页字节数 | 逻辑页数据 |
| 32 + 页字节数 | 4 | 头部与整个逻辑页数据的 CRC32C |

每帧长度为页字节数 + 36；页号 n 的物理字节偏移为 n × (页字节数 + 36)，乘加必须检查溢出。设备分段应作用于该物理字节流，不能直接用逻辑记录地址发起物理读。

页内非记录空间逐字节为零，包括对齐间隙、已放弃的预留及页尾填充。遇到非零字节必须从该位置解析完整 RREC，校验记录长度、CRC、前驱小于当前逻辑地址、记录版本不超过页帧版本。只有完整帧 CRC 通过后才能解释间隙；不能把未验证的零区当作合法删除或空页。读取者还必须传入预期页号与页大小，拒绝错页和截断。


P5.1 的记录发布路径在发布前固定每条记录的操作版本，包括墓碑。普通页刷盘只将调用者版本作为上界校验，不再将页版本覆盖写入每条记录；同页可以包含多个记录版本。新版本 Upsert/RMW 对旧版本记录采用追加，同版本且仍可变的记录继续支持原地更新。P5 已接入跨阶段请求许可及恢复过滤。

实时页读取不将请求操作版本当作整页版本上限；页帧可包含多个版本的记录，仍逐条验证记录版本不超过帧上界。新旧操作的执行顺序由引擎许可处理，恢复所需的记录版本过滤另由检查点恢复流程执行。


## 检查点目录与预留文件

检查点目录为 checkpoints/<32 位小写十六进制 token>/。材料名由清单数字身份固定映射为 <16 位十六进制 id>-<16 位十六进制 generation>.material，不接受清单提供任意路径。manifest 保存编码清单；commit.pending 同步后重命名为 commit，最后同步目录才向调用者报告发布成功。

owner 是 create_new 建立的排他预留文件，不能作为恢复成功证据。其 v1 布局为：RCLM 四字节魔数、u16 小端版本 1、u16 零保留位、16 字节 StoreId、16 字节 CheckpointToken、前 40 字节的 CRC32C（u32 小端），共 44 字节。创建者同步 owner 文件、token 目录及 checkpoints 父目录；命名空间新建时还同步设备根目录。已有 token 不自动复用，失败后的可能可见提交不自动删除。owner 的固定样例见 tests/fixtures/p5-owner.hex；它不参与恢复提交判定。

## 索引材料

索引材料采用 RIND 编码，记录桶数量、表代次及各桶/tag 的日志链头。所有数值采用固定宽度小端编码。

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 4 | ASCII RIND |
| 4 | 2 | 版本 1 |
| 6 | 2 | 零保留位 |
| 8 | 8 | 非零二次幂桶数量 |
| 16 | 8 | 表代次 |
| 24 | 8 | 条目数量 N |
| 32 | 24 × N | 条目数组 |
| 32 + 24 × N | 4 | 前述全部字节的 CRC32C |

每条目为桶号 u64、tag u16、六字节零保留位、日志地址 u64。条目严格按（桶号、tag）升序排列，禁止重复；桶号必须小于桶数量，地址允许零但拒绝 u64::MAX。空索引材料仍保留 36 字节头部与校验。进程内 owner、CAS 修订号、空链与缓存头不进入材料。

解码先验证校验、头部及条目计数与输入长度精确一致，检查乘加溢出后才分配条目数组。文件读取者仍须依据材料长度和资源配置限制输入分配；校验正确不授予地址访问许可。索引导出逐桶取锁，属于模糊快照，恢复须使用 manifest 指定的重放范围，不能将编码成功解释为全局一致快照。

独立固定样例 `tests/fixtures/p5-index.hex` 共 84 字节，桶数量 8、代次 3，两个条目分别为（0、7、0）与（7、65535、4096）。该样例约束 v1 编码与解码。


## v1 实施范围与兼容规则

当前引擎要求页尺寸至少 4096 字节；RPAG 的低层编码器允许更小的二次幂页用于固定样例，不能将其误认为 Config 接受任意小页。每个日志材料恰好保存一个完整 RPAG，完整/索引检查点恰好一份 RIND。清单低层结构校验允许的其他组合，不等于 v1 恢复入口支持它们。

恢复校验完整提交和全部材料后，在独立 restore-<随机 token> 目录重写工作日志，保留逻辑地址、过滤高版本记录并修复前驱。工作目录是运行期文件布局，不能作为恢复集合提交证据。已有检查点材料不随恢复重写；保存并重用 StoreId 与正确配对的 index/log token 即可选择恢复集合。v1 不兼容 C++ FASTER 文件格式。

保留记录的持久依据是每个 token 下不可变的 commit 与 manifest；manifest 的 base_index 记录日志检查点的索引依赖，materials 记录其独立材料副本。所有已存在检查点默认保留，没有按代数、时间或磁盘压力自动过期策略。运行期目录只记录本次进程已发布或选中恢复的条目，未知 token 不等于可删除。显式释放入口及删除协议由 P7.2 交付，在此之前不删除检查点目录。当前材料是独立副本，不引用活动 segments/restore-* 段；不能把材料的逻辑范围错误当成共享物理段引用。

冻结涵盖上述字段位置、整数宽度、端序、CRC32C、版本/标志拒绝、文件命名及恢复匹配语义。RREC/RPAG/RIND/RMAN/RCMT/RCLM 的必需版本均为 1。后续不兼容字节或语义改变必须使用新的必需版本或 FormatId，不能只更新固定样例；旧读取者须拒绝未知必需版本。新增功能若声称保持 v1，必须继续通过旧固定样例与跨功能恢复测试。

内建 ByteKey 采用原始字节（含空与非 UTF-8），U64Key 采用八字节小端；稳定哈希为 FNV-1a 64 位，种子为 0xcbf29ce484222325 的八字节小端。键身份分别为 raster:bytes:v01、raster:u64le:v01，算法身份为 raster:fnv1a64:1。改变算法、种子或编码身份时必须拒绝原恢复集合，不做静默重建兼容。值布局身份与规范解码同样逐项验证；持久数据不保存 Rust 原子或锁的内存镜像。

新增独立 RPAG 样例 tests/fixtures/p5-page.hex 为 292 字节：256 字节逻辑页、页号 2、版本上界 7，在页内偏移 16 嵌入既有 p1-record 样例，其余全零。样例用独立 Python 字段打包及逐位 CRC32C 计算产生。测试核对完整重编码、逐字节损坏，以及重算 CRC 后的未知版本和标志拒绝。另修正并验证 final_record 之后仅允许全零填充，不接受带合法 CRC 的后续记录。
