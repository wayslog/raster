## 验收对应

| 门槛 | 实际测试与证据 |
| --- | --- |
| 空键、变长键 | 原始空字节、非 UTF-8、65537 字节拥有型往返；长度上限算术测试 |
| 相同 tag 不同键 | 8969/9239 的实际哈希 tag 碰撞，分别验证 ByteKey/U64Key 比较拒绝串键 |
| 整数边界 | 0、1、2^63、u64::MAX 等固定编码和独立哈希预期；短输入和尾随数据拒绝 |
| 算法、种子、编码版本变化 | validate_identity 分别改变字段，均返回错误 |
| 跨重启一致 | 两个独立进程执行固定向量并比较编码/哈希/语义描述；新生成身份不同 |
| 身份生成 | 三种身份、四线程共 384 个不重复非零样本；短读和失败源不产生身份 |
| 地址有效性 | 两种地址分页往返、无效值、零、末端、乘加溢出、非二次幂和偏移越界 |
| 编码拒绝无副作用 | 错误缓冲长度保持原输出字节不变 |

新增 2 个单元测试与 9 个集成测试（其中一个也作为子进程入口并执行固定向量断言）。全部为真实类型/KeyCodec 调用，不使用 P0 模型替代。随机样本不能证明数学上的绝对唯一；4 GiB 键仅验证长度算术，未分配巨大缓冲。

## 检查命令

本地与 CI 均检查默认特性、`--no-default-features --features config-toml`、`--all-features`：

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked --examples
RUSTDOCFLAGS='-D warnings' cargo doc --locked --no-deps
```

后三组 Cargo 检查按特性追加对应参数；clippy 的特性参数置于 `--` 前。cargo test 包含 doctest。CI 使用既有路径脱敏配置，仍沿用 `p0-*` 产物名，实际内容包含当前全部测试。
