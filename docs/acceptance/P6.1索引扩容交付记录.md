# P6.1 索引扩容交付记录

状态：**进行中**。已实现索引内部的双表路由、逐桶迁移、表代次与旧快照重定位。公开 grow_index、全局动作、业务回调保护、真实 Pending 穿越与最终报告尚待接入，不能据此宣称在线扩容入口可用。

## 增量迁移协议

MemIndex 以读写控制锁保护当前表、迁移游标和待回收旧表，各桶继续保留独立锁。扩容准备分配两倍桶数的新表并递增代次；每个推进预算至多迁移相应数量的旧桶。已迁移桶按完整哈希路由到新表，未迁移桶仍唯一写入旧表。控制锁覆盖路由选择与桶操作，迁移与发布不会写入两个不同版本的同一逻辑桶。

迁移将每个旧桶的 tag/链头复制到两个新桶，二者共享历史日志链后缀，后续写入按新增哈希位分别追加。完整键比较仍在日志链完成；没有把相同 tag 当成相同键。该实现不读取日志或跨 I/O 持有租约，但旧后缀可能包含另一新桶的记录，查找开销不会在扩容瞬间全部消失。后续压缩可重建较短链，不能以错误的全桶键假设裁剪共享后缀。

EntrySnapshot 增加仅用于路由的完整哈希，不写入 RIND。相等性仍由物理条目身份、桶、tag、代次、链头和修订号决定，保持同桶同 tag 的共享链语义。旧代次条件发布返回新表当前快照 Conflict，外部身份、未来代次和非法地址仍拒绝。持久映像条目不作为条件发布许可；迁移期间 snapshot 返回 Busy，后续全局动作仲裁会阻止检查点与扩容重叠。

## 旧表保留

所有桶完成迁移后才切换主表，旧表留在待回收槽，未释放前不能再次扩容。release_retired 只能由已交付的 ReleaseIndex epoch 动作调用；错误代次拒绝。组件测试实际持有 epoch guard，确认旧表仍存活，释放 guard 并收取动作后才释放旧表。当前引擎尚未接入该调用顺序。

## 已有验证与后续门槛

新增测试验证每次一桶的预算、部分迁移路由、新旧快照冲突、两半链头分流、重复扩容/映像冲突、旧表 epoch 保留，以及四线程条件发布跨越迁移后最后链头不丢失。既有索引碰撞、溢出桶、恢复映像、非法身份和发布测试继续通过；磁盘 v1 字节布局不变。
