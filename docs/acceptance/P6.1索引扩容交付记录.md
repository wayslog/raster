# P6.1 索引扩容交付记录

状态：**完成**。公开 grow_index、全局动作、业务回调保护、真实 Pending 穿越和最终报告已接通，新增六项引擎测试通过。

## 增量迁移协议

MemIndex 以读写控制锁保护当前表、迁移游标和待回收旧表，各桶继续保留独立锁。扩容准备分配两倍桶数的新表并递增代次；每个推进预算至多迁移相应数量的旧桶。已迁移桶按完整哈希路由到新表，未迁移桶仍唯一写入旧表。控制锁覆盖路由选择与桶操作，迁移与发布不会写入两个不同版本的同一逻辑桶。

迁移将每个旧桶的 tag/链头复制到两个新桶，二者共享历史日志链后缀，后续写入按新增哈希位分别追加。完整键比较仍在日志链完成；没有把相同 tag 当成相同键。该实现不读取日志或跨 I/O 持有租约，但旧后缀可能包含另一新桶的记录，查找开销不会在扩容瞬间全部消失。后续压缩可重建较短链，不能以错误的全桶键假设裁剪共享后缀。

EntrySnapshot 增加仅用于路由的完整哈希，不写入 RIND。相等性仍由物理条目身份、桶、tag、代次、链头和修订号决定，保持同桶同 tag 的共享链语义。旧代次条件发布返回新表当前快照 Conflict，外部身份、未来代次和非法地址仍拒绝。持久映像条目不作为条件发布许可；迁移期间 snapshot 返回 Busy，全局动作仲裁已阻止检查点与扩容重叠。

## 旧表保留

所有桶完成迁移后才切换主表，旧表留在待回收槽，未释放前不能再次扩容。release_retired 只能由已交付的 ReleaseIndex epoch 动作调用；错误代次拒绝。组件测试实际持有 epoch guard，确认旧表仍存活，释放 guard 并收取动作后才释放旧表。引擎已经接入此顺序，公开四操作和 Session::poll 的短期访问均进入 epoch，Pending 不跨 I/O 持有 guard。

## 索引组件验证

新增测试验证每次一桶的预算、部分迁移路由、新旧快照冲突、两半链头分流、重复扩容/映像冲突、旧表 epoch 保留，以及四线程条件发布跨越迁移后最后链头不丢失。既有索引碰撞、溢出桶、恢复映像、非法身份和发布测试继续通过；磁盘 v1 字节布局不变。

## 公开动作与请求保护

Maintenance::grow_index 接受一次 GrowIndex 动作并返回票据。GrowPrepare 等待参与会话观察阶段，GrowCopy 初始化两倍表并逐次搬迁一个桶，Publish 等待 ReleaseIndex epoch 动作安全交付，释放旧表后才完成动作和报告。扩容不递增日志检查点版本。会话通过 refresh/poll 参与屏障并推进自己的请求；任意维护线程调用 poll，或通过 Session::wait_maintenance 协同推进。

迁移前非阻塞取得所有业务写入仲裁锁，遇到正在执行的回调立即让出，不等待该回调。这保证从用户计算/原地修改到条件发布之间不会仅因桶迁移失效；不同桶和维护步骤之间仍允许读写。RMW/Delete 在磁盘完成后重新检查完整条目快照，代次改变则重新定位，尚未执行的用户回调不会被维护线程提前执行。

票据丢弃不取消动作，多个推进者只有实际结束任务的线程计数一次完成；重复扩容、相冲突的检查点和动作期间关闭被拒绝。失败/恐慌或参与会话放弃后票据稳定失败，引擎失败关闭，旧表仍有拥有型引用，不因失败提前释放。等待超时不会取消任务。

## 引擎验收范围

- 内存键值在扩容前后完整读取，容量与表代次报告真实；持有旧 epoch guard 时不报告完成，释放后可再次扩容。
- 原生文件后端中 RMW、Read、Delete 的 Pending 跨越表切换，值与墓碑保持正确，RMW 回调只执行一次。
- 暂停在 replacement 回调内的写入与维护推进交错，恢复回调后成功发布，未因迁移丢失已准备值。
- 四个会话的 400 次原生磁盘写入和两个维护推进线程并发，完成只计数一次，随后逐键核对全部数据。
- 参与会话放弃使共享报告稳定失败；空索引和丢弃票据仍能完成，动作期间不能关闭或注册新会话。
- 扩容后完成 Full 检查点，再以对应桶数量恢复，核对更新值、删除结果和正常值。

恢复仍严格验证配置桶数量；应用应保存 IndexGrowthReport.new_buckets，并为该检查点配置相同的 Config.index.buckets。引擎初始 Config 不冒充当前表容量，实际容量来自扩容报告或索引映像。P6.4 会继续覆盖缓存/扫描等交叉场景。

index 模块移除了整个模块的 dead_code 抑制。Cache 变体只为 P6.2 保留，冲突快照当前由协议测试验证、引擎重新 prepare、后续供条件复制使用，两者采用明确的非测试 dead_code 期望标注。仅测试使用的 locate 限制在 cfg(test)，删除了重复的底层 locate。没有改变冻结 v1 字节布局。
