## 兼容性结论

固定上游为 [FASTER 321d872eabda6a0345c8bd76419f89723ed864ae](https://github.com/microsoft/FASTER/tree/321d872eabda6a0345c8bd76419f89723ed864ae)。普通删除遵循盲删策略，并保留满足前驱、版本和可变性约束时的安全索引移除。成功不保证此前存在活跃值，不能把所有缺失/重复删除统一成 NotFound。禁止创建的 RMW 可留下空标签槽，后续盲删行为与上游相同。

用户确认的唯一删除兼容修正是 `force_tombstone=true` 禁止使墓碑不可达的索引移除。因此启用 `abort_if_tombstone` 的读取能够观察仍可达的强制墓碑；后续覆盖和显式截断仍按正常生命周期处理。完整说明和五项公开回归见 [删除契约](P9.1删除契约.md)。

原始上游核心未被覆盖：执行器分别保留原始 C++、仅增加 `!force_tombstone` 条件的参考副本，以及真实 Rust 输出。每个随机后端的原始 25 处差异全部保留；与修正参考必须逐行完全相等，不通过忽略删除操作或只比最终值放宽验收。文件和单条件补丁的 SHA-256 已核查。大生命周期轨迹继续直接与原始上游比较，包含超内存冷读/RMW、检查点关闭恢复及三个会话续接。

P0 的固定确定模型保留独立预期。真实引擎轨迹使用观察模型：值、强制墓碑、接受序号和拒绝副作用严格检查；只有普通盲删结果及普通墓碑可达性采用已声明的有限合法集合。物理地址、Pending 时机和内部重试次数不作为跨实现相等条件。

## 性能与资源边界

[旧 P3 性能复核](P9.2性能复核结论.md)保留完整八组不利结果及处理：当前完整协议的吞吐仍比旧内存原型低约 44%—68%，多组 P99 超过原复核线。已消除同步路径额外分配、重复查询并修正值许可争用错误；容量、身份、版本及失败终结协议保留，不承诺旧原型或 C++ 吞吐。

删除变更后的 macOS 短矩阵又触发数值复核；同主机交替测量和相同二进制控制见 [删除变更性能复核](P9.2删除变更性能复核.md)。所有红色数值及失败工作流继续保留。共享 runner 的磁盘尾延迟和短样本波动不能由业务成功解释为稳定性能，不能把制品审核通过写成性能恢复。

资源循环的稳定存活分配为 Linux 9,809 字节/6 次、macOS 9,937 字节/8 次；句柄分别为 7/9，线程均为 1。测量期 RSS 最大增长为 139,264/98,304 字节，低于运行前固定的 16 MiB 线。该有限循环证明规定工作量下受控，不是无限运行无泄漏或任意硬件的保证。
