## 已接通的复合任务

Maintenance::compact 仍返回一张维护票据，复制结束后按照选项执行后续动作。checkpoint 与 shift_begin 不再作为未实现选项拒绝；多工作者的调度与资源约束见下文。

执行顺序为复制、可选 Full 检查点、可选 GC。上游 InternalCompactWithLookup 在复制线程全部结束后先完成 checkpoint，再执行 ShiftBeginAddress；RasterKV 采用相同顺序。[固定上游实现](https://github.com/microsoft/FASTER/blob/321d872eabda6a0345c8bd76419f89723ed864ae/cc/src/core/faster.h#L3644)

engine/compaction_follow_up.rs 保存子任务票据与步骤。每一步先结束自己的全局动作，再争取下一步；Busy 不占着旧动作等待新动作。复制、检查点或 GC 的终结错误不自动重试，不重复执行已发布的复制；GC 延后报告也是完整步骤结果。压缩不会隐式释放检查点。

api/maintenance.rs 的结果槽分为 Pending、Ready、Taken。公共票据仍可反复观察同一共享报告；仅不向外暴露的内部子票据允许移交拥有型结果，从而保留原始 OS 错误与部分效果。移交时若完成端暂持报告副本，下次推进再取，不阻塞。Taken 不会被完成端 Drop 改成第二个失败报告。

CompactionFailed 保留 until、copied、已成功 checkpoint/gc（使用 Box）及原始 cause。若检查点成功后删除失败，报告保留可恢复 token，cause 中的 GcFailed 保留实际 begin、index_cleaned 与 deleted_segments。业务 panic 的失败关闭路径先终结并收取子任务结果，不以通用错误覆盖已生效边界。

维护进度把步骤之间的间隙计为任务尚未完成。shutdown 在该间隙返回 Busy；持有压缩任务锁核对到关闭入口已关闭，避免新动作与关闭竞争。无活跃会话时可用 Maintenance::poll 推进；活跃会话仍须正常刷新。Deadline 超时不丢弃票据或取消已接受步骤。

## 已接通多工作者

engine/compaction_workers.rs 为一次压缩创建固定数量的工作线程，使用每工作者一个槽保存 ConditionalCopy。生产者负责有界扫描和 ScanDedup 去重，工作者并行查证、编码与发布。没有按每次 poll 重新创建线程，也没有把同线程批量调用当作并行。每个槽最多一个请求，调度器至多另持一个待投递请求；原有候选键数和字节预算继续限制 ScanDedup。

配置 max_compaction_workers 默认 64；公开 workers 超预算在接受前拒绝，完成路由容量同时为工作者、待投递请求、后台刷页与扫描留出空间。启动线程失败发生在接受复制动作之前，停止并收取已启动的空闲线程。线程只在单个工作步骤持有存储强引用，空闲期间保存 Weak，不形成存储/线程所有权环。

槽锁内执行一步并捕获 panic，在途请求保存在槽中，不随工作线程栈意外销毁。普通错误通知所有工作者停止新任务，排空已接受 I/O 后退出；调度器收取线程并确认计数，才结束复制动作。失败关闭先停止所有发布、收取线程并报告已知效果，未归还读取及租约仍留在任务槽中；设备 shutdown 结束后才释放。工作者停止前的维护等待保持原票据，deadline 超时不提前丢弃任务。

工作者的副作用计数只统计实际发布目标，包括可能在其他工作者失败时已经发布的复制。每次投递和每工作者计数都检查溢出；工作者收尾后汇总并确认总数不超过投递数。普通失败不会重复执行复制。空槽接收新请求时，在槽锁内再次检查停止位，避免工作者已退出却仍投递请求。

发布成功或普通失败之前全部线程已 join；失败关闭时 shutdown 也先等待线程停止，再关闭设备。正常任务未结束时保持既有 Busy 关闭语义；自动任务的停止、排空仍由本节后续工作接入。没有增加依赖或改变持久格式。

## 自动维护实施与验证范围

engine/auto_compaction.rs 持有一个调度线程，调用原有 Lookup 压缩和 GC 入口，复用同一票据、全局动作、资源排空与错误报告。默认关闭；默认间隔 250ms、触发比例 0.8、目标比例 0.2、单次上限 512 MiB，启用必须显式设置非零日志预算。安全冷区向下页对齐，没有完整冷页时等待。workers 沿用 Rust 已记录的默认 1，并受 max_compaction_workers 限制。

上游 AutoCompactHlog 设定日志预算，InternalUpsert/InternalRmw 达到预算时协助正在进行的压缩；CompactRecords 无任务时返回，并不构成硬性拒写。因此本实现预算为触发与状态提示，没有引入新的拒写上限。上游名为 round down 的表达式实际加到下一页；RasterKV 保守取安全边界以内的完整页，避免越过 safe_head。[固定上游调度与帮助函数](https://github.com/microsoft/FASTER/blob/321d872eabda6a0345c8bd76419f89723ed864ae/cc/src/core/faster.h#L4260)

状态、等待、停止契约见 [公开接口](../10-RasterKV公开接口.md)。自动任务不隐式生成或释放检查点，停止不取消已接受的压缩；DeferredByRuntime 只接续物理 GC，不重新搬迁。普通失败停止调度并保留原始报告；panic/协议错误使引擎失败关闭。线程空闲期间不持有存储，Stopped/Failed 在 join 后报告。shutdown 先停止并排空自动任务，随后才检查会话、扫描和手动任务。

本次增加十一项测试，覆盖：目标边界与配置拒绝；禁用和空闲销毁；真实在途读取时停止/超时；无会话自动关闭排空；普通 I/O 错误的原始 OS 原因及不重放；手动检查点屏障竞争；读者阻碍 GC 后的自动物理回收；协议错误、真实设备 poll 恐慌以及接受前恐慌时对手动全局动作的终结；三轮自动压缩、墓碑、检查点、恢复和会话续接。

真实交错测试还修复了两个已复现问题：压缩移动 begin 后，挂起读取沿旧链返回 Missing，原实现会把始终存在的键报告为 NotFound；现在重新核对索引并继续查询。设备 poll 恐慌会使轮询序列化锁中毒，原关闭流程再次使用正常轮询而无法结束；现在仅在设备关闭且发布线程退出后使用终态完成回收路径。该路径不恢复运行权限。压缩扫描遇到 InvalidState 也统一进入失败关闭，保持与工作者协议错误一致。

测试中的接受前 Busy 保留原请求与序号重试，明确检查没有消费序号；已接受的错误不重试。I/O 门闩保存真实原生完成，关闭测试在归还前验证不能提前成功。没有新增外部依赖或改变 v1 持久格式。
