# P9.1 删除契约与验收

2026-09-12：实现和 P9.1 交叉验收完成；交付提交 `a834f48b53865098c8325d81cc52934bb322c26d`。本节不代替 P9.2 性能及 P9.3 最终文档门槛。

普通 Delete 遵循固定上游提交 `321d872eabda6a0345c8bd76419f89723ed864ae` 的盲删策略。索引中没有对应标签入口时返回 `NotFound`；存在入口时，只检查驻留记录，不能为了判定键是否存在读取旧磁盘记录。成功表示删除已生效，不证明此前存在活跃值。已到达的墓碑也可以再次成功删除。

同版本、仍可变的匹配记录可原地标记墓碑。普通删除仅在该记录为当前链头、前驱已不在有效日志范围时尝试清除索引入口；冲突不能覆盖其他写入，同标签碰撞键不能因此丢失。删除清除的是索引可达性，不立即释放日志字节。

`force_tombstone=true` 必须留下可查询的墓碑，不采用使墓碑不可达的索引清除优化。这是明确接受的上游兼容修正；普通 Read 返回 `NotFound`，启用 `abort_if_tombstone` 的 Read 返回 `Aborted(Tombstone)`。该保证不延长已经被显式截断、回收或覆盖的记录的生命周期。

验收使用已经确认的公开边界：`Session` 的四操作、选项及结果；`DeviceFactory/Device` 的实际文件 I/O；公开诊断、检查点、恢复和维护入口。设备装饰器只计数或控制实际 I/O，不替换引擎算法。逐项先记录失败用例再实现。内部索引修订与日志许可另外验证 ABA、冻结和版本边界，不以内部测试代替公开行为验收。

参考模型继续独立验证键值、序号和副作用；不预测具体索引布局、日志地址或 Pending 次数。表示方式相关的删除返回及非强制墓碑可达性必须明确建模为有限的合法结果，不能忽略任意差异。上游原始结果保留，强制墓碑兼容修正单独列出。


## 实施中的具体发现

普通删除的“入口存在”包括 RMW 留下的空标签槽：上游 `FindOrCreateEntry` 会在 `create_if_missing=false` 返回缺失后保留槽位。RasterKV 现区分没有条目和已占用但无地址的条目；Read 仍缺失，后续盲删可成功。槽位不代表有效键，GC 可清理，序号和逻辑副作用契约不变。

跨实现上下文也必须一致。C++ 驱动器的字节值更新总走追加；旧 Rust 驱动器允许容量足够时原地替换，导致普通删除面对不同的前驱链。现在仅在上游对照中统一为数字允许原地、字节总追加；P3 通用轨迹仍覆盖字节原地替换。没有修改生产 Schema 的更新策略。

基准输入和逻辑应用字节分母保持不变。固定基准先读、写、RMW，再普通删除；首次删除必须成功，重复删除允许成功或缺失。恢复后的普通墓碑允许缺失，所有活跃值仍精确比较。成功/缺失统计记录真实结果，审计仅允许上述重复删除数量内的变化，并严格要求业务总数守恒。这不降低已有性能复核阈值。

## 当前本地证据

公开文件设备测试已观察旧删除额外读取一次旧页，修改后零次；普通链头索引移除测试、空槽行为测试均先失败再通过。单独验证同标签碰撞、多次删除、强制墓碑、旧检查点保留及新检查点恢复；源许可测试覆盖并发读取、条件复制、冻结、版本和发布冲突。

首轮修正 C++ 随机对照还暴露了三处差异：字节更新策略一处、空标签槽两处。修正适配器和空槽行为后，本地 Null 7,508 步与参考修正逐行一致；原始 C++ 的 25 处差异保留。该 C++ 环境经 Podman 指令翻译运行，只作为预检；正式 Linux 结果见下节。

本地翻译环境的文件 C++ 预检失败于 `libaio io_setup` 返回 -38（不支持的系统调用），继而上游断言退出；原生 Ubuntu 文件对照仍是必需门槛。没有把该环境失败计为兼容性通过。新增墓碑源许可用例在 nightly Miri 默认泄漏检查下通过。

三组本地工程矩阵实际完成 31 个检查：default 为 430 个运行测试和 8 个 doctest，config-toml/all 各 435 和 9；五个公开示例分别实际运行并检查目录保护。Miri 完成 40 项默认泄漏检查及 1 项明确的故意遗忘例外；预存脚本的页范围/日志用例数量已从实际列表校正，没有放宽通过规则。另完成内存整数单线程、超内存变长值四线程两组基准冒烟，各 16,384 操作和 2,048 个恢复键；正式性能数字以独立原生矩阵为准。

失败用例、首次三处参考差异、修正后 Null 对照、完整本地测试和 Miri 记录见 [数据清单](data/p9-delete/manifest.json)，文件均有 SHA-256。它们记录未提交工作区及其基线，最终交付提交由下节原生 CI 证据确定。

本轮未增加外部依赖、公开 API 或生产 unsafe 块。两项新增 `allow(dead_code)` 仅用于基准示例和基准支持测试复用确定模型时，未调用的盲删观察模型；不是生产模块的临时占位。正式 Clippy 仍对全部目标启用 `-D warnings`。
