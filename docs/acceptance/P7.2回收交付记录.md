状态：**进行中。已补齐普通页读取的物理段保护，公开 ShiftBegin、索引 GC、段删除与保留集合释放尚未接通。**

## 已接入的读取保护

`log/read_page.rs` 在首次提交前取得整个页帧覆盖范围的段租约，而不是只保护当前一次分段 I/O。普通冷读取、条件复制的元数据查询以及使用 PageRead 的检查点读取都因此受到保护。

保护持续跨越队列繁忙重试、短读和下一段提交；设备完成仍留在请求邮箱中时也不能使相关段映射失效。成功或失败终结且设备已归还全部缓冲后释放保护，后续页解析只依赖拥有型字节。错误存储实例不能接续既有保护的请求。

公开扫描与压缩扫描既有的外层租约继续保留；本步补齐普通日志查询，尚不启动物理删除。调用者仍负责正常排空；异常放弃请求的失败关闭协议禁止继续发起成功维护。

## 已执行验证

新增 `src/engine/scan_tests.rs` 两项真实引擎测试：

- `普通冷读取跨段短读期间保护全部段且完成后释放`：暂停设备、注入短读，确认页帧覆盖的两个段均返回 Busy；完成进入邮箱后后续段仍受保护；会话完成读取后两个映射均可失效。
- `普通冷读取失败收尾释放段保护且不保留失败请求`：单次 I/O 失败按 NotApplied 终结，段保护随失败收尾释放。

本地 Rust 1.98.1 全部特性的格式、Clippy、全量测试、示例编译与 rustdoc 已通过，共 331 个运行测试及 6 个 doctest。脱敏日志位于忽略目录 `target/p7-gc-read-local/`。这只证明读取保护前置工作，不代替 GC 引擎验收。

## 接下来的实施约束

1. 逻辑 begin 发布须验证记录边界、已刷盘范围和安全 head；普通键查询与物理扫描对失效范围的输出分别遵守业务及扫描契约，不能绕过在途请求终结。
2. 索引清理须保留并发发布的代次/修订校验，不能把持久映像当作 CAS 许可，也不能通过清空条目后重置修订制造 ABA。缓存头需要先规范化。
3. 删除只作用于当前实例绑定的工作段目录，按页帧的实际物理偏移计算整段可删范围；关闭、删除、目录同步与重试结果分别处理。
4. v1 检查点使用独立材料副本，manifest 的逻辑范围不能直接当作工作段共享依赖。旧索引检查点与新日志检查点的配对必须检查 GC 后是否仍能取得所需范围。
5. 保留集合的显式释放还需处理真实材料依赖、持久化状态和未知磁盘 token 的默认保留；不能按本进程目录缺项授权删除。
6. DeferredByRecoverySet 必须终结当前动作，允许之后检查点并重新回收；P7.3 的串接任务不得持有当前动作等待新动作。

完整交付仍需公开 API、删除失败重试、读写/扫描竞争及至少两代保留恢复集的原生验证。
