状态：**进行中，功能与验证用例已接入，等待最终代码提交的 Linux/macOS 原生 CI 验收。**

本阶段交付公开逻辑截断、逐桶索引 GC、可重试工作段删除、磁盘检查点依赖枚举及显式检查点释放。P7.3 的自动调度、多工作者和串接动作未据此验收。

| 入口或模块 | 实际行为 |
| --- | --- |

v1 检查点拥有独立材料副本，不引用 segments/restore-* 工作段。工作段 GC 不释放检查点；检查点逻辑范围也不能作为共享物理文件引用。本阶段没有增加依赖或修改 v1 manifest/commit 的字节编码。

## 逻辑截断与工作段回收

热记录边界错误在接受前拒绝；冷页内边界通过有界页读取验证，失败以零效果 GcFailed 终结。begin 不能倒退、超过已知尾部或穿过未完成初始化。逻辑 begin 在全部业务仲裁内发布，并先规范化缓存头。普通查询遇到被截断旧链返回缺失；物理扫描跨越截断范围返回 RangeTruncated。GC 不迁移最新值，需要保留它们时应先压缩。

GC 期间后台刷盘仅排空既有写入，作废完整页无需重新刷出。首个保留页可以从页内记录边界开始，后续页编码和检查点跳过作废前缀。跳过的 flushed_until 范围不是持久化凭据。删除范围按页帧实际物理偏移计算，仅枚举当前工作目录中完整位于保留帧之前的已绑定段。

`GcReport { begin, index_cleaned, deleted_segments, physical }` 分别报告逻辑和物理结果。运行期租约阻碍删除时返回 `DeferredByRuntime { begin, end }` 并终结本次动作；释放读者后可用相同 begin 重试。deleted_segments 统计本次经目录同步确认的删除，包括接续上次失败的步骤；未确认计数不能证明磁盘没有发生删除。普通错误为 `GcFailed { begin, index_cleaned, deleted_segments, cause }`。

删除任务保留路径、代次、旧句柄及当前步骤，关闭/删除/同步失败后额外轮询不会重试。显式新 GC 才接续；已经关闭或不存在的文件允许继续同步。身份错误或 panic 进入失败关闭，在设备结束前不丢弃未知在途资源。

索引清理压紧存活条目并释放多余溢出块，桶的单调修订同时穿越清理和扩容。缓存安装在业务仲裁内重新检查动作、源地址和 begin，迟到冷值不能复活旧键。find_mutable 同时检查 begin/read_only/head，修复页内截断后通过同标签存活链头原地更新旧记录、报成功却读不到的问题。GC 使旧自动索引配对失效，需先生成新 Index/Full，再生成 Log。

## 目录枚举与跨实例仲裁

`ReadDirectory { path, max_entries, max_name_bytes }` 返回单层拥有型名称和类型；空路径表示设备根目录。名称保留平台字节；符号链接只报告类型。条目或名称预算超限时整体失败，不返回可能漏依赖的部分目录。macOS/APFS 拒绝非法 UTF-8 名称时如实返回 OS 错误；Linux 和内存设备验证名称字节保留。

`TryLock { path, mode }` 以独立打开、不截断的句柄尝试文件锁，成功返回 Locked(FileId)，竞争完成返回 Busy 且没有句柄。锁文件不能删除或替换，锁句柄不接受数据 I/O。Close/shutdown 显式解锁后关闭，防止复制或进程继承描述符延长锁寿命；异常退出由操作系统解除仍持有的锁。底层目录能力限制路径与符号链接逃出根目录。

原生 Linux/macOS 后端声明目录枚举和文件锁能力；内存设备只声明枚举，不提供跨进程锁或持久化。所有共享检查点目录的参与者须遵守同一协议，不支持其他程序绕过锁修改目录。

- 发布 Shared 锁在 DirectoryPrepare 创建检查点命名空间之前取得，覆盖材料写入、Log 基准重新验证、最终 commit 重命名和目录同步，成功报告前确认关闭。早期前置提交只锁最终发布，本次前移以保证独占枚举期间没有新目录或文件插入。
- 恢复 Shared 锁在第一个 manifest 读取之前取得，覆盖两遍读取、校验、重放及独立工作副本同步，对外发布实例前确认释放。
- 释放 Exclusive 锁覆盖全部目录枚举、依赖判断、失效、删除和同步，不能检查完引用后解锁再删。

Log 在共享锁内重读基准 commit/manifest；另一实例已释放基准时拒绝发布新 Log，沿用检查点失败关闭协议。已经恢复的实例使用独立工作副本，源检查点之后被释放不影响其业务读取。

## 显式释放与持久化协议

`release_checkpoint(token)` 接受独立维护动作，经会话或维护 poll 推进。它表示调用者放弃该 token；不自动选择过期集合。实例内动作冲突在接受前返回 Busy。目录锁竞争在已接受票据中返回 CheckpointReleaseFailed、cause=Busy，终结本次动作，调用者可稍后显式重试。

目录读取验证所有规范 token 目录和元数据身份、结构、校验及有效 Log 基准。运行期 RetentionCatalog 仅为缓存，未被当前进程登记的磁盘 token 仍受保护。未知名称、链接、损坏或缺失清单、commit 与 commit.released 同时存在、有效 Log 基准缺失/失效都使本次释放保守失败。未提交目录默认保留，不能作为成功释放目标；未在清单中的材料也不会被顺带删除。

被有效 Log 引用的 Index/Full 返回 `DeferredByRecoverySet { blockers, begin, end }`，blockers 为磁盘中的实际恢复集。本次没有失效或删除，且全局动作已经结束；之后可以生成新检查点，释放引用方，再显式重试基准 token。不存在等待新动作的死锁或隐式删除队列。

无引用时按以下顺序执行：

1. 将 commit 原子重命名为 commit.released，保留原 v1 提交证据字节。
2. 同步 token 目录，确认恢复入口已失效；此前绝不删除材料。
3. 按已验证 manifest 删除各材料，每项删除后同步目录；已不存在也须通过同步确认。
4. 保留 owner、manifest、commit.released 与 token 目录，关闭独占锁后终结动作。

保留元数据阻止 token 复用并构成持久化删除意图。重启后显式再次调用可验证该意图并继续，不依赖原进程任务。已恢复实例可在释放源 token 后继续使用工作副本。材料之外的元数据目录清理尚无自动策略。

| retirement | 保证 |
| --- | --- |
| NotAttempted | 本次尚未发出失效操作，不证明未知或先前已失效 token 仍可恢复 |
| PossiblyRetired | 已接受重命名或发现先前失效标识，本次尚未确认失效目录同步 |
| Retired | 已确认失效目录同步，后续删除仍可能只完成一部分 |

`CheckpointReleaseReport` 与 `CheckpointReleaseFailed` 均包含 token、retirement 和 confirmed_absent_materials；错误另含 cause。计数表示本次经目录同步确认不存在的材料，包含重试前已经缺失的材料，不是新增删除数或释放字节数。Completed 仅说明 manifest 材料均已处理，不表示 token 目录全部移除。普通错误正常解锁并结束动作；身份损坏、panic、锁资源不确定等失败关闭，设备终结前保留资源。

本实例在接受失效重命名后撤销同 token 的自动基准配对，确认目录同步后才从运行期保留缓存移除。其他实例必须靠发布前磁盘复查发现失效，不能以缓存授权新 Log。

默认预算为 maintenance.max_checkpoint_tokens=4096、max_checkpoint_catalog_bytes=64 MiB，均须非零。字节预算累计全部目录名称、56 字节 commit 和 manifest 声明长度，在材料清单分配前检查；条目预算限制每层枚举。已释放 token 元数据也计入预算，超限需调整配置，不会静默只扫描一部分。
