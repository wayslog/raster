## 底层逐桶索引清理

`index/gc.rs` 清除 begin 之前的链头及空条目，在桶独占锁内压紧剩余条目并释放多余溢出块。公开 GC 先发布合法逻辑 begin、规范化缓存头，再按实际表容量逐桶调用，覆盖此前已经扩容的索引。

桶保存单调发布修订和最近回收时的空槽修订。清理后旧的空槽许可不能因条目再次消失而重新有效，重新插入相同地址也不能重用旧许可；普通不同标签的写入不会无端撤销另一空槽的许可。扩容同时复制两个修订字段，持久格式仍不保存这些运行期字段。

## 公开逻辑截断与工作段删除

`Maintenance::shift_begin(address)` 接受一个独立 GC 动作，由会话或维护轮询推进。热记录边界错误在接受前拒绝；冷页内边界通过有界页读取验证，失败报告仍携带零效果。动作冲突返回 Busy，等待超时沿用原票据。

发布逻辑 begin 时取得全部业务仲裁，先规范化缓存头；begin 不能倒退或超过已知尾部，也不能穿过未完成初始化。普通键查询遇到 begin 之前的链返回缺失；物理扫描跨越被截断范围返回 RangeTruncated。已经接受的修改请求完成 I/O 后重新查询索引，不使用截断前的值执行回调。

后台刷盘在 GC 期间只排空既有写入。GC 越过已作废的完整页并释放内存页；首个保留页可以从页内记录边界开始，后续页编码和检查点材料跳过作废前缀。删除范围按页帧的物理偏移计算，只枚举当前实例工作目录中完整位于保留帧之前的已绑定段。

删除任务先摘除段映射，随后依次关闭句柄、删除文件、同步目录。全页帧租约保护短读、跨段读取以及已经进入邮箱但尚未收取的完成。不能立即释放的运行期租约返回 `DeferredByRuntime { begin, end }` 并终结本次动作；该范围说明待回收旧前缀，不是实际删除字节计数。释放读者后可按相同 begin 重新发起。

`GcReport` 分别给出 begin、index_cleaned、deleted_segments 和 physical。deleted_segments 只统计本次经目录同步确认的删除，包括接续上次失败的任务；Completed 表示本次候选工作段已处理，不表示检查点目录已清理。普通错误返回 `GcFailed { begin, index_cleaned, deleted_segments, cause }`，错误报告保留已经发生的效果，未确认计数不证明磁盘没有发生删除。

关闭、删除或目录同步失败后，任务保留原路径、旧句柄和当前步骤。额外轮询不会自动重试；下一次显式 GC 才接续。已经关闭或已经删除的结果允许继续同步。身份损坏及 panic 按失败关闭协议处理，在设备结束前不丢弃未知在途资源。

缓存安装在业务仲裁内重新检查维护状态及源地址。即使较新的同标签链头在 GC 后保持不变，旧键的迟到磁盘值也不能重新装入缓存。新检查点过滤未清完的旧索引头；GC 使旧的自动索引配对失效，用户需先生成新 Index/Full，才能继续生成 Log 检查点。两代已提交恢复集的独立材料均继续保留。
